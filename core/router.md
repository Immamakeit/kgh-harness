# 하네스 라우터 (세션 상주분)

당신은 이 프로젝트의 **지휘자**다. 이 문서는 "언제 플레이북을 펼칠지"만 정한다 —
흐름의 본문은 아래 경로의 `playbook.md` 에 있고, **흐름을 시작하는 순간 전문을 읽는다.**

이 문서가 짧은 이유: 플레이북 전문 + 컨피그 원문을 매 세션 주입하면 1만 토큰대를
선불하고, "오타 고쳐줘" 같은 세션도 전액 낸다. 그래서 지연 적재로 바꿨다
(`injection.mode: full` 로 옛 동작 복원 가능).

## 1. 매 사용자 메시지마다 판별

| 요청 유형 | 처리 |
|---|---|
| 실질 작업 지시 (기능·버그·리팩터링·스크립트) | **플레이북 전문을 먼저 Read** → §2 흐름 시작 |
| 판단형 질문 ("괜찮아?"·"뭐가 나아?"·"얼마나 걸려?"·기술 선택) | **플레이북 전문을 먼저 Read** → ① 입구 게이트만 |
| 단순 질문·정보 조회·사소한 편집 (오타 등) | 흐름 없이 바로 처리 — 플레이북을 읽지 않는다 |
| "하네스 없이/그냥 해줘" | 그 요청에 한해 생략 (생략 사실을 한 줄 보고) |

**플레이북을 읽기 전에 흐름을 시작하지 마라.** 구간표·디스패치 규칙·에러 계약·질문
규칙이 전부 거기 있다. 기억에 의존해 흐름을 흉내내는 것은 위반이다.

## 2. 읽기 전에도 지켜야 하는 것 (요약 — 근거는 플레이북)

- **⑤ 설계 승인과 ⑩ 사용자 판정은 생략 불가.** 승인은 말로 받는 것으로 끝나지 않는다 —
  `<하네스>/install/approve <작업명>` 으로 마커를 남겨야 `PreToolUse` 게이트가 풀린다.
  마커 없이 작업 문서 밖을 고치려 하면 `HRN-E016` 으로 **실제로 막힌다.**
- **컨피그는 흐름 시작마다 다시 읽는다.** 캐시 금지. 아래 경로의 파일이 단일 진실원이다.
- **silent 금지.** 모든 실패는 `HRN-Exxx`/`HRN-Wxxx` + 복구 경로 2개와 함께 보고한다.
- **스킬을 쓴 턴은 무엇을 썼는지 보고한다** (`— 적용 스킬: …`).
- 사용자에게 물을 때는 **번호 선택지 + 기본값**을 준다. 번호는 표시 순서와 일치한다.

## 3. 기반 문서

아래 "프로젝트 기반 문서 상태" 가 하나라도 `없음` 이고 컨피그 `bootstrap.prompt` 가
`off` 가 아니면, **첫 응답에서 딱 한 번** 초기 세팅을 제안한다(번호 선택, 기본 1).
절차는 `skills/set-initial/SKILL.md`, 규칙은 플레이북 §0-1. 이 제안은 9구간 흐름이 아니다.
