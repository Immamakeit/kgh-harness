# Cost-Bottleneck-Check (판단 게이트)

## 핵심 원칙

판단형 답변은 **아래 필수 슬롯을 전부 채운 보고서**다. 슬롯이 하나라도 비면 미완성이다.
정보가 없어 못 채우는 슬롯은 **가정으로 채우지 말고 "되물음" 슬롯에 올린다.**

## 분류 (가장 먼저 수행)

- **업무급**: 대상 코드베이스가 존재하고, 요청이 그 코드베이스의 기능·요건·구현 방식에
  대한 것 → 업무급 슬롯 사용 (코드 조사 필수)
- **전략급**: 사업성·기술 선택·조직·투자 등 코드베이스 밖의 방향 판단 → 전략급 슬롯 사용
- 판돈이 큰 업무급(비가역 스키마 변경, 아키텍처 변경 수반)은 전략급 슬롯을 **추가로** 채운다.

## 공통 규칙

1. **근거 없는 문장 금지** — 모든 주장에 파일 경로 · 실측값 · 출처 중 하나를 단다.
2. **가정 금지** — 답을 좌우하는 정보가 없으면 되물음 슬롯에 올리고, 결론을 그 되물음
   기준의 조건부로 쪼갠다.
3. **"간단히/짧게" 요청을 받아도 슬롯을 삭제하지 않는다** — 슬롯당 1~2줄로 압축한다.
4. 보고에 적용 사실을 명시한다: `— cost-bottleneck-check 적용`.

## 업무급 필수 출력 (전 슬롯 REQUIRED)

1. **현황 (코드 인용)** — `impact-scan` 스킬이 있으면 호출, 없으면 read-only 탐색
   서브에이전트로 조사한다. 관련 모듈 · 기존 유사 구현 · 의존 관계를 파일 경로와 함께.
2. **전수 점검표** — 각 항목에 "확인함(발견 내용)" 또는 "해당 없음(사유)"을 기입한다.
   빈 칸 금지. **첫 발견에서 멈추지 말고 표를 끝까지 돈다.**

   | 항목 | 확인할 것 |
   |---|---|
   | 인증·권한 경로 | 새 진입점의 인증 방식, 기존 로직과의 중복 여부 |
   | 테스트 커버리지 | 변경 경로에 테스트가 있는가 → 없으면 리스크·공수에 반영 |
   | 배포·런타임 | 배포 방식이 이 변경과 충돌하는가 (재시작, 상시 연결, 프로세스 모델) |
   | 데이터·스키마 | 마이그레이션 필요 여부, 비가역성 |
   | 동기/비동기 경계 | 트랜잭션·블로킹 호출 위에 얹는 변경인가 |
   | 결합부·중복 | 같은 일을 하는 코드가 몇 곳인가 (이번 변경으로 늘어나는가) |

3. **실비용** — 영향 파일 범위를 근거로 한 공수. 선행 정리 작업이 필요하면 분리 명시.
4. **리스크** — 깨질 곳과 깨지는 조건.
5. **되물음** — 답을 좌우하는 미확인 정보 목록.
6. **조건부 결론** — "조건 A면 X, 조건 B면 Y" + 권장 첫 행동.

## 전략급 필수 출력 (전 슬롯 REQUIRED)

1. **재프레임** — 질문에 박힌 해결책 이름(MSA, K8s, RAG…)을 벗기고 문제와 비용의
   언어로 재작성한다. "누가 왜 이 프레임을 가져왔는가"에 답하거나 되물음에 올린다.
2. **되물음** — 진짜 문제 · 현재 병목을 모르면 여기 올린다.
3. **비용표** — 구축 · 전환 · 운영 증가분 · 학습 · 기회비용 · 비가역성 각각.
   숫자가 없으면 자릿수(order of magnitude) + 가정을 명시한다.
4. **병목 대조** — "이걸 완벽히 성공시키면 좋아지는 것"이 "지금 우리를 실제로 묶는
   제약"인가. 채택 후 이동할 새 병목도 예측한다.
5. **반례** — 이 방향이 실패하는 조건, 실제 후퇴·실패 사례(출처), 반대 방향의 최강
   논변(steelman), "어떤 증거가 나오면 결론을 바꿀 것인가".
6. **조건부 결론 + 최소 검증 실험** — 측정 가능한 조건 분기, 결론이 깨지는 조건,
   가장 큰 불확실성을 가장 싸게 해소할 첫 실험.

## 판정 반환 (게이트 분기용)

| 판정 | 의미 | 다음 |
|---|---|---|
| **PASS** | 프레임·병목 정합, 방향 유효 | 설계 단계 진행 |
| **REDIRECT** | 프레임이 틀렸거나 병목 불일치 | 재프레임된 질문과 함께 요구사항 단계로 반려 |
| **CONDITIONAL** | 되물음·검증 실험 해소 전 진행 불가 | 사용자 응답 또는 실험 결과 대기 |

## 완료 기준 (제출 전 자가 점검)

- [ ] 필수 슬롯 전부 채움 — 빈 슬롯 = 미완성
- [ ] (업무급) 전수 점검표 전 항목에 "확인함/해당 없음" 기입
- [ ] 근거 없는 주장 0개
- [ ] 판정(PASS/REDIRECT/CONDITIONAL) 명시
- [ ] 적용 사실 명시
