# Interactive-Script (대화형 스크립트 표준)

## 핵심 원칙

스크립트는 **사용자가 명령어를 몰라도 되는 단일 진입점**이다. 실패는 런타임이 아니라
사전에 잡고, 선택지가 있는 곳은 물어보되 디폴트를 주고, 무엇이 됐는지 끝에 요약한다.
(vault `script-standards.md` 실행체)

## 1. 사전 점검 (실행 전 차단)

- 런타임에야 죽을 실패를 **실행 전에** 점검한다: 런타임/도구 설치 · 필수 환경변수 ·
  의존성 · 포트 선점 · 필수 파일.
- 각 점검 실패는 원인 + 해결법을 안내하고 멈춘다 (다음 항목 참조).

## 2. 대화형 + 디폴트 (선택지가 있는 곳)

**갈림길에서는 물어보되, 디폴트를 제시하고 Enter로 넘어가게 한다.** 예:

```bash
# 포트 선점 시 — 종료가 아니라 선택지
read -rp "포트 $PORT 사용 중입니다. 다른 포트로 띄울까요? [기본: 8003] " p
PORT="${p:-8003}"

# 의존성 재설치 확인
read -rp "package.json이 바뀌었습니다. 의존성 다시 설치할까요? [Y/n] " a
[[ "${a:-Y}" =~ ^[Yy]$ ]] && npm install
```

- 비대화형 환경(CI 등)도 고려한다: `[ -t 0 ]`로 TTY를 확인하고, 아니면 디폴트로 진행하며
  선택 내용을 로그한다.
- 물을 가치가 없는 것(예: node 미설치)은 묻지 말고 안내 후 종료한다. 진짜 갈림길만 묻는다.
- 갈림길의 답이 **정해진 목록**이면 자유 입력을 시키지 않는다 — `ask_choice` 로 번호를
  고르게 한다. 목록을 만들 수 없을 때만 `ask`(자유 입력)를 쓴다.

## 3. 에러 메시징 (silent 금지, raw 방치 금지)

- `set -euo pipefail` + 실패 지점마다 사람이 읽을 메시지. 조용히 죽는 경로 0개.
- raw 에러/스택을 **숨기지도, 그대로 던지지도 않는다** — 원문은 보이되 **원인 해석과
  해결 방법을 덧붙인다**. 하네스 에러 계약을 쓰는 스크립트면 `HRN-Exxx/Wxxx` 코드로 래핑.
- 안내는 사용자 눈높이 언어로. (색상 구분 권장: 안내/성공/주의/오류)

## 4. 종료 요약 (결과 비은닉)

성공·실패 무엇으로 끝나든 **무엇이 됐고 무엇이 안 됐는지 요약**한다. 서버 기동처럼
프로세스를 넘겨받는 경우(`exec`)에도, 넘기기 **직전**에 준비 완료 항목과 접속 주소를 찍는다.

```bash
ok "준비 완료 — Node $(node -v) · 의존성 OK · 환경변수 OK · 포트 $PORT"
ok "접속: http://localhost:$PORT   (종료: Ctrl+C)"
exec npm start
```

## 완료 기준 (제출 전 자가 점검)

- [ ] 단일 진입점, 사용자가 내부 명령어를 몰라도 실행 가능
- [ ] 런타임 전 사전 점검 (도구·환경변수·의존성·포트)
- [ ] 갈림길에서 선택지 + 디폴트 제시 (비대화형 폴백 포함)
- [ ] 모든 실패에 원인 + 해결법, silent 종료 없음
- [ ] 종료 시(또는 exec 직전) 상태 요약 + 접속 정보
- [ ] 사용 보고 (하네스 공통 규칙): 그 턴 보고 마지막에 `— 적용 스킬: interactive-script`
