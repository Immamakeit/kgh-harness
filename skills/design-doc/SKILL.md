# Design-Doc (설계 굳히기 + 승인 게이트)

## 핵심 원칙

**명시적 승인 전에는 구현이 존재하지 않는다.** 이 스킬의 산출물은 설계 문서와
승인 요청, 딱 두 개다. 규칙의 문구를 어기는 것은 곧 규칙의 정신을 어기는 것이다.

## 1. 문서 굳히기

- 상류 결과물(브레인스토밍 합의, 판단 게이트 판정, 영향도 조사)을 **인용해서** 채운다.
  재분석·재유도하지 않는다.
- 위치: `.harness/work/<작업명>/<YYYY-MM-DD>/설계.md`
  (컨피그 `workdocs.path`가 있으면 그것이 우선. vault에 직접 쓰지 않는다 — vault 저장은
  판정 통과 후 obsidian-cli 스킬의 몫)
- 템플릿: 설계 템플릿의 5섹션 전부 필수 — 요구사항/의도 · 작업 대상 및 영향도(코드 인용,
  일반론 금지) · 설계안 · 작업 범위/**비대상** · 승인.
- **비대상에 "없음" 금지** — 구체 항목 1개 이상. 논의에서 미뤄진 것, 알지만 안 고치는
  결함이 후보다.
- frontmatter `status`는 `작성중` → 완성 시 `승인대기`. **다른 상태값을 창작하지 않는다.**
- **이 단계에서 만드는 문서는 설계.md 하나다.** 구현계획·구현후보고를 미리 쓰지 않는다.

## 2. 승인 게이트 (HARD GATE)

문서 완성 → status `승인대기` → 사용자에게 **승인/반려만 답하면 되는 질문**을 제시하고
**멈춘다.**

**명시적 승인 전 금지 목록** (커밋 여부와 무관하다 — 워킹트리 변경도 구현이다):
- 소스 파일 수정 · 새 코드 파일 생성 · 의존성 설치 · 마이그레이션 · 설정 변경
- "미리 만들어두기", "일부만 먼저", "테스트용으로만"도 전부 금지
- 허용되는 것: **read-only 조사**(설계 보강용 코드 읽기·검색)뿐

**승인으로 인정되는 것**: "승인", "통과", "진행해" 등 설계 문서를 본 뒤의 명시적 긍정.
**승인이 아닌 것**: 문서 이전의 논의 합의 · "구현까지 해줘"라는 애초 지시 · 침묵·부재 ·
"좋네요" 같은 모호 반응(재확인한다).

게이트를 생략할 수 있는 유일한 경우: 사용자가 **"승인 없이 진행해"라고 명시적으로**
말했을 때뿐. 마감·부재·간단함은 생략 사유가 아니다.

**반려 시**: 어느 부분이 반려인지 질문 → 답을 받아 재설계 → 다시 `승인대기`. 이 루프를
반복한다.

## 합리화 반박표 (전부 실제 관찰된 위반)

| 합리화 | 반박 |
|---|---|
| "구두로 '구현까지'라고 지시했으니 선진행하고 사후 승인받자" | 지시는 작업 범위지 게이트 생략이 아니다. 사후 승인 = 게이트 부정 |
| "커밋 전이라 되돌리기 쉬우니 해두자" | 되돌리기 쉬움은 면죄부가 아니다. 반려 시 오염·비용은 실재한다 |
| "status를 '구현완료-승인대기'로 적으면 정직하다" | 상태값 창작이 곧 위반의 자백이다. 수명주기 밖 상태는 없다 |
| "오늘 마감이니 기다릴 수 없다" | 마감은 사용자에게 게이트 지연 비용을 알릴 사유지, 건너뛸 사유가 아니다 |
| "사용자가 3시간 없으니 그동안 진행하는 게 효율적" | 부재 중 할 일은 read-only 조사와 대기 안내뿐이다 |
| "설계가 자명해서 승인이 형식적이다" | 자명하면 승인도 빨리 난다. 형식적이어도 게이트는 게이트다 |

## 레드플래그 — 이 생각이 들면 멈춰라

- "일단 코드부터 만들어두고..."  - "어차피 승인될 텐데..."
- "커밋만 안 하면..."             - "사용자가 바쁘니까 알아서..."
- "이건 구현이 아니라 준비지..."   (파일이 바뀌면 구현이다)

**전부 = 멈추고 승인 요청으로 끝내라.**

## 완료 기준 (제출 전 자가 점검)

- [ ] 설계.md가 `.harness/work/<작업명>/<날짜>/`에 있고 5섹션 + ≤10자 요약 완비
- [ ] 비대상에 구체 항목 ≥1
- [ ] status = `승인대기` (창작 상태값 없음)
- [ ] 소스·의존성 무변경 (git status로 확인 가능해야 함)
- [ ] 최종 응답이 승인/반려 질문으로 끝남 + 부재 시 "승인 후 진행" 명시
- [ ] 구현계획·구현후보고 선작성 없음
- [ ] 사용 보고 (하네스 공통 규칙): 그 턴 보고 마지막에 `— 적용 스킬: design-doc`
      (여러 스킬 적용 시 쉼표로 병기). 미보고 = 위반
