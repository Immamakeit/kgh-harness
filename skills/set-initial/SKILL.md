# Set-Initial (기반 문서 세팅)

## 핵심 원칙

문서를 잘 쓰는 스킬이 아니다. **절차를 지키는 스킬이다.**
베이스라인 관찰에서 무너진 곳은 글솜씨가 아니라 네 가지였다 —
되돌릴 길 없이 덮어씀 · 선택지 없이 진행 · 질문 없이 창작 · 결정을 사후 통보.
이 스킬은 그 넷만 막는다.

**사용자가 "갈아도 된다"고 말해도, 그건 덮어쓸 권한이지 되돌릴 길을 없앨 권한이 아니다.**

## 만드는 것

| 파일 | 내용 |
|---|---|
| `PRD.md` | 무엇을 · 왜 · 누가 · 범위/비범위 · 기술 스택(+고른 이유) |
| `CLAUDE.md` | **작업 규칙 원본.** 3단계 답 + 항상 들어가는 항목 |
| `AGENTS.md` | `CLAUDE.md` 를 가리키는 포인터 3줄. **규칙 전문을 복사하지 않는다** |

방향을 뒤집지 않는다 — 규칙 원본은 `CLAUDE.md`, `AGENTS.md` 는 포인터다.
두 파일에 규칙을 두 벌 두면 갈라진다.

## 0단계 — 되돌릴 길부터 (건너뛰기 금지)

**파일을 하나라도 쓰기 전에** 이 순서를 밟는다.

1. 세 파일의 상태를 읽는다. **"없음" = 파일이 없거나 공백만.** 내용의 품질은 판정하지 않는다.
2. 하나라도 내용이 있으면 **목록을 보여준다** — 파일명 · 줄 수 · 최종 수정.
3. **되돌릴 길을 확보한다.**
   - `git status` 가 깨끗하다 → git이 곧 백업이다. 그대로 진행하고 그 사실을 알린다.
   - 더럽거나 git 저장소가 아니다 → 덮어쓸 파일마다 `<파일>.bak` 을 만들고 알린다.
   - `.bak` 도 못 만든다(권한 등) → **덮어쓰지 않는다.** 사실을 말하고 사용자 지시를 받는다.
4. 처리 방식을 고르게 한다:

```
이미 있는 문서를 찾았습니다.
  CLAUDE.md   18줄  (3일 전)
  PRD.md      없음
  AGENTS.md   없음

  1) 전부 새로 만든다 (기존 내용 대체)
  2) 없는 것만 만든다
  3) 파일별로 하나씩 묻는다
  4) 가진 문서를 붙여넣겠다
  5) 직접 입력 / 다른 방식
  6) 취소
번호 입력 [기본: 3]:
```

세 파일이 전부 없으면 이 단계를 건너뛰고 바로 1단계로 간다 — 지울 게 없으니 물을 것도 없다.

**사용자가 "취소"를 고르면 만들어둔 `.bak` 을 지운다.** 아무것도 안 바꿨는데 찌꺼기를
남기지 않는다. 지우기 전에 한 줄로 알린다.

## 질문 계약 (이 스킬의 규율)

**번호 선택형 질문을 내기 전에 `skills/preference-options/SKILL.md` 를 참조한다** —
옵션 **순서** · **기본번호** · `(추천)` 표시를 그 사람의 선호 프로필 기준으로 정한다
(플레이북 §6-1). 아래 네 요소의 틀 자체는 바뀌지 않는다 — 그 **안에서만** 조정한다.

모든 질문은 **네 가지를 전부** 갖춘다. 하나라도 빠지면 위반이다.

1. **번호** 선택지 — 최대 4개, 우선순위 순
2. **직접 입력** — 제시한 게 다 마음에 안 들 수 있다. 항상 넣는다
3. **건너뛰기** — 그 항목을 문서에서 빼거나 기본 문구로 둔다
4. **기본번호** — `[기본: N]` 으로 표시. Enter로 넘어가게 한다

**번호는 표시 순서와 항상 일치한다.** 추천을 앞으로 재배열했으면 번호도 다시
매긴다 — 플레이북 §6 질문 규칙과 같은 규율이다.

**예외 (선택지를 만들 수 없는 질문 딱 2개):** 1단계의 **"무엇을 만듭니까?"** 와
**"지금 없어서 불편한 게 뭡니까?"** 는 자유 서술로 묻는다 — 답이 임의의 문장이라 선택지
자체를 만들 수 없기 때문이다(플레이북 §6 질문 규칙과 같은 논리: "선택지를 만들 수 없을
때만 자유서술"). **이 두 문항 외에는 예외가 없다** — 1단계의 "누가 씁니까?"를 포함해
나머지 모든 질문은 위 네 요소를 그대로 따른다.

```
Q1. 커밋 메시지 형식
  1) [작업유형]: 메시지        예) [feat]: 로그인 추가
  2) Conventional Commits      예) feat: add login
  3) 직접 입력
  4) 건너뛰기 (규칙 안 적음)
번호 입력 [기본: 2]:
```

셸에서 물을 일이 생기면 `install/lib.sh` 의 `ask_choice` 를 쓴다 — 비대화형 폴백과
재질문이 이미 들어 있다.

### 질문 ID (`preference-options` 입력 계약)

선호 프로필은 **표시 문구가 아니라 안정 식별자**로 통계를 쌓는다 — 라벨 텍스트로
매칭하면 문구를 다듬을 때마다 학습이 끊긴다. 이 스킬이 내는 질문의 ID는 아래로 고정한다.
**문구를 바꿔도 ID는 바꾸지 않는다.**

| 질문 | `question_id` | `option_id` |
|---|---|---|
| 3단계 Q1 커밋 메시지 형식 | `set-initial.commit_format` | `bracket-type` / `conventional-commits` / `custom` / `skip` |
| 3단계 Q2 커밋 단위 | `set-initial.commit_unit` | `per-file-change` / `per-feature` / `custom` / `skip` |
| 3단계 Q3 브랜치 | `set-initial.branch_strategy` | `direct-main` / `feature-branch-pr` / `custom` / `skip` |
| 3단계 Q4 보일러플레이트 | `set-initial.boilerplate` | `forbid` / `allow` / `custom` / `skip` |
| 3단계 Q5 기능 개발 범위 | `set-initial.feature_scope` | `just-this-feature` / `design-for-growth` / `custom` / `skip` |
| 3단계 Q6 문서 위치 | `set-initial.docs_location` | `docs-dir` / `repo-wiki` / `custom` / `skip` |

`custom`("직접 입력")은 **추천 후보에서 항상 제외**하고, 입력한 텍스트 **원문은 기록하지
않는다** — 골랐다는 빈도만 센다. 0단계·1단계 질문에는 ID를 붙이지 않는다(아래 참조).

### `as_recommended: true` 일 때 — 3단계를 표 하나로

`preferences.as_recommended` 가 켜져 있으면 3단계 6문항을 **하나씩 묻지 않고 표 하나로
모아 보여준 뒤 자동 진행**한다(플레이북 §6-1). 근거 없는 자동 채택은 없다.

```
[as-recommended] 3단계 작업 규칙을 추천대로 자동 선택했습니다.
| 질문 | 선택 | 근거 |
|---|---|---|
| Q1 커밋 메시지 형식 | 1) Conventional Commits | 이력 6회 중 5회 |
| Q2 커밋 단위 | 1) 파일 변경마다 | 이력 부족 — 스킬 기본값 |
| Q3 브랜치 | 1) 기능 브랜치 → PR | 이력 8회 중 7회 |
| Q4 보일러플레이트 | 1) 금지 | 이력 부족 — 스킬 기본값 |
| Q5 기능 개발 범위 | 1) 지금 그 기능을 제대로 | 이력 부족 — 스킬 기본값 |
| Q6 문서 위치 | 1) docs/ | 이력 4회 중 3회 |
되돌리려면 "Q1 다시"처럼 말씀하시면 그 항목만 다시 묻습니다.
```

**자동 채택하지 않는 것 (이 스킬 범위):**

- **1단계의 자유 서술 2문항**("무엇을 만듭니까?" · "지금 없어서 불편한 게 뭡니까?") —
  선택지가 없어 추천할 옵션 자체가 없다. `as_recommended` 값과 무관하게 **자동 채택
  대상이 아니며** 그대로 대화형으로 묻는다. (1단계 "누가 씁니까?"는 선택지가 있으므로
  개인화 대상이지만, 프로젝트마다 답이 달라 이력이 쌓여도 의미가 옅다 — 통계가
  임계값을 넘지 못하면 평소대로 스킬 기본값이 나간다.)
- **0단계의 기존 문서 처리**는 자동 채택 **대상이다.** 되돌릴 길(git 청결 확인 · `.bak`)을
  이 스킬이 **게이트와 무관하게 항상 먼저** 확보하기 때문이다(플레이북 §6-1의 제외
  원칙은 "되돌릴 길이 미치지 않는" 동작만 겨냥한다). 그 확보 절차 자체는 어떤 경우에도
  생략하지 않는다.

## 1단계 — 무엇을·왜 (PRD 씨앗)

질문 3개. 이것만 묻고 더 늘리지 않는다.

- **무엇을 만듭니까?** (한 문장, 자유 서술 — 질문 계약의 예외)
- **누가 씁니까?**

  ```
  1) 나 혼자
  2) 팀
  3) 사내 전체
  4) 외부 사용자
  5) 직접 입력
  6) 건너뛰기 (문서에 안 적음)
  번호 입력 [기본: 1]:
  ```

- **지금 없어서 불편한 게 뭡니까?** (이게 '왜'가 된다, 자유 서술 — 질문 계약의 예외)

기존 코드가 있으면 먼저 읽고 초안에 반영한다. 단 **읽어서 안 것을 물어본 것으로 치지 않는다** —
코드에서 스택은 읽히지만 목적과 사용자는 읽히지 않는다.

답을 모아 `PRD.md` 초안을 보여주고 넘어간다.

## 2단계 — 스택 (추천하고, 고르게 한다)

**혼자 정하지 않는다.** 이게 베이스라인이 가장 크게 무너진 곳이다.
PRD를 근거로 3안을 만들고 **각각 왜 그런지 한 줄씩** 붙인다.

```
PRD 기준 추천:
  1) … — 왜 (추천)
  2) … — 왜
  3) … — 직접 입력
  4) 건너뛰기 (스택은 나중에)
번호 입력 [기본: 1]:
```

- 저장소·인증처럼 **답이 갈리는 결정은 전부 이 방식으로 묻는다.** 하나로 뭉뚱그려
  "스택 정했습니다"라고 하지 않는다.
- 기존 코드에 이미 스택이 있으면 그것을 1번으로 두되, 그래도 **고르게 한다.**
- 고른 값과 **고른 이유**를 `PRD.md` 기술 스택 절에 적는다.
- **여기서 프로젝트를 초기화하지 않는다** — `npm create`·`git init`·의존성 설치 금지.
  스택은 문서에 적기만 한다. 초기화가 필요하면 별도 작업으로 뺀다.

## 3단계 — 작업 규칙 6문항 (CLAUDE 씨앗)

**창작해서 채우지 않는다.** 아래 6개를 묻는다. 각 질문은 질문 계약을 따른다.

| # | 질문 | 선택지(기본) |
|---|---|---|
| Q1 | 커밋 메시지 형식 | `[작업유형]: 메시지` / Conventional Commits(기본) / 직접 / 건너뛰기 |
| Q2 | 커밋 단위 | 파일 변경마다(기본) / 기능 단위로 모아서 / 직접 / 건너뛰기 |
| Q3 | 브랜치 | main 직접 / 기능 브랜치 → PR(기본) / 직접 / 건너뛰기 |
| Q4 | 보일러플레이트 (요청 안 한 스캐폴딩·예제) | 금지(기본) / 허용 / 직접 / 건너뛰기 |
| Q5 | 기능 개발 범위 | 지금 그 기능을 제대로(기본) / 확장 대비 설계 / 직접 / 건너뛰기 |
| Q6 | 문서를 어디에 남기나 | `docs/`(기본) / 저장소 위키 / 직접 입력 / 건너뛰기(안 남김) |

**묻지 않고 항상 넣는 항목** (선택지로 낼 가치가 없는 기본값):
기존 코드 컨벤션을 따른다 · 시키지 않은 파일을 만들지 않는다.

기존 `CLAUDE.md` 를 갈아엎는 경우, **원문에 있던 규칙을 먼저 읽고** 살릴 것은 새 문서로
옮긴다. 갈아엎기는 내용을 버리는 게 아니라 형식을 다시 세우는 것이다.

**기존 문서에 이미 답이 적혀 있으면 그 값을 기본번호로 삼는다.** 예를 들어 원문에
"커밋 메시지는 영어 현재형 한 줄"이 있으면 Q1의 기본은 표의 기본값이 아니라 그것이다.
표의 기본값은 아무 단서도 없을 때 쓰는 값이다 — 사용자가 이미 정해둔 것을 표가 이기지 않는다.

## 4단계 — 생성

1. 만들 파일 목록과 줄 수를 보여주고 `1) 전문 보기 [기본] 2) 바로 생성` 을 묻는다.
2. 생성한다.
3. git 저장소면 `[docs]: 프로젝트 기반 문서 3종` 으로 **커밋을 제안한다.** 사용자가
   원치 않으면 하지 않는다.
4. `.bak` 을 만들었으면 그 경로를 알리고, 확인 뒤 지우라고 안내한다.

## 붙여넣기 경로

0단계에서 "가진 문서를 붙여넣겠다"를 고르면:
받은 텍스트를 서식에 맞춰 정리하고 **빈 칸만** 되묻는다. 이미 답이 있는 항목을 다시 묻지 않는다.

> "PRD는 받았습니다. 커밋 규칙이 안 적혀 있는데 3단계 Q1만 답해주세요."

## 합리화 반박표 (전부 베이스라인에서 실제 관찰됨)

| 합리화 | 반박 |
|---|---|
| "사용자가 갈아도 된다고 했으니 바로 덮어쓰자" | 덮어쓸 권한이지 되돌릴 길을 없앨 권한이 아니다. git 청결 확인이나 `.bak` 이 먼저다 |
| "코드를 읽으면 스택이 보이니 물을 필요 없다" | 코드에서 읽히는 건 지금 쓰는 것이지 앞으로 쓸 것이 아니다. 저장소·인증은 코드에 없다 |
| "합리적인 기본값이니 내가 정하고 알려주면 된다" | 사후 통보는 선택지가 아니다. 되돌릴 기회를 주지 않는다 |
| "질문이 많으면 귀찮아하니 줄이자" | 기본번호가 있어서 Enter 여섯 번이면 끝난다. 창작한 규칙을 나중에 고치는 게 더 귀찮다 |
| "규칙은 어차피 뻔하니 채워 넣자" | 뻔한 규칙은 기본값으로 두고 **묻는다.** 문서에 적힌 규칙은 사용자가 동의한 것이어야 한다 |
| "AGENTS.md에도 전문을 넣어야 다른 도구가 읽는다" | 두 벌은 갈라진다. 포인터 3줄이면 읽힌다 |
| "이왕 하는 김에 스캐폴딩까지 해주자" | 시키지 않은 일이다. Q4에서 보일러플레이트를 금지로 답한 사용자에게는 특히 |
