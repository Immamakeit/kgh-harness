# interactive-script — 시나리오 (RED)

vault script-standards의 실행 스킬: 대화형 단일 스크립트, 선택지·디폴트 안내,
결과 비은닉, silent 에러 금지, raw 에러 노출 금지.

## 시나리오 — 개발환경 구동 스크립트 작성

webapp-legacy에 "개발환경 구동 스크립트 만들어줘. 팀원들이 명령어 몰라도 쓸 수 있게."

**환경의 실제 조건 (스크립트가 다뤄야 할 실패 지점):**
- `node_modules` 없을 수 있음 (npm install 필요 여부 판단)
- DB 접속 정보가 환경변수 (`DB_HOST`, `DB_PASS`) — 없으면 앱이 런타임에야 죽음
- SMTP 환경변수 미설정이 일반적 (알림 경로만 실패)
- 포트 8002 선점 가능성

**기대하는 베이스라인 실패:**
- 비대화형 일방 실행 (선택지·디폴트 안내 없음)
- silent 실패: 에러 나면 raw 스택/출력 그대로 노출 or 그냥 종료
- 사전 점검 없이 실행 → 런타임에야 죽음 (DB 변수 등)
- 결과 보고 없음 (뭐가 됐고 뭐가 안 됐는지)

## 판정 기준 (GREEN에서 재사용)

| 체크 | 기준 |
|---|---|
| 대화형 + 디폴트 | 선택지가 있는 지점에서 물어보고, Enter=디폴트 명시 |
| 사전 점검 | 의존성·필수 환경변수·포트를 실행 전 점검 |
| 에러 메시징 | 모든 실패 지점에 원인 + 해결 방법 안내 (raw 에러 은닉하지 않되 해석을 덧붙임) |
| silent 금지 | 조용히 죽는 경로 없음 (set -e 후 트랩 없이 종료 등) |
| 결과 보고 | 종료 시 상태 요약 (구동 주소, 성공/실패 항목) |
| 사용자 눈높이 | 명령어 몰라도 실행 가능 (단일 진입점) |
