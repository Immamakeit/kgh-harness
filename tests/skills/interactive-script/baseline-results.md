# 베이스라인 관찰 결과 (RED — 스킬 없음)

관찰일: 2026-07-16 · "개발환경 구동 스크립트, 명령어 몰라도" 요청

## 채점

| 체크 | 결과 | 근거 (dev.sh 실물) |
|---|---|---|
| 사전 점검 | ✅ | node·.env·필수 env·node_modules·포트 5단계 선점검 (런타임 전 차단) |
| 에러 메시징 | ✅ | 모든 실패에 원인 + 해결법 (`nodejs.org에서 설치`, `.env 채우고 재실행`) + 색상 구분 |
| silent 금지 | ✅ | `set -euo pipefail`, 각 분기 명시적 exit·안내 |
| 사용자 눈높이 | ✅ | 단일 진입점 `./dev.sh`, 한국어 안내 |
| 비밀값 처리 | ✅ | .env 분리 + .gitignore + .env.example (요청 안 했는데 스스로) |
| **대화형 + 디폴트** | ❌ | **자동 가드 방식** — 선택지를 묻지 않음. script-standards의 "현재 선택지·디폴트 선택지 명확 안내"·"대화형" 미충족 |
| **결과 보고(종료 요약)** | ⚠️ | `exec npm start`로 대체돼 종료 상태 요약 없음. 실패 분기 안내는 훌륭하나 "성공 시 무엇이 준비됐는지" 요약 부재 |

## 해석 — 부분 실패 존재 → 얇은 스킬 정당

impact-scan과 달리 여기엔 **표준 대비 실질 갭**이 있다. 베이스라인 스크립트는 매우
훌륭하지만 script-standards의 두 조항을 놓친다:

1. **대화형/선택지·디폴트** — vault: "모든 스크립트는 사용자에게 현재 선택지, 디폴트
   선택지 등을 명확히 안내해야 한다." 베이스라인은 가드-후-종료라 상호작용이 없다.
   (예: node_modules 재설치, 포트 선점 시 "다른 포트로?" 같은 선택지를 묻지 않음)
2. **결과 비은닉 = 종료 요약** — 성공 경로에서 무엇이 점검·준비됐는지 요약이 없다.

## 결론 — 얇은 스킬 제작 (표준 인용형)

베이스라인의 강점(사전 점검·에러 메시징·단일 진입점)은 이미 좋으니 **의무로 고정**하고,
갭 2개(선택지·디폴트 상호작용 / 종료 요약)만 겨냥하는 얇은 스킬을 만든다.
성격상 discipline이 아니라 **표준 체크리스트(reference)** 형태.
