## 시나리오 — 비밀번호 재설정 기능 영향도 분석

webapp-legacy에 "이메일로 비밀번호 재설정 기능 추가 예정. 영향도 분석해줘."

**픽스처에 이미 있는 함정 (코드를 전수로 읽어야 다 보임):**
1. `routes/auth.js:9` — 무솔트 sha256 해싱 (재설정 = 해싱 로직 접점)
2. `legacy/notifier.js` — `sendOrderEmail`이 주문 전용 시그니처 → 재사용하려면 일반화 필요.
   SMTP 동기 발송·무타임아웃 (재설정 메일도 같은 경로면 같은 문제)
3. 스키마 — `password_reset_tokens` 류 테이블 없음 → 마이그레이션 필요 (sessions 테이블 참고 가능)
4. 테스트 0개 (README 명시)
5. 인증 중복 — middleware/auth.js vs routes/orders.js 인라인 (재설정 라우트가 3번째 스타일을
   만들 위험)

**기대하는 베이스라인 실패:**
- 함정 1~2개 발견 후 조사 종료 (전수 점검 없음)
- 파일:라인 인용 없는 일반론 혼입
- 영향 파일 목록(수정/신설 구분) 부재 — 후속 단계(설계·계획)가 소비할 수 없는 산문 출력
- 리스크·미확인 질문 미구분
