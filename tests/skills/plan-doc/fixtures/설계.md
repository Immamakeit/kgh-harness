# 설계 — 주문상태-실시간알림

## 1. 요구사항 / 의도
- 주문 상태 변경 시 접속 중인 유저에게 실시간 알림 (SSE)
- 알림 실패가 주문 처리를 막지 않게 (best-effort)

## 2. 작업 대상 및 영향도
### 2-1. 이메일이 트랜잭션 안에 있음 — `routes/orders.js:30-53`
- SMTP 발송(1~3초, 타임아웃 없음)이 트랜잭션 내 await — 실패 시 상태 변경 롤백,
  커넥션 풀(limit 5) 점유.
### 2-2. 세션 만료 검사 누락 — `routes/orders.js:8-15`
- 인라인 `checkSession`에 `expires_at` 검사 없음. `middleware/auth.js`의 `requireAuth`는 올바름.
### 2-3. SSE 인프라 부재
- 이벤트 발행 구조 없음. 클라이언트는 EventSource 사용 예정 (헤더 불가 → 쿼리 토큰 필요).

## 3. 설계안
### 3-1. SSE 모듈 신설 — `lib/sse.js` + `routes/events.js`
- 유저별 연결 레지스트리, 25초 heartbeat, `GET /api/events` (requireAuth 인증). 신규 의존성 없음.
### 3-2. 알림을 커밋 후로 분리 — `routes/orders.js` PUT 핸들러
- 조회 → UPDATE → commit → 응답. 커밋 후 이메일+SSE best-effort (실패 시 로그만).
### 3-3. 세션 만료 버그 수정
- 두 라우트의 인라인 `checkSession`을 `requireAuth` 미들웨어로 교체.
### 3-4. 실패 시나리오
- 이메일/SSE 실패 → 로그만, 주문 처리 정상. 주문 미존재 → 404.

## 4. 작업 범위 / 비대상
- **범위**:
  - `lib/sse.js`, `routes/events.js` 신설
  - `routes/orders.js`: checkSession → requireAuth 교체, 알림 커밋 후 이동, SSE 발송 추가
  - `server.js`: events 라우터 마운트
- **비대상** (알고 있으나 이번에 안 함):
  - `legacy/notifier.js`의 큐 도입·재시도·SMTP 타임아웃
  - `PUT /:id/status`에 **관리자 권한 검사가 없는 문제** (별도 작업으로 분리)
  - `routes/auth.js:9`의 무솔트 sha256 패스워드 해싱
  - 미접속 유저용 알림 저장/폴백
  - 멀티 인스턴스 확장(외부 pub/sub)
