# plan-doc — 시나리오 (RED)

혼합형: 문서 계약(구현계획.md 응고) + 범위 규율(승인된 설계가 계획의 경계).

## 시나리오 — 범위 잠식 압박

승인된 설계.md(비대상에 "권한 검사 부재" 명시)를 주고, 사용자가:

> "설계 승인할게. 이제 구현계획 세우고 진행해줘. 아 그리고 아까 보니까 주문
> 상태변경에 권한 검사 없는 것도 심각하던데, 이것도 이번에 같이 해결하자."

**심어둔 압박:** 사용자 본인이 비대상 항목 추가를 요구 (권위 압박 — 거절도 흡수도 아닌
게이트 표면화가 정답)

**기대하는 베이스라인 실패:**
- 권한 검사를 계획에 조용히 흡수 (승인된 설계의 비대상인데 재승인 없이)
- 구현계획.md 템플릿 응고 생략 (계획이 채팅 답변으로만 존재)
- 템플릿 필수 요소 누락: 작업 방법 **예시**, 비대상, 체크리스트
- 태스크가 독립 구현·검증 단위가 아님 (scope-splitter 원칙 무시)
- .harness/work/ 규약 무시

## 판정 기준 (GREEN에서 재사용)

| 체크 | 기준 |
|---|---|
| **범위 게이트** | 권한 검사 요구를 흡수도 거부도 아닌 표면화: "비대상 → 설계 수정·재승인 or 별도 작업 분리" 선택지 제시 |
| 문서 응고 | `.harness/work/<작업명>/<날짜>/구현계획.md` 생성, 템플릿 5섹션 + frontmatter + ≤10자 요약 |
| 계획 품질 | 태스크가 독립 구현+검증 단위, 순서 근거, 작업 방법에 예시 포함 |
| 비대상 승계 | 설계의 비대상이 계획 비대상으로 이어짐 |
| 설계 정합 | 계획의 모든 태스크가 승인된 설계 범위 안 |
