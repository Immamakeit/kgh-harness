(`git status --porcelain` 확인, `find -newer` 확인 — 새 파일 없음). 즉 실행하지 않은

**2차 시도(SKILL.md 복사 후 재실행)**: 이번엔 실제로 Claude Code 자체의 프로젝트 메모리

## 시나리오 2 — 열람

> "내 선호 프로필 보여줘. 어디에 저장되어 있는지 경로도 같이 알려줘."

실제로 경로를 댔다 — 그러나 그 경로는 **하네스가 정의한 곳이 아니라 Claude Code
자체의 프로젝트별 메모리 디렉터리**다:

```
/home/ghkim/.claude/projects/<이 픽스처 경로를 해시한 이름>/memory/
```

이 경로는 (a) **프로젝트마다 다르다** — 설계가 요구하는 "사람에게 붙는 전역 취향"과
정반대로 **프로젝트에 묶여** 있다. 다른 프로젝트에서 같은 질문을 하면 이 이력이 안 보인다.
(b) 하네스 문서 어디에도 적혀 있지 않다 — 사용자가 다음에 또 물어보면 매번 재발견해야
한다. (c) `question_id`/`option_id`/카운트 구조가 없고, 자연어 설명 전체를 그대로
저장·출력한다.

## 시나리오 3 — 삭제

> "선호 프로필 초기화해줘."

확인을 받으려는 시도는 있었다(3지선다: 전체 삭제/답만 삭제/정렬 규칙만 삭제) — 이 점은
설계 의도(§3-4-4 "프로필 삭제는 항상 확인")와 우연히 방향이 같다. 그러나:
- 이건 **일반적인 파괴적 작업 신중함**이지, "선호 프로필은 되돌릴 길이 없는 유일한
  예외라서 `as_recommended`와 무관하게 항상 확인한다"는 **설계된 규칙이 아니다**
  (그런 규칙이 있다는 언급 자체가 없다).
- `.bak` 백업은 **기본 동작이 아니라 사용자가 요청해야 하는 옵션**으로 제시됐다 —
  set-initial의 "되돌릴 길부터, 건너뛰기 금지" 규율과 다르다.

## 실물 증거

`claude -p`가 실제로 만든 파일 (Claude Code 자체 메모리 기능, 하네스와 무관):

```
~/.claude/projects/-tmp-...-scratchpad-pref-fixture-todo-cli/memory/
├─ MEMORY.md
├─ project-setup-defaults.md
└─ prefer-history-weighted-option-order.md
```

`project-setup-defaults.md` 전문(발췌):

> 프로젝트 초기 세팅 질문에 대한 사용자의 고정 선택 (2026-08-25 기준, 직전 3개
> 프로젝트에서 매번 동일하게 답함):
> - **커밋 메시지 형식**: Conventional Commits (`feat:`, `fix:`, `chore:` …)
> - **브랜치 전략**: 기능 브랜치 → PR (master/main 직접 커밋 안 함)

자연어 문장 그대로가 저장 단위다 — `question_id: set-initial.commit_format` /
`option_id: conventional-commits` 같은 안정 식별자가 아니다. 표시 문구가 조금만
바뀌어도(예: SKILL.md의 옵션 문구를 수정하면) 이 기록은 매칭이 끊긴다.

**추가 시도(시나리오 4, 참고용)**: 자유서술 답변("회사 내부 회식비 정산…", "사번
오타로 두 번 사고남" 등 구체적 사내 정보 포함)을 실제로 흘려보내 원문이 그대로
저장되는지 확인하려 했으나, `--resume`로 세션을 이어 붙인 시도가 90초 타임아웃으로
끝나 **결정적 증거는 얻지 못했다**. 다만 시나리오 1·2에서 이미 "자연어 문장을 그대로
저장한다"는 패턴이 확인됐으므로, 자유서술 원문도 같은 방식으로 저장될 개연성이
높다 — 이 관찰만으로 확정하지 않고 정직하게 미확인으로 남긴다.
