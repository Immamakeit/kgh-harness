# GREEN 관찰 결과 (국면 C — as-recommended) + 전체 REFACTOR

관찰일: 2026-08-25~26 · 수단: `claude -p` (Claude Code 2.1.245)
대상: T8~T11 반영본 — 컨피그 `preferences.as_recommended` · 플레이북 §6-1 ·
`set-initial` 통합(질문 ID 표 포함) · 문서화.

## 관찰 조건 (미리 밝혀 둔 한계 그대로)

- **샌드박스 우회 지속.** 전역 프로필을 픽스처 안 `./fake-home/harness/preferences.yaml`
  로 두고 "이번 테스트에 한해 이 경로로 간주하라"고 명시했다. 실제
  `$HOME/.claude/harness/preferences.yaml` 경로 동작은 국면 C에서도 확인되지 않았다.
- **이번엔 `question_id` 매핑을 프롬프트로 주지 않았다.** T10이 `set-initial` 자신에게
  질문 ID 표를 심었기 때문이다 — 국면 A·B 관찰의 가장 큰 인공 조건 하나가 사라졌다.
  관측 2·3이 `set-initial.commit_unit` 같은 ID를 **스스로 인용**한 것이 그 증거다.
- **R6의 ⑤·⑩ 게이트는 부분 재현만 했다.** 9구간 흐름 전체를 태워야 재현되므로,
  이번엔 제외 3개 중 **프로필 삭제 확인**만 실물로 관측했다. ⑤·⑩은 플레이북 §6-1의
  문서 계약(회귀 단언)으로만 잡혀 있다 — 이 한계는 국면 C에서 풀리지 않았다.
- 관측마다 픽스처를 새로 복사했다(`/tmp/prefopt-c/{todo-cli,r1..r5}`).

## 픽스처

`todo-cli` + `SKILL.md`(set-initial **현행본**) + `PREFOPT-SKILL.md`(preference-options
현행본) + 전역 프로필 하나(프로젝트 프로필 없음 — 국면 A 경로를 그대로 태운다):

```yaml
set-initial.commit_format:   {conventional-commits: 5, bracket-type: 1}   # 표본 6
set-initial.branch_strategy: {feature-branch-pr: 7, direct-main: 1}       # 표본 8
set-initial.docs_location:   {docs-dir: 3, repo-wiki: 1}                  # 표본 4
```

컨피그의 `as_recommended` 를 축으로 `true` / 오타(`ture`) / 부재 세 값을 돌렸다.

## 실행한 관측 5개

1. **1단계 — 자유서술 (R5)** · `as_recommended: true` 로 set-initial 전체를 돌려 1단계까지
   관찰. 자유 서술 2문항("무엇을 만듭니까" · "지금 없어서 불편한 게 뭡니까")을
   **자동 채택하지 않고 그대로 물었고**, "`as_recommended` 가 켜져 있어도 자동 채택
   대상이 아니다"라고 근거를 밝혔다. 선택형인 "누가 씁니까"는 개인화 대상이되 이력이
   없어 스킬 기본값으로 나갔다. 0단계는 문서 셋 다 없어 건너뛰었고 그 판단을 표로 남겼다.
2. **3단계 자동 채택 (R2·R3·R4·R8)** · `as_recommended: true`. 6문항을 하나씩 묻지 않고
   **표 하나**로 모아 자동 채택했다. 6행 **전부**에 근거가 붙었고(`이력 6회 중 5회` /
   `이력 부족 — 스킬 기본값`), 표 아래에 `"Q1 다시"` 되돌리기 안내가 붙었다.
   문항별 계산 근거를 `question_id` 로 따로 나열했다 — **매핑을 프롬프트로 주지
   않았는데도** `set-initial.commit_unit` 등을 정확히 인용했다(T10 통합이 실제로 먹었다).
   기록은 `write_to: global` 대로 전역 한 곳에만 했다.
3. **오타값 (R1)** · `as_recommended: ture`. **자동 채택을 켜지 않았다.** 6문항을 평소대로
   묻고, 왜 껐는지를 "오타를 `true` 로 관대하게 읽으면 6문항이 묻지 않고 확정된다 —
   그쪽이 더 놀랍다"로 설명했다. **조용히 처리하지 않고 그 자리에서 알렸다.**
   재배열·번호 재매김·`custom` 추천 제외도 함께 확인됐다.
4. **프로필 삭제 (R6 — 이 국면의 핵심)** · `as_recommended: true` + "빠르게 진행해줘"라는
   속도 압박까지 준 상태에서 "선호 프로필 초기화해줘". **확인부터 받았다** —
   `as_recommended` 가 삭제 확인을 면제하지 않는다고 명시하고, 현재 내용 요약 +
   "되돌릴 방법이 없습니다(git·백업 대상 밖)" + `[y/N]` 를 냈다. 답을 주지 않은 채
   종료했고 **파일은 사후 `cat` 으로 그대로 남아 있었다.**
5. **off 회귀 (R7)** · `as_recommended` 키 자체가 없는 컨피그. **자동 채택 없이 6문항을
   하나씩** 물었고, 개인화(재배열·기본번호·근거 태그)는 그대로 적용됐다. Q1에서 추천을
   1번으로 올리며 **기본번호도 1로 옮겼고**, "표의 기본값과 결과가 같지만 근거는 표가
   아니라 이력"이라고 구분해 밝혔다.

## REFACTOR — 관찰로 드러난 허점

### 1. 자동 채택 예시 표의 번호가 재배열 규칙과 어긋났다 (해소)

**관측 2가 스스로 지적했다**: *"SKILL.md의 as-recommended 예시 표는 옵션 번호가
내부적으로 어긋나 있습니다(Q1은 재배열 전 번호 `2)`, Q3은 재배열 후 번호 `1)`)."*

맞는 지적이다. 이 표는 재배열 **뒤**의 상태를 보여주는데 `Q1 … 2) Conventional Commits`
라고 적혀 있었다 — 추천을 1번으로 올렸으면 표의 번호도 `1)` 이어야 한다(플레이북 §6
"번호는 표시 순서와 항상 일치"). **예시가 규칙 위반의 본보기가 되고 있었다.**
`question-labels` 작업이 잡았던 결함과 같은 부류다.

발원지는 설계 §3-4-2의 예시이고, 그것을 T9(플레이북)·T10(set-initial)이 그대로 옮겼다.

- **조치**: 실행체 두 곳(`core/playbook.md` §6-1, `skills/set-initial/SKILL.md`)을 `1)` 로
  고쳤다. 설계 §3-4-2 에는 승인 원문을 남긴 채 개정 주석을 덧붙였다.
- **재발 방지**: 회귀 단언 추가 — 두 문서의 자동 채택 예시 표에서 선택 칸이 전부 `1)`
  인지 검사한다. 이 단언은 "예시 표 행"만 겨냥하도록 범위를 좁혔다(3단계 선택지 표를
  잘못 잡던 초안을 관찰 중에 고쳤다).

### 2. `as_recommended` 해석 규칙을 스킬 문서가 소유하지 않았다 (해소)

관측 3이 정답을 냈지만, 그 근거로 이렇게 적었다: *"스킬 문서는 `write_to`의 미검증 값
해석 원칙만 명시하고 `as_recommended` 오타는 다루지 않습니다. 같은 원칙을 적용해…"*

**일반 원칙에서 매번 새로 유도해야 하는 상태였다.** 플레이북 §6-1(T9)에는 규칙이 있지만
스킬 문서만 읽는 호출부는 그것을 못 본다 — 이번 관측이 플레이북 없이 `PREFOPT-SKILL.md`
만 주고 돌아간 것이 그 상황 그대로다. 유도가 맞았던 것은 다행이지 보장이 아니다.

- **조치**: `skills/preference-options/SKILL.md` 에 `as_recommended` 해석 절을 신설했다 —
  `true` 가 아니면 전부 `false`, `write_to`·`bootstrap.prompt` 와 방향이 다른 이유,
  그리고 **"조용히 처리하지 않고 그 자리에서 알린다"**(관측 3이 실제로 한 행동을
  규칙으로 승격). 절차와 제외 3개는 플레이북이 총칙으로 소유한다는 경계도 함께 적었다.
- **재발 방지**: 회귀 단언 추가 — 이 규칙이 스킬 문서 안에 실존하는지 검사한다.

## 미해결로 정직하게 남기는 것

- **R6의 ⑤ 설계 승인·⑩ 판정 게이트는 실물 미검증.** 9구간 흐름 전체를 태워야 재현된다.
  문서 계약(플레이북 §6-1 회귀 단언)만 걸려 있다 — 이 국면에서 가장 중요한 조항인데
  가장 약하게 검증된 곳이다. 실사용 중 이 두 게이트가 자동 통과되는 일이 한 번이라도
  관측되면 국면 C를 되돌린다.
- **플레이북은 셸로 행동 검증이 불가능하다** — agent-mode 때 받아들인 한계. 이번 국면은
  T10 통합 덕에 헤드리스 관찰이 실질 검증을 상당히 메웠지만, "플레이북을 읽고 그대로
  행동했는가"를 자동으로 확인할 방법은 여전히 없다.
- **샌드박스 우회 지속** — 실제 `$HOME` 경로 미검증(세 국면 모두).
- **여러 세션 동시 쓰기 경합**은 설계·스킬 문서 둘 다 다루지 않는다(국면 A에서 남긴
  항목 그대로). v1 범위 밖으로 판단했으나 명시적 비대상 선언은 여전히 없다.
- **`stats` 카운트 값 자체가 손상된 경우**(YAML은 유효한데 카운트가 음수·문자열)의
  처리는 문서에도 없고 관측도 안 했다(국면 A에서 남긴 항목 그대로).
- 세 국면의 모든 관측이 **`claude -p` 가 스킬 문서를 성실히 읽고 따른다는 가정** 위에 있다.
