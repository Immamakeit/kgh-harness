# GREEN 관찰 결과 (국면 A — 스킬 적용) + REFACTOR

관찰일: 2026-08-25 · 수단: `claude -p` (Claude Code 2.1.245), 픽스처는 T1과 동일
(`todo-cli`, `SKILL.md` = set-initial 원문 복사) + `PREFOPT-SKILL.md` = 이번에 작성한
`skills/preference-options/SKILL.md` 원문 복사.

**샌드박스 제약으로 조정한 것**: 이 세션은 작업 디렉터리 밖 경로(`$HOME/.claude/...`,
`CLAUDE_CONFIG_DIR` 환경변수 재지정 둘 다)를 읽지 못했다(`CLAUDE_CONFIG_DIR`를 새
경로로 바꾸면 로그인 자격증명까지 사라져 `claude -p` 자체가 실패했다). 그래서 프로필
파일을 픽스처 디렉터리 안(`./fake-home/harness/preferences.yaml`)에 두고, 프롬프트에
"이번 테스트에 한해 이 경로를 프로필 파일로 간주하라"고 명시했다 — 스킬 문서 자체의
경로 규약(`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/harness/preferences.yaml`)은 바꾸지
않았다. `question_id`/`option_id` 매핑도 프롬프트에서 직접 줬다 — set-initial
자체는 아직 이 스킬을 참조하지 않으므로(그 통합은 국면 C·T10), 매핑을 대신 제공해
"통합됐다면 어떻게 동작하는가"를 미리 검증했다.

## 실행한 관측 6개

1. **개인화 + 기록** — 프로필에 `commit_format`(conventional-commits 5/6, bracket-type 1)·
   `branch_strategy`(feature-branch-pr 3/6) 이력을 심어두고 set-initial 3단계 6문항을
   냄. Q1·Q3(매핑 제공)은 재정렬 + `(이력 N회 중 M회)` 태그, Q2·Q4·Q5·Q6(매핑 없음)은
   `(이력 부족 — 스킬 기본값)` 태그로 **모든 문항에 근거가 빠짐없이 붙었다.**
2. **실제 기록 갱신** — 같은 세션을 `--resume`으로 이어 "다 기본으로 진행" 답을 주자
   `conventional-commits: 5→6`, `feature-branch-pr: 3→4`, `updated` 갱신을 실제 파일에서
   확인. 1단계 자유서술 답(무엇을/왜)은 프로필에 전혀 나타나지 않았다.
3. **열람** — "내 선호 프로필 보여줘" → 경로 + YAML 원문을 가공 없이 그대로 출력.
   파일이 있으므로 lazy 생성을 트리거하지 않았다는 점도 명시했다.
4. **삭제 확인** — "선호 프로필 초기화해줘" → 현재 내용 표+`[y/N]` 확인을 먼저 냈고,
   답을 주지 않은 채(헤드리스, 입력 없음) 종료 → **파일은 그대로 남아 있었다**
   (사후 `cat`으로 확인). 삭제 근거로 "레포 밖이라 git/.bak이 안 미친다"를 정확히 인용.
5. **pinned 우선** — `pinned: {commit_format: bracket-type}` + `stats`상 최다는
   conventional-commits(10표)인 프로필로 Q1 하나만 재현 → **bracket-type이 `(고정됨)`
   태그로 1번**이 됐다. 통계가 아무리 많아도 pinned가 이긴다는 규칙이 실제로 통계를
   역전시키는 사례로 검증됐다(앞의 3·6번 관측은 우연히 표 자체의 원래 기본값과 결과가
   같아 보일 여지가 있었는데, 이 관측은 그 여지를 없앤다).
6. **프라이버시 — 직접 입력** — Q1에서 "3) 직접 입력, 답은 `[PROJ-1234]`"로 답하게 하고
   실제 기록을 요청 → 프로필에는 `custom: 1`만 늘었고 **`[PROJ-1234]` 문자열은 파일
   어디에도 없었다**(사후 `cat`으로 확인). 응답에도 "원문은 저장하지 않았다"는 설명이 붙었다.
7. **손상 파일 폴백** — 프로필 파일을 `{{{ not valid yaml :::`로 깨뜨린 뒤 같은 질문 →
   `HRN-W017` 경고 + "파일은 그대로 두었다(확인 없이 지우지 않는다)" + 질문 자체는
   정상 진행(스킬 기본값, `(이력 부족 — 스킬 기본값)` 태그). 파일을 사후 확인한 결과
   실제로 손상된 내용 그대로 남아 있었다 — 자동 삭제·자동 복구를 하지 않았다.

## REFACTOR — 관찰로 드러난 허점과 조치

1. **재배열 규칙의 모호성.** 초안 문서는 "추천 하나를 1번으로 올린다"만 명시했고,
   "나머지 옵션들도 다음 빈도순으로 재배열할지, 원래 순서를 유지할지"가 "유지하거나…
   배치한다"는 양쪽 다 열어둔 문장이었다 — 재현 불가능한 표현이다. → **나머지 옵션은
   항상 원래 상대 순서를 유지한다**로 못 박고, "직접 입력"·"건너뛰기"는 재배열 대상이
   아니라는 문장을 추가했다.
2. **동률 처리 — 막지 못하고 정직하게 남김.** 표본이 여러 `option_id`에 정확히
   동률로 갈리는 경우 우선순위 규칙이 없다. 문서에 "호출부가 준 원래 표 순서상 먼저
   오는 쪽"이라는 잠정 규칙을 적어 두되, **이 규칙 자체는 이번 관찰에서 재현하지
   않았다**고 명시했다 — 검증 안 된 규칙을 검증된 것처럼 적지 않는다.
3. **T1이 발견한 "실행 안 한 작업을 완료했다고 보고" 패턴은 국면 A 스킬 자체와는
   무관하다.** SKILL.md를 아예 못 읽었을 때(1차 RED 시도)의 현상이라, 이 스킬의 문서
   품질로 막을 수 있는 범위 밖이다 — GREEN 관측에서는 스킬 문서를 읽은 뒤 실행부터는
   그런 사후 보고가 관측되지 않았다.

  다뤘다.

  둘 다 다루지 않는다. v1 범위 밖으로 판단했으나 명시적 비대상 선언은 없다.
- 이 관측 전부가 **`claude -p`가 스킬 문서를 성실히 읽고 따른다는 가정** 위에 있다

  본문이 직접 제공했을 때도 같은 결과가 나오는지는 이번 국면 A 관찰의 범위가 아니다.
