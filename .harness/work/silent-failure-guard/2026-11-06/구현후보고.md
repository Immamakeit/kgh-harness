# 구현 후 보고 — silent-failure-guard

## 1. 변경 요약

볼트 대조 6건 중 사용자가 고른 **① vault_root 가드 + ⑥ fail-open 가시성**. 둘 다 볼트
`script-standards.md` 의 *"silent 에러 엄격 금지 · 절대 결과를 숨기지 않는다"* 위반이었고,
둘 다 내가 만들었거나 방치한 것이다.

### ① `vault_root` 가 죽은 경로를 가리켜도 아무것도 안 잡았다

- `HRN-W023` 신설 — 경고·비차단이되 **⑪ 저장은 건너뛴다.**
  - 차단하지 않는 이유: 볼트가 다른 PC 것이거나 드라이브가 안 붙었을 수 있다.
  - 쓰기를 막는 이유: vault 밖 유령 트리에 쓰고 "저장 완료"를 보고하는 것은 **침묵보다
    나쁘다** — 사용자가 확인했다고 믿게 만든다.
- 3중 방어: 검증기(`validate_config.py`) → `setup`/`update` 요약 → `obsidian-cli` 스킬의
  저장 절차 1단계(마지막 방어선).
- `setup` 의 vault 탐지가 `CONFIG_CREATED -eq 1` 안에 갇혀 기존 설치를 영구 방치하던 것을
  고쳤다. **탐지기는 멀쩡했고 호출 조건이 좁았던 것이 원인이다.**
- `lib.sh vault_root_state()` 로 bash·python 양쪽의 상태 이름을 통일(`ok|empty|missing`).
- 이 레포 자신의 `vault_root` 를 실제 경로로 교정 — 2026-08-14 에 지정한
  `/mnt/c/gh-obsidian-vaults/LLM-Wiki` 는 상위 폴더부터 소멸해 있었다.

### ⑥ fail-open 경고가 아무에게도 안 갔다

공식 훅 문서: *"Claude **never** sees stderr from a hook that exits 0."* 즉 `exit 0` +
stderr 는 사용자도 모델도 못 보고 디버그 로깅 사용자만 본다. 주석에 `silent 금지` 라고
적고 silent 에러를 만들었다.

**3중 출력**으로 교체 — `.harness/gate.log`(확실) + stdout JSON
`systemMessage`·`additionalContext`(최선 노력, PreToolUse 에서 **실측 미확인**) +
stderr(디버그 로깅용). `install/approve --list` 가 누적 건수를 보고한다.

**`permissionDecision` 은 넣지 않았다.** `"allow"` 는 권한 프롬프트를 건너뛴다 —
fail-open 의 뜻은 "훅이 없는 것처럼 진행"이지 권한 승격이 아니다. 키 부재를 회귀로 고정.

## 3. 검증 결과

- **린트**: `shellcheck -S warning` — **0건** (`setup`·`update`·`approve`·`lib.sh`·
  `validate-config`·훅 2종·회귀 스위트). `py_compile` 통과.
- **코드리뷰**: 자체 점검으로 결함 4건을 잡아 고쳤다 (§3-1).
- **요건 충족**: 계획서 §5 체크리스트 T1~T12 전부 완료. 회귀 **411 PASS / 0 FAIL**
  (383 → 28건 추가). 컨피그 검증 소스·템플릿 양쪽 rc=0.

### 3-1. 구현 중 잡은 결함 4건

1. **같은 침묵이 세 곳이었다** (설계는 한 곳만 봤다). `fail_open` 외에 **휴리스틱 열화
   경고**와 **`gate.enforce: warn` 모드**도 `exit 0 + stderr` 였다. warn 모드의 경고를
   아무도 못 보면 **warn 은 사실상 off** 다. 세 곳 모두 고쳤다.
2. **`grep -E '\t'` 는 탭이 아니다.** GNU grep ERE 가 `\t` 를 탭으로 읽지 않아
   `--list` 의 fail-open 집계가 **항상 0건**이었다. `printf '\t'` + `-F` 로 교체.
3. **`list_tasks` 가 `work/` 없으면 조기 반환한다.** 그 안에 fail-open 보고를 뒀더니
   **작업을 시작한 적 없는 새 설치에서 게이트 고장이 영원히 안 보였다.** 회귀가 잡았다.
   `report_fail_open` 으로 분리 — 게이트 고장은 흐름 시작 여부와 무관한 사실이다.
4. **승인 마커를 커밋에서 빠뜨렸다.** 마커는 추적 대상(기존 14건)인데 T1~T7 뒤로 밀렸다.
   이 파일이 git 에 남는 것이 설계의 일부다(승인 시각·경로가 diff 에 드러나 "조용히 승인"이
   불가능해진다).

### 3-2. 설계에서 벗어난 점 1건

경고를 즉시 내지 않고 `note()` 로 **모았다.** 휴리스틱 경로는 뒤에서 차단(exit 2)으로
끝날 수 있고, 그때는 stdout JSON 이 아니라 **차단 메시지 본문**에 섞어야 모델이 본다
(차단의 stderr 는 모델에게 전달되는 것이 문서로 확인된 유일한 경로다). 설계 §3-3 은
`fail_open` 한 곳만 상정했다.

## 4. 직접 확인 시나리오

> 모두 소스 레포 루트에서. 실측으로 확인한 그대로다.

1. **죽은 vault 경로가 보고되는가**
   ```bash
   cp harness.config.yaml /tmp/c.yaml
   sed -i 's#gh-vaults/llm-wiki#gh-NOWHERE/none#' /tmp/c.yaml
   python3 -I install/validate_config.py /tmp/c.yaml config/schema.yaml adapters . ; echo "rc=$?"
   ```
   - **기대 결과:** `⚠ HRN-W023 — storage.vault_root 의 경로가 없습니다` + 조치 2경로,
     그리고 `rc=0` (**비차단**).

2. **정상 경로에서는 조용한가**
   ```bash
   ./install/validate-config | grep -c W023
   ```
   - **기대 결과:** `0`.

3. **fail-open 이 3경로로 나오는가**
   ```bash
   T=$(mktemp -d); cp harness.config.yaml "$T/"
   mkdir -p "$T/.harness/work/t/2026-11-06"; touch "$T/.harness/work/t/2026-11-06/설계.md"
   printf 'broken' | CLAUDE_PROJECT_DIR="$T" ./adapters/claude/hooks/pre-tool-use.sh; echo "rc=$?"
   cat "$T/.harness/gate.log"
   ```
   - **기대 결과:** stdout 에 `systemMessage` 를 가진 JSON 1줄, stderr 에 `HRN-W021`,
     `gate.log` 에 탭 5필드 1줄(2번째가 `W021`), `rc=0`.
   - **그리고 JSON 에 `permissionDecision` 이 없어야 한다** — 있으면 권한 승격이다.

4. **미무장 상태에서 조용한가** (매 도구 호출의 잡음 확인)
   ```bash
   printf '{"tool_name":"Edit","tool_input":{"file_path":"install/setup"}}' \
     | CLAUDE_PROJECT_DIR="$PWD" ./adapters/claude/hooks/pre-tool-use.sh | wc -c
   ```
   - **기대 결과:** `0` (0바이트).

5. **차단 메시지가 실제로 존재하는 경로를 안내하는가**
   ```bash
   mkdir -p .harness/work/zz/2026-11-06 && touch .harness/work/zz/2026-11-06/설계.md
   printf '{"tool_name":"Edit","tool_input":{"file_path":"install/setup"}}' \
     | CLAUDE_PROJECT_DIR="$PWD" ./adapters/claude/hooks/pre-tool-use.sh
   rm -rf .harness/work/zz
   ```
   - **기대 결과:** `HRN-E016` 차단(rc=2), 안내 경로가 `<레포>/install/approve` —
     `.harness/install/approve`(없는 경로)가 아니다.

6. **비대화형 설치가 묻지 않고 값을 보존하는가**
   ```bash
   W=$(mktemp -d); git -C "$W" init -q; ./install/setup "$W" </dev/null >/dev/null 2>&1
   sed -i 's#^  vault_root: .*#  vault_root: /nonexistent/x#' "$W/harness.config.yaml"
   ./install/setup "$W" </dev/null 2>&1 | grep -E "W023|지정하시겠습니까"
   grep vault_root "$W/harness.config.yaml"
   ```
   - **기대 결과:** `HRN-W023` 2회(setup + 검증기), `지정하시겠습니까` **0회**,
     컨피그 값은 `/nonexistent/x` 그대로.

7. **전체 회귀**
   ```bash
   ./tests/install/run-tests.sh | tail -3
   ```
   - **기대 결과:** `PASS: 411  FAIL: 0`.

### 남은 사실 (과장하지 않는다)

- **stdout JSON 두 필드는 실측 미확인이다.** 공식 문서가 *"Some events discard it, and
  each event's section says so"* 라고만 하고 PreToolUse 절은 `systemMessage` 를 언급하지
  않는다. 그래서 **로그를 중심**에 뒀다. 실제 Claude Code 세션에서 fail-open 을 유발해
  두 필드가 표시되는지 확인하면 이 미지(未知)가 닫힌다.
- **셸 경유 임의 쓰기는 여전히 열려 있다** — 이 작업은 게이트의 *가시성*을 고쳤고
  *포위망*을 넓히지 않았다. 표류를 잡는 장치지 적대적 우회를 막는 장치가 아니다.
- **볼트 대조 ②③④⑤는 손대지 않았다** — MOC 의무 위반(고아 노트 39개) · 승인 원장
  이원화(`.approved` vs `설계.md` §5) · `workflow.md` 의 낡은 폴더 구조 기술 · ⑤ 집행이
  볼트에 역류되지 않음. 그중 **②가 가장 크다**(통과할 때마다 고아가 3개씩 늘어난다).
