# 구현 후 보고 — agent-mode

## 1. 변경 요약

최상위 컨피그 키 `agent_mode: single | multi` 를 신설해 **디스패치 여부의 전역 마스터
스위치**를 만들었다. `single` 이면 `stages.<구간>.dispatch` 값은 전부 무시된다.

| 태스크 | 결과 |
|---|---|
| T1 | `config/schema.yaml` `top_level` 에 `agent_mode` 등록 + 템플릿·루트 컨피그 반영 |
| T2 | 플레이북 §1-2-1 — `agent_mode` 해석 규칙 (§1-5 원칙의 사례로 연결) |
| T3 | 플레이북 §3 — 실효 모드 판정 + 사전/사후 2단계 감지 + `HRN-W016` 열화 |
| T4 | 회귀 테스트 4종 (키 없음 / `single` / `multi` / 오타값) |
| T5 | `PRD.md` §8의 `HRN-W016` `(예정)` 표기 제거 + §4 각주 |
| T6 | ⑧ 권고 반영 — §3 번호 겹침 해소 (판정 단계 `0~3` vs 프롬프트 `①~④`) |
| T7·T8 | 플레이북 **규칙 실존 계약** + **절 참조 정합** 테스트 (11케이스) |
| T9 | `HRN-W016` 판단 근거 명시 의무화 |
| T10 | `single` 실사용 관찰 1회 (`claude -p`, 기록 보존) |
| T11 | §3-8 별도 승인 후 — 플레이북 §6에 `model` 미적용 고지 |

**"덜 놀라운 쪽"은 `multi` 로 정했다.** 기존 설치본은 `agent_mode` 를 모르는 채
`dispatch` 값대로 이미 돌고 있다. 누락·오타를 `multi` 로 해석하면 그 동작이 유지되지만,
`single` 로 해석하면 잘 돌던 구간이 조용히 인라인으로 바뀐다 — 컨피그를 안 건드렸는데
동작이 바뀌는 쪽이 더 놀랍다. `bootstrap.prompt`(모르면 묻는다) ·
`preferences.as_recommended`(모르면 멈춘다) 와 방향은 달라도 §1-5의 같은 원칙이다.

## 4. 직접 확인 시나리오

1. 현재 모드를 확인한다.
   ```bash
   cd ~/dev/kgh-dev-harness && grep -A4 '^agent_mode' harness.config.yaml
   ```
   - **기대 결과:** `agent_mode: multi` + 주석 3줄(single 의미, 검증 안 됨, 오타는 multi).

2. 싱글로 바꾸고 검증한다.
   ```bash
   sed -i 's/^agent_mode: multi/agent_mode: single/' harness.config.yaml
   ./install/validate-config | tail -3
   ```
   - **기대 결과:** `검증 통과`. 이 상태로 새 세션을 열고 작업을 지시하면 impact·implement·
     verify가 서브에이전트 없이 메인 세션에서 돌고, 구간 보고에 그 사실이 적힌다.
   ```bash
   sed -i 's/^agent_mode: single/agent_mode: multi/' harness.config.yaml   # 원복
   ```

3. **부정 케이스 ①** — 오타를 내도 막히지 않고 `multi` 로 취급된다.
   ```bash
   sed 's/^agent_mode: multi/agent_mode: bogus/' harness.config.yaml > /tmp/t.yaml
   ./install/validate-config /tmp/t.yaml | tail -3
   ```
   - **기대 결과:** `검증 통과` (구조만 검사하므로). 플레이북 §1-2-1에 따라 흐름에서는
     `multi` 로 해석된다.

4. **부정 케이스 ②** — 키가 아예 없는 구버전 컨피그도 통과한다.
   ```bash
   grep -v '^agent_mode' harness.config.yaml | grep -v '^ *# single이면\| *# 주의: 이 값은\| *# 값은(오타' > /tmp/legacy.yaml
   ./install/validate-config /tmp/legacy.yaml | tail -3
   ```
   - **기대 결과:** `검증 통과`. 하위호환.

5. 전체 회귀.
   ```bash
   bash tests/install/run-tests.sh | tail -2
   ```
   - **기대 결과:** `PASS: 161  FAIL: 0`

합리적이었지만, **코드 체계에 구멍이 있다.** 이 관찰이 없었으면 드러나지 않았을 결함이다.
`agent-mode` 범위 밖이라 고치지 않고 기록만 남긴다.
