# 구현 후 보고 — branch-strategy

## 1. 변경 요약

GitHub 원격의 브랜치 보호를 **대화로 세워주는 스킬**을 만들었다. 하네스 스킬 9번째.

| 태스크 | 결과 |
|---|---|

| T3 REFACTOR | 재관찰 + "사전 승인을 받아도 프리뷰를 생략하지 않는다" 문구 보강 |

| 델타 2 | 오케스트레이터 직접 재관찰 2건 (T6이 남긴 공백 해소) |

## 2. RED이 잡아낸 것

베이스라인(스킬 없음)은 6개 시나리오 중 **4개에서 `CLAUDE.md` 를 스스로 고쳤다.**
설계가 "이 스킬은 `CLAUDE.md` 를 쓰지 않는다"(브랜치 규칙 문서화는 `set-initial` Q3 소유)로
정한 바로 그 경계를 태연히 넘었다. 그 외에 즉시 `PUT` 실행 · 되돌릴 길 없음 ·
요청 바디 미리보기 없음 · 사후 통보 — 전부 실패.

양호했던 것도 있다: **위협 모델 설명은 베이스라인부터 과장이 없었다.** 그래서 스킬은
그 부분을 다시 가르치지 않는다.

- **린트:** `shellcheck -S warning` (스텁 포함 7개 파일) **경고 0**.
- **코드리뷰: 수행함 (서브에이전트, sonnet).** **차단 0 · 권고 2 · 참고 2.**
  리뷰어가 실측으로 확인한 것:
  - **원격 보호 설정이 2026-08-25에 손으로 건 값과 정확히 일치** — 쓰기 흔적 0건.
    구현자가 자진 신고한 사고(초기에 PATH 스텁이 잘못 걸려 진짜 `gh` 가 실행됨)가
    GET만이었다는 것이 독립 확인됐다.
  - 픽스처에 토큰·계정 문자열 **0건**.
  - `set-initial` 질문 계약 4요소가 모든 질문에 승계됨.
  - `CLAUDE.md` 경계가 **합리화 반박표까지 갖춰** 명문화됨 —
    "CLAUDE.md가 틀렸으니 이 김에 고쳐주자" 항목을 미리 넣어 우회 유혹을 차단.
  - `(예정)` 표기가 `E011~E014`·`W019` 5개만 빠지고 `W017`·`W018` 은 남음.
  - **권고 2건**(스텁이 `--jq` 를 무시함 · 404 stdout/stderr 미분리) → **T6으로 반영.**
- **T6 + 직접 재관찰:** 스텁을 실제 `gh` 와 바이트 단위로 맞춘 뒤, **오케스트레이터가
  직접 두 시나리오를 태워** 스킬이 새 형태를 올바르게 소비하는지 확인했다.
  - `no_admin` → 0단계 5번에서 `HRN-E014` 로 정확히 차단, 관찰 사실 인용, 이후 단계 미진행.
  - `solo_unprotected` → 7단계 점검 통과 → 위협 모델 → Q1까지. C1~C7 전부 충족.
    특히 **`enforce_admins: false` 면 admin push는 경고만 찍히고 통과한다**는 한계를
    스스로 짚었다(과장 없음). 호출 로그에 쓰기 **0건**.
- **테스트:** `tests/install/run-tests.sh` **176 PASS / 0 FAIL** (이 작업은 셸 테스트를
  늘리지 않는다 — 스킬 검증은 RED/GREEN 관찰 기록이 담당한다).
- **⑧ 2회차 리뷰는 생략했다 (숨기지 않는다).** 1회차가 이미 "판정에 올려도 됨"으로
  판정했고, T6은 **검증 도구**를 고친 것이며, 그 효과를 오케스트레이터가 직접 실측 2건으로
  확인했기 때문이다. 스킬 로직 자체는 1회차 이후 바뀌지 않았다.
- **미검증으로 남는 것:**
  - **`HRN-W019`(부분 적용 실패) 경로 미관찰.** 스텁이 쓰기를 항상 성공시켜 한 번도
    밟히지 않았다. 고치려면 실제 GitHub의 부분 실패 형태를 알아야 하는데, 모르는 채
    흉내내면 **틀린 것을 검증하게 된다.** 실사용에서 재현되면 그때 실물을 보고 만든다.
  - **대화형 멀티턴에서 Q2 프리뷰가 항상 나오는지** — 헤드리스 단일턴 관찰의 구조적 한계.
    문서에 못박은 것까지가 전부다.
  - **GitHub App 토큰처럼 `X-Oauth-Scopes` 헤더가 없는 인증에서의 `E012` 판정** —
    그 인증 방식을 이 환경에서 만들 수 없다.
  - **실제 쓰기 경로 전체가 미검증이다.** 설계상 RED/GREEN에서 실 저장소에 쓰지 않기로
    했으므로, `PUT` 이 실제로 성공하는 모습은 사용자가 직접 써봐야 확인된다.

## 5. 직접 확인 시나리오

> `Immamakeit/kgh-harness` 는 **이미 오늘 손으로 보호를 걸어둔 상태**다. 아래 1~2는
> 그 상태를 읽기만 한다.

1. 스킬이 배포물에 실렸는지 본다.
   ```bash
   cd ~/dev/kgh-dev-harness && ls skills/ | tr '\n' ' '
   grep -n 'branch-strategy' core/playbook.md README.md
   ```
   - **기대 결과:** 스킬 9종에 `branch-strategy` 포함. 플레이북 트리거 1줄 + README "브랜치 보호" 절.

2. **실제로 써본다** — 이 저장소에서 Claude Code 세션을 열고:
   ```
   브랜치 보호 설정해줘
   ```
   - **기대 결과:** 0단계 점검 표(gh→auth→scope→remote→admin→GET→협력자) → 위협 모델 →
     현재 보호 상태가 **이미 있으므로 "이미 적용된 값과 동일" 고지**(멱등성) →
     Q1(번호·직접 입력·건너뛰기·기본번호) → **요청 바디 미리보기** → Q2(기본 N).
     **최종 확인 전에는 아무것도 바뀌지 않는다.**

3. **부정 케이스 ①** — admin이 아닌 저장소. 스텁으로 재현:
   ```bash
   S=$(mktemp -d); cp tests/skills/branch-strategy/fixtures/stub-gh "$S/gh"; chmod +x "$S/gh"
   mkdir -p "$S/p" && cd "$S/p" && git init -q . && git remote add origin https://github.com/testowner/testrepo.git
   PATH="$S:$PATH" STUB_GH_LOG="$S/log" STUB_GH_SCENARIO=no_admin "$S/gh" api repos/testowner/testrepo --jq '.permissions.admin'
   ```
   - **기대 결과:** `false`. 이 상태로 스킬을 태우면 `HRN-E014` 로 차단되고 스냅샷 단계로
     넘어가지 않는다.

4. **부정 케이스 ②** — 원격이 GitHub이 아니면 막힌다.
   ```bash
   cd "$S/p" && git remote set-url origin https://gitlab.com/x/y.git
   ```
   - **기대 결과:** 스킬이 `HRN-E013` 으로 차단. `gh` 를 호출하기 전에 로컬 git으로 판정한다.

5. 회귀.
   ```bash
   cd ~/dev/kgh-dev-harness && bash tests/install/run-tests.sh | tail -2
   ```
   - **기대 결과:** `PASS: 176  FAIL: 0`
