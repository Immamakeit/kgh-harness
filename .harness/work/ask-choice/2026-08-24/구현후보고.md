### 3-1. 린트 — 통과

```

(출력 없음)
```

`-S warning` 레벨에서 출력이 없다. `SC1091`(info)은 `source` 경로를 못 따라가는 것으로
기존 스크립트 전체의 관행이며 이 레벨에서는 잡히지 않는다.

### 3-2. 코드리뷰 — **통과** (조건부 아님)

`superpowers:requesting-code-review` 규율로 서브에이전트 리뷰 수행.

## 4. REFACTOR 1회차 — 왜 통과인데 루프를 돌았나

코드리뷰 판정은 통과였고 발견 3건은 전부 경미였다. 그럼에도 두 건을 닫았다.

**CLAUDE.md §4가 GREEN 다음의 허점 봉쇄를 요구하고, 발견된 것이 남의 코드가 아니라
이번 작업이 방금 쓴 함수의 계약 공백이기 때문이다.** 현재 유일한 호출부에서 트리거되지
않는다는 것은 "지금은 안 터진다"이지 "계약이 온전하다"가 아니다.

두 증상의 뿌리가 하나였다 — 기본번호가 무효라 Enter 를 쳐도 검증에 걸리고, 파이프 입력이
바닥나면 `read` 가 영원히 블록됐다. 입구 검증 하나로 둘 다 닫혔고, `read` 실패 처리를
두 번째 자물쇠로 걸었다.

**세 번째 발견은 고치지 않았다.** 개행 포함 라벨의 목록 표시 흐트러짐은 순수 코스메틱이고,
호출부가 만드는 라벨(vault 이름 + 경로)에는 개행이 들어갈 수 없다. 봉쇄할 허점이 아니다.

## 5. 계획서 결함 3건 — 전부 내 것

작업자들이 셋 다 숨기지 않고 보고했다.

1. **`run_with_tty` 가 무한 대기했다.** 내가 `printf '%s' "$input"` 을 썼는데, `'2\n'` 을
   `%s` 로 내보내면 **백슬래시와 n 두 글자**가 나간다. 실제 개행 바이트가 아니라 pty 의
   `read -rp` 가 영원히 기다렸다. 작업자가 `ps aux` 로 멈춘 프로세스를 확인하고 `%b` 로
   고쳤다. 검증 의도는 유지한 채 버그만 고쳤고 별도 `[fix]` 커밋으로 분리했다.
2. **내 열화 테스트가 아무것도 열화시키지 않았다.** 계획서의 `PATH=/usr/bin:/bin` 과
   `env -i` 는 python3·wslpath 가 여전히 `/usr/bin` 에 있고 `/mnt/c` 가 환경변수와 무관하게
   마운트돼 있어 **정상 탐지 결과를 냈다.** 통과처럼 보이지만 아무것도 검증하지 않는
   테스트였다. 작업자가 세 갈래를 각각 격리해 진짜 열화를 만들었다.
3. **`VAULT_ROOT=""` 중복 선언.** 실물 `install/setup` 이 이미 선언하고 있었다.

## 6. 발견한 기존 결함 — 이번 작업 소관 아님

**`harness.config.yaml` 의 `vault_root` 가 배포 템플릿으로 새어 나간다.**

```
harness.config.yaml:16   vault_root: /mnt/c/gh-obsidian-vaults/LLM-Wiki
install/setup:218        r'^(\s*vault_root:\s*)null(\s*#.*)?$'    ← null 만 매칭
```

이 레포의 컨피그가 그대로 신규 설치 템플릿이다. 결과가 둘이다:

1. **환경 정보 누출** — 임의의 프로젝트에 설치할 때마다 이 레포 소유자의 vault 절대경로가
   박힌다. 사용자가 "건너뛰기"를 골라도 그렇다.
2. **이번 기능이 이 레포에서는 무력화된다** — 치환 정규식이 `null` 만 잡으므로, vault 를
   골라도 반영되지 않고 "자동 반영 실패" 경고가 뜬다.

리뷰어가 독립적으로 재현했고, 중요한 구분을 해줬다:

> `ask_choice` 는 1번을 정확히 선택해 `VAULT_ROOT` 를 올바르게 만들었다(경고 메시지의
> 값으로 증명됨) — **배선 자체는 정상.** 반영되지 않은 것은 정규식이 `null` 만 매칭하는
> 기존 결함.

커밋 `2846807`(2026-08-14)부터 있던 것이고 이번 작업이 만든 것이 아니다. 승인된 설계의
비대상 밖이라 손대지 않았다. **판정 시 결정이 필요하다 — §7.**

PRD §7.1이 이미 못박고 있다: *"`vault_root` 는 디폴트값이 없다. 하드코딩 금지(이식성)."*
지금 상태는 그 규칙 위반이다.

## 7. 판정 시 결정이 필요한 것

`vault_root` 템플릿 누출(§6)을 어떻게 할지. 세 선택지:

- **(a) 별도 작업으로 분리** — 이번 판정은 `ask_choice` 만 보고, 누출은 다음 작업으로.
  이미 계획이 있다 — 공개 저장소 준비의 **T2(환경 의존 값 제거)** 가 정확히 이 항목이다.
- **(b) 지금 최소 수정** — `harness.config.yaml` 의 `vault_root` 를 `null` 로 되돌리고
  치환 정규식이 기존 값도 매칭하게 고친다. 다만 이 레포 자신의 dogfooding 저장이 멈추므로
  로컬 오버라이드 방법을 함께 정해야 한다.
- **(c) 그대로 둔다** — 공개 계획이 없다면 성립하나, 공개 저장소로 낼 예정이므로 권하지 않는다.

**(a)를 권한다.** 로컬 오버라이드 방법을 정하는 것은 설계 판단이고, 승인 없이 이번 작업에
끼워 넣을 사안이 아니다.

**5) 범위 밖 번호를 넣으면**

위 1)번을 실행하고 `9` 를 입력한다.

**조용히 99를 반환하지 않는다.**

**7) 반환값이 오염되지 않는지 (가장 중요)**

```bash
r="$(bash -c "source install/lib.sh; ask_choice '고르세요' 1 '가' '나'" </dev/null 2>/dev/null)"
printf '[%s] 길이=%s\n' "$r" "${#r}"
```

**기대:** `[1] 길이=1`. 목록이나 경고가 섞이면 길이가 1이 아니다.

**8) Obsidian 없는 환경 흉내 — 열화**

```bash
D=$(mktemp -d)
env -i PATH=/usr/bin:/bin HOME="$HOME" bash -c "source $PWD/install/lib.sh; detect_obsidian_vaults; echo rc=\$?"
```

**기대:** 이 머신에서는 여전히 탐지된다(python3·wslpath 가 `/usr/bin` 에 있다).
**탐지가 안 되는 환경이라면** 빈 출력에 `rc=0` 이 나오고, `install/setup` 은 종전처럼
자유 입력을 묻는다. 어느 쪽이든 설치는 막히지 않는다.

- 통과 → 산출 문서 3종을 vault에 저장하고 마무리합니다.
- 실패 → 어느 부분이 실패인지 여쭙고, 보완 계획을 세워 구현 단계로 재진입합니다.
