# 설계 — ask_choice 번호 선택 입력 + vault 탐지

## 1. 요구사항 / 의도

사용자 요구: **"harness 자체에서 질문으로 던질 때, 옵션을 주르륵 주고 번호만 입력해도 되게."**

두 계층에 각각 답이 필요하다.

**세션 계층은 이미 된다.** Claude Code의 질문 도구가 번호 UI를 낸다 — 이 작업의
브레인스토밍에서도 네 번 썼다. 코드가 아니라 **플레이북에 규칙이 없는 것**이 문제다.
지금은 선택지를 줄지 자유서술을 요구할지가 매번 판단에 맡겨져 있다.

**스크립트 계층은 안 된다.** `install/lib.sh`에 `ask`(자유 입력)와 `ask_yn`(예/아니오)만
있고 다지선다가 없다. 그래서 `install/setup`의 vault 경로 입력이 **절대경로 타이핑**이다:

```
install/setup:178
  VAULT_ROOT="$(ask "storage.vault_root (Obsidian vault 절대경로) — 건너뛰려면 Enter" "")"
```

그런데 Obsidian이 등록된 vault 목록을 파일로 갖고 있다. 실측했다:

```
/mnt/c/Users/UserK/AppData/Roaming/obsidian/obsidian.json  → 등록 vault 4개
  C:\gh-obsidian-vaults\ObsidianGit · studying · 개발 · LLM-Wiki
```

`wslpath -u 'C:\gh-obsidian-vaults\LLM-Wiki'` → `/mnt/c/gh-obsidian-vaults/LLM-Wiki` 로
변환도 된다(`/usr/bin/wslpath` 실존 확인).

즉 **타이핑시킬 이유가 없다.** 번호 선택 헬퍼를 만들면 죽은 코드가 아니라 즉시 쓰인다.

### 브레인스토밍에서 확정된 것 (2026-08-24, 인용)

| # | 결정 |
|---|---|
| 1 | 범위는 **헬퍼 + `install/setup`의 vault_root 호출부까지.** 헬퍼만 만들지 않는다 |
| 2 | vault 탐지는 **WSL/Windows만.** 다른 플랫폼은 지금과 같은 자유 입력으로 열화 |
| 3 | 구조는 **`install/lib.sh`에 추가** — 새 파일로 분리하지 않는다 |

2번의 이유를 명시한다: **Linux·macOS는 이 환경에서 실측할 수 없다.** 경로를 코드에 넣을
수는 있으나 돌려보지 못한 것을 지원한다고 적지 않는다.

## 3. 설계안

### 3-1. `ask_choice` — 번호를 반환한다

```bash
# ask_choice "질문" "기본번호" "선택지1" "선택지2" ...
#   → 선택된 번호(1-based)를 stdout으로 echo
```

**라벨이 아니라 번호를 반환한다.** 호출부가 자기 배열을 인덱싱하게 하려는 것이다.
라벨을 반환하면 `"LLM-Wiki  /mnt/c/..."` 같은 표시용 문자열에서 경로를 다시 파싱해야
한다 — 표시와 값이 엉킨다.

```
storage.vault_root 를 지정하시겠습니까?
  1) LLM-Wiki        /mnt/c/gh-obsidian-vaults/LLM-Wiki
  2) 개발             /mnt/c/gh-obsidian-vaults/개발
  3) 직접 경로 입력
  4) 건너뛰기 (나중에 컨피그에서 지정)   [기본]
번호 입력 [4]:
```

**동작 계약:**

| 입력 | 동작 |
|---|---|
| 유효 번호 | 그 번호 반환 |
| 빈 입력(Enter) | 기본번호 반환 |
| 범위 밖·비숫자 | 사유를 알리고 **재질문** |
| 재질문 3회 초과 | 기본번호 채택 + 그 사실 로그 (무한 루프 방지) |
| 비TTY(CI 등) | 기본번호 채택 + `note` 로그 — `ask`·`ask_yn` 과 동일 |

**⚠ 반드시 지킬 것 — 출력 오염.** 이 함수의 stdout은 `$(...)`로 캡처된다. 선택지 목록과
안내는 **전부 stderr로** 내보내야 한다. `lib.sh:21-24`가 같은 함정에 대한 주석을 이미
달아뒀다(`note()`가 stderr인 이유). `read -rp` 의 프롬프트는 bash가 stderr로 보내므로
안전하고, 목록 출력만 명시적으로 `>&2` 를 붙인다.

### 3-2. `detect_obsidian_vaults` — 탐지 실패는 에러가 아니다

```bash
# detect_obsidian_vaults
#   → "<이름>\t<변환된 절대경로>" 를 한 줄씩 stdout. 탐지 실패 시 빈 출력(성공 종료).
#   WSL/Windows 전용.
```

**절차:**

1. `/mnt/c/Users/*/AppData/Roaming/obsidian/obsidian.json` 탐색 — 없으면 빈 출력
2. `python3` 없으면 빈 출력 (`json` 은 표준 라이브러리라 PyYAML 문제는 없다)
3. `wslpath` 없으면 빈 출력 — Windows 경로를 변환 못 하면 쓸 수 없는 값이다
4. JSON의 `vaults` 에서 각 항목의 `path` 를 `wslpath -u` 로 변환
5. **변환된 경로가 실제로 존재하는 것만** 낸다 (삭제된 vault가 목록에 남아 있을 수 있다)
6. 이름은 경로의 마지막 요소를 쓴다

`detect_superpowers`(`lib.sh:264`)가 매니페스트 JSON을 python3로 파싱하는 것과 같은 패턴이다.
새 방식을 만들지 않는다.

### 3-3. `install/setup` 호출부

```
vault 탐지 성공 (N개)          vault 탐지 실패
─────────────────────          ─────────────────────
1..N) 탐지된 vault              지금과 동일한 자유 입력
N+1)  직접 경로 입력            (ask "…절대경로… — 건너뛰려면 Enter" "")
N+2)  건너뛰기        [기본]
```

- **기본은 "건너뛰기"** — 지금 동작(Enter = 건너뜀)을 그대로 잇는다. 설치가 사용자
  의사 없이 vault를 붙잡지 않는다.
- "직접 경로 입력"을 고르면 기존 `ask` 로 넘어간다 — 두 경로가 공존한다.
- 건너뛰면 지금처럼 `HRN-W010`.
- 탐지 결과를 **몇 개 찾았는지 먼저 알린다** (결과 비은닉).

### 3-4. `core/playbook.md` 질문 규칙

§6(보고 규칙)에 한 항목을 더한다:

```markdown
- **질문 규칙**: 사용자에게 물을 때는 선택지를 제시하고 디폴트를 표시한다. 자유서술을
  요구하는 질문은 선택지를 만들 수 없을 때만 쓴다. 선택지가 3개를 넘으면 우선순위 높은
  것부터 4개까지만 내고 나머지는 "기타"로 접는다.
```

세션 계층에는 코드 변경이 없다. **규칙이 없어서 안 하던 것**이므로 규칙을 적는다.

### 3-5. 열화 경로 정리 (전부 비차단)

| 상황 | 동작 |
|---|---|
| `obsidian.json` 없음 (Linux·macOS·Obsidian 미설치) | 자유 입력 |
| `python3` 없음 | 자유 입력 |
| `wslpath` 없음 | 자유 입력 |
| 등록 vault 0개 / 경로가 전부 실존하지 않음 | 자유 입력 |
| 비TTY | 기본값(건너뛰기) + 로그 |

**어느 경우에도 설치를 막지 않는다.** 신규 에러코드도 만들지 않는다 — 탐지는 편의이지
요건이 아니다.

## 4. 작업 범위 / 비대상

### 범위

2. `install/lib.sh` 에 `detect_obsidian_vaults` 추가
3. `install/setup:178` vault_root 입력을 번호 선택으로 교체 (탐지 실패 시 자유 입력 유지)
4. `core/playbook.md` §6 에 질문 규칙 추가

6. `tests/install/run-tests.sh` 에 테스트 추가 (RED 선행)

### 비대상 — 알면서 안 하는 것

- **Linux·macOS vault 탐지를 하지 않는다.** 경로를 아는데도 넣지 않는 이유는 하나다 —
  이 환경에서 돌려볼 수 없다. 돌려보지 못한 것을 지원한다고 적지 않는다. 두 플랫폼은
  자유 입력으로 지금과 동일하게 동작한다.
- **`install/update` 의 `ask_yn` 2곳(L85·91)을 바꾸지 않는다.** 예/아니오는 번호 선택이
  오히려 손이 더 간다. `y` 한 글자가 `2` + Enter보다 빠르다.
- **`install/setup` 의 설치 경로 입력(L56)·진행 확인(L75)을 바꾸지 않는다.** 전자는
  선택지를 만들 수 없고(임의 경로), 후자는 예/아니오다.
- **탐지된 vault가 Obsidian에서 실제로 열리는지 확인하지 않는다.** 디렉토리 실존까지만
  본다. 앱을 띄워 확인하는 것은 과하고, `obsidian-cli` 스킬이 저장 시점에 이미
  `HRN-W011` 로 다룬다.
- **세션 계층의 질문 도구와 `ask_choice` 를 통합하지 않는다.** 하나는 대화형 UI, 하나는
  셸 프롬프트다. 계층이 다르므로 규격만 같은 방향으로 맞추고 코드는 잇지 않는다.
- **열린 쟁점 O1(문서 status 전이 시점)은 이번 범위 밖이다.** `residual-cleanup-1`
  판정 시 별도 작업으로 남긴 것이며 여기서 다루지 않는다.
- **`install/lib.sh` 의 기존 함수를 리팩터링하지 않는다.** `ask`·`ask_yn` 은 그대로 둔다.
  추가만 한다.
