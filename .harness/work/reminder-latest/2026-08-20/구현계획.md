# 구현계획 — reminder-latest

> **에이전트 실행자용:** 각 태스크는 독립 구현 + 독립 검증 단위다. 순서대로 수행하되,
> **태스크 1(RED)을 건너뛰고 5(SKILL.md)로 가지 않는다** — writing-skills Iron Law.

**목표:** 임의의 저장소에서 실행하면 "최근 한 일 · 현재 상태 · 큰 방향 · 다음 한 수"를
40줄 이내로 브리핑하는 전역 스킬을 만든다.

**구조:** `collect.sh`가 사실만 수집하고 `SKILL.md`가 해석·서식만 규정한다.

**기술 스택:** bash(수집) + python3(세션 jsonl 파싱) + git.

## 전역 제약 (모든 태스크에 암묵 적용)

- 산출 위치는 `~/.claude/skills/reminder-latest/` — **이 저장소 파일은 변경하지 않는다.**
- `collect.sh`는 **cwd 기준**으로 동작한다. 스킬 설치 경로를 기준으로 삼지 않는다.
- **silent 에러 금지** (CLAUDE.md §5): 모든 열화는 `### NOTES`로 표면화하고, 스크립트는
  어떤 경우에도 비정상 종료로 침묵하지 않는다. `set -e` 사용 금지 — 부분 실패해도 나머지
  구획을 계속 수집해야 한다.
- `collect.sh`는 **해석·추측을 하지 않는다.** 판단은 전부 SKILL.md(에이전트)의 몫이다.
- 세션 발화는 **200자 절단 · 최대 30줄**을 넘기지 않는다 (설계 §2 전수점검 인증·권한 항).

### 태스크 2 — `collect.sh` git 축 (REPO · COMMITS · STATUS · NOTES)

**목적:** git에서 읽을 수 있는 사실을 구획 형식으로 뱉는다.

**범위(In/Out):** In — 위 4구획 + 골격 / Out — DIRECTION·WORKDOCS·SESSION

**선행조건:** 태스크 1 완료

**구현 체크리스트**

- [ ] `mkdir -p ~/.claude/skills/reminder-latest`
- [ ] `collect.sh` 골격과 git 축 작성 (아래 코드)
- [ ] `chmod +x ~/.claude/skills/reminder-latest/collect.sh`
- [ ] 정상 저장소에서 실행 → 4구획 출력 확인
- [ ] 예외 2종 확인 (git 아님 / 커밋 0개)
- [ ] 커밋 (작업 문서 변경분만 — 스킬 파일은 레포 밖이라 커밋 대상이 아님)

```bash
#!/usr/bin/env bash
# reminder-latest / collect.sh — 저장소 복귀 브리핑 원자료 수집
# 인자 없음. cwd 기준. 사실만 뱉고 해석하지 않는다.
# set -e 금지: 한 구획이 실패해도 나머지를 계속 수집해야 한다.
set -uo pipefail

NOTES=()
note() { NOTES+=("$1"); }

REPO_PATH=$(pwd -P)
REPO_NAME=$(basename "$REPO_PATH")

if git rev-parse --git-dir >/dev/null 2>&1; then
  IS_GIT=yes
  BRANCH=$(git rev-parse --abbrev-ref HEAD 2>/dev/null || echo '(detached)')
else
  IS_GIT=no
  BRANCH='(해당 없음)'
  note "git 저장소가 아님 — 커밋·변경 축을 수집하지 못했다. 문서·세션만으로 보고할 것."
fi

echo "### REPO"
echo "path: $REPO_PATH"
echo "name: $REPO_NAME"
echo "branch: $BRANCH"
echo "git: $IS_GIT"
echo

echo "### COMMITS"
if [ "$IS_GIT" = no ]; then
  echo "(수집 불가 — git 저장소 아님)"
elif ! git rev-parse HEAD >/dev/null 2>&1; then
  echo "(없음 — 첫 커밋 전)"
  note "커밋이 하나도 없다."
else
  git log -15 --date=short --pretty='%h %ad %s' 2>/dev/null
  _last=$(git log -1 --pretty=%ct 2>/dev/null || echo 0)
  if [ "$_last" -gt 0 ]; then
    echo "last_commit_days_ago: $(( ( $(date +%s) - _last ) / 86400 ))"
  fi
fi
echo

echo "### STATUS"
if [ "$IS_GIT" = no ]; then
  echo "(수집 불가 — git 저장소 아님)"
else
  _porc=$(git status --porcelain 2>/dev/null)
  if [ -n "$_porc" ]; then
    echo "$_porc"
    echo "dirty_count: $(printf '%s\n' "$_porc" | grep -c .)"
  else
    echo "(작업트리 깨끗함)"
  fi
  _stash=$(git stash list 2>/dev/null)
  if [ -n "$_stash" ]; then
    echo "-- stash --"
    echo "$_stash"
  fi
  _up=$(git rev-parse --abbrev-ref --symbolic-full-name '@{u}' 2>/dev/null || true)
  if [ -n "$_up" ]; then
    git rev-list --left-right --count "$_up...HEAD" 2>/dev/null \
      | awk -v u="$_up" '{print "vs " u ": behind " $1 ", ahead " $2}'
  else
    echo "upstream: (없음)"
  fi
fi
echo
```

NOTES 구획은 **파일 맨 끝**에 온다 (태스크 3·4가 note를 더 쌓으므로). 태스크 2 시점에는
아래를 파일 끝에 둔다:

```bash
echo "### NOTES"
if [ ${#NOTES[@]} -eq 0 ]; then
  echo "(없음 — 완전 수집)"
else
  printf '%s\n' "${NOTES[@]}"
fi
```

**테스트 방식**
- 절차:
  ```bash

  mkdir -p "$SCRATCH/notgit" && cd "$SCRATCH/notgit" && ~/.claude/skills/reminder-latest/collect.sh
  mkdir -p "$SCRATCH/emptygit" && cd "$SCRATCH/emptygit" && git init -q . && ~/.claude/skills/reminder-latest/collect.sh
  ```
- 기대결과:
  - 1번: `git: yes`, 커밋 15줄, `last_commit_days_ago:` 존재, STATUS에 `dirty_count:` 존재
  - 2번: `git: no`, COMMITS/STATUS가 `(수집 불가 …)`, NOTES에 "git 저장소가 아님" 1줄
  - 3번: `(없음 — 첫 커밋 전)`, NOTES에 "커밋이 하나도 없다" 1줄
  - **세 경우 모두 exit code 0** (`echo $?`로 확인) — silent 실패도 비정상 종료도 없어야 한다
- 테스트 적절성 근거: 설계 §3-4 열화표의 3개 행(git 아님·커밋 0개·정상)이 이 스크립트 분기와
  1:1 대응한다. 분기별 수동 실행이 가장 직접적인 검증이다.

**완료 기준:** 위 3케이스가 기대 출력과 일치하고 전부 exit 0.

**리스크/충돌:** 태스크 3·4는 같은 파일의 **다른 구획**만 추가하므로 이 코드를 수정하지 않는다.

### 태스크 3 — `collect.sh` 문서 축 (DIRECTION · WORKDOCS)

**목적:** 방향 문서 사다리 히트와 작업 문서 트리를 **경로만** 넘긴다.

**범위(In/Out):** In — 두 구획 / Out — 문서 **본문** 읽기(에이전트 몫), 커밋 축

**선행조건:** 태스크 2의 골격

**구현 체크리스트**

- [ ] DIRECTION 구획 추가 (사다리 1→2→3→4)
- [ ] 1차 히트 최대 2개까지만 `primary:`, 나머지는 `other:`
- [ ] WORKDOCS 구획 추가 (최신 8개)
- [ ] 4개 저장소에서 사다리 단이 기대대로 나오는지 확인

```bash
echo "### DIRECTION"
_primary=()
_rung=0
for _c in CLAUDE.md AGENTS.md; do
  [ -f "$_c" ] && { _primary+=("$_c"); _rung=1; }
done
if [ "$_rung" -eq 0 ] && [ -f PRD.md ]; then
  _primary+=("PRD.md"); _rung=2
fi
if [ "$_rung" -eq 0 ] && [ -d docs ]; then
  while IFS= read -r _f; do
    [ -n "$_f" ] && { _primary+=("$_f"); _rung=2; }
  done < <(find docs -maxdepth 2 -type f -name '*.md' 2>/dev/null | sort | head -2)
fi
if [ "$_rung" -eq 0 ] && [ -f README.md ]; then
  _primary+=("README.md"); _rung=3
fi

echo "rung: $_rung"
if [ "$_rung" -eq 0 ]; then
  echo "(방향 문서 없음)"
  note "방향 문서가 없다 — 큰 방향은 커밋 메시지에서 추론하고 반드시 (추정)으로 표시할 것."
else
  _i=0
  for _p in "${_primary[@]}"; do
    _i=$((_i+1)); [ "$_i" -gt 2 ] && break
    echo "primary: $_p"
  done
fi
# 1차 히트에 안 든 나머지 후보는 존재만 알린다 (본문은 읽지 않는다)
for _c in CLAUDE.md AGENTS.md PRD.md README.md; do
  [ -f "$_c" ] || continue
  case " ${_primary[*]-} " in *" $_c "*) continue ;; esac
  echo "other: $_c"
done
echo "note: CLAUDE.md/AGENTS.md는 이미 세션 컨텍스트에 로드돼 있을 수 있다 — 재독 금지."
echo

echo "### WORKDOCS"
_wd_found=no
for _base in .harness/work docs/superpowers/specs docs/superpowers/plans docs/specs docs/plans; do
  [ -d "$_base" ] || continue
  _list=$(find "$_base" -type f -name '*.md' -printf '%T@ %p\n' 2>/dev/null \
          | sort -rn | head -8 | cut -d' ' -f2-)
  # -printf 미지원 환경(BSD find) 폴백
  [ -z "$_list" ] && _list=$(find "$_base" -type f -name '*.md' 2>/dev/null | sort | tail -8)
  [ -z "$_list" ] && continue
  _wd_found=yes
  echo "-- $_base (최신순 최대 8) --"
  echo "$_list"
done
[ "$_wd_found" = no ] && echo "(없음)"
echo
```

### 태스크 4 — `collect.sh` 세션 축 (SESSION)

**목적:** 최근 2세션의 **사용자 발화만** 시각과 함께 뽑는다.

**범위(In/Out):** In — SESSION 구획 + python3/디렉토리 부재 열화 / Out — 어시스턴트 응답 파싱
(설계 §4 비대상 4)

**선행조건:** 태스크 2의 골격 (`note` 함수)

**구현 체크리스트**

- [ ] 슬러그 유도 (`/` → `-`)
- [ ] 정확 매칭 실패 시 basename 폴백
- [ ] python3 부재 열화
- [ ] 파싱 실패를 예외 종료가 아닌 NOTES 경고로 처리
- [ ] 200자 절단 · 30줄 상한 확인

```bash

_slug=$(printf '%s' "$REPO_PATH" | sed 's#/#-#g')
_sdir="$HOME/.claude/projects/$_slug"
```

**R3 — 훑기 불가 (B 심각, A 부분적).**
B는 방향·상태·다음이 산문에 섞여 있어 눈으로 위치를 잡을 수 없다. A는 번호 절이 있어

**R4 — 추측과 사실을 구분하지 않는다 (A·B 공통).**

### 태스크 4 — 세션 축: 시뮬 방법 확정 + 결함 2건 수정

**python3 부재 시뮬 방법** (계획서에 "되는 쪽을 쓴다"로 열려 있던 항목):

| 방법 | 결과 |
|---|---|
| `PATH=빈디렉토리` | ❌ bash 자체가 사라져 실행 불가 |
| `/bin/false` 심볼릭 링크 선점 | ❌ `command -v`가 링크를 실행 가능 파일로 잡음 |
| **shim 디렉토리** (필요 도구만 링크, python3 제외) | ✅ 채택 |

shim 구축 시 `command -v`를 쓰면 **셸 함수로 정의된 명령**(이 환경의 `grep`)이 경로 대신
이름을 반환해 `grep -> grep` 자기참조 링크가 생긴다. `type -P`를 써야 한다. 이 과정에서
collect.sh의 전체 의존성이 확정됐다: **git·sed·awk·grep·find·sort·head·cut·basename·date·wc
+ python3(선택)**.

|---|---|---|
| D3 | 스킬 주입 페이로드(`Base directory for this skill: …`)가 사용자 발화로 섞여 30줄 예산 잠식 | `NOISE` 접두사 필터 추가 |
| D4 | 시각이 UTC로 출력(`02:03`)돼 사용자가 겪은 시각(11:03 KST)과 불일치 | `datetime.astimezone()`으로 로컬 변환, 실패 시 원문 폴백 |
