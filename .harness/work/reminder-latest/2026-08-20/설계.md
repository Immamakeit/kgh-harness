# 설계 — reminder-latest (저장소 복귀 브리핑 전역 스킬)

## 1. 요구사항 / 의도

**사용자 원문:** "이 스킬을 실행하면, 세션에 해당되는 저장소 기준으로 해서, 최근에 하던 일,
일의 상태, 큰 틀에서의 방향 등을 보기좋고 명확하게 보고해서 한 번 딱 하고나면, 다시 기억나고
감 잡아서 다음작업들 할 수 있게 하는게 목적."

해결하려는 문제: 저장소를 오랜만에 열었을 때 `git log`를 읽어도 **왜 거기서 멈췄는지**가
복원되지 않는다. 커밋은 결과만 남기고 의도는 대화에만 남는다.

**스콥:** `~/.claude/skills/` — 이 환경의 **모든 저장소**에서 동일하게 쓴다. 하네스 워크플로
전용이 아니다.

### 브레인스토밍 확정 사항 (재유도 금지)

| # | 결정 | 근거 |
|---|---|---|
| 1 | 소스는 **git + 프로젝트 문서**를 기본, **세션 기록**을 상시 병용 | 아래 §2 실측으로 세션 기록 비용이 무시할 수준임이 확인됨 |
| 2 | 보고 골격 = **상태판(B안)** + 말미 요약 블록 | 요청 4요소(최근 일·상태·방향·다음)가 그대로 섹션이 됨 |
| 3 | `다음 한 수`는 **제안하되 `(추정)` + 근거 표기** | 편의는 살리고 오도 위험은 표시로 상쇄 |
| 4 | 방향 문서는 **사다리 첫 히트 1~2개만** | 전부 읽으면 무거워짐 |
| 5 | `CLAUDE.md`는 **재독 금지**, 컨텍스트의 것 사용 | 이미 세션에 로드됨 = 공짜 |
| 6 | 구현 형태 = **SKILL.md + collect.sh** | 예외 경로 5갈래를 프롬프트가 아닌 코드로 관리 |

## 2. 작업 대상 및 영향도 (실측)

### 2-1. 신규 산출물

| 대상 | 상태 |
|---|---|
| `~/.claude/skills/reminder-latest/SKILL.md` | 신규 |
| `~/.claude/skills/reminder-latest/collect.sh` | 신규 (실행권한 필요) |

(작업 문서 3종만 `.harness/work/`에 남는다).

### 2-3. 세션 기록 실측 (C 소스 타당성)

```
~/.claude/projects/-home-ghkim-dev-kgh-dev-harness/
  637b5bbd….jsonl   4.8 MB
  1a6a28ae….jsonl   1.2 MB
  7d713a9b….jsonl   0.19 MB
```

- 파일은 크지만 **사용자 발화만 추출 시 1.2MB → 13줄**. 실측 출력:
  `08-14 통과` / `08-14 1,2,3 하고 난다음에 다시 보고해` / `08-14 승인`
  → 커밋에 없는 **게이트 통과 시점과 미해결 의문**이 그대로 잡힌다.
- **`jq`는 이 환경에 없음.** `python3`(`/usr/bin/python3`)로 추출 성공 → python3 의존.
- 디렉토리명은 절대경로의 `/`를 `-`로 치환한 슬러그 → cwd에서 기계적 유도 가능.

| 배포·런타임 | 확인함 — `python3` 존재 여부가 유일한 외부 의존. 부재 시 세션 축만 열화(§3-4) |

## 3. 설계안

### 3-1. 구조

```
~/.claude/skills/reminder-latest/
  SKILL.md       # 트리거 + 해석·서식 규율 (에이전트 몫)
  collect.sh     # 원자료 수집, 해석 안 함 (결정적 실행)
```

역할 분리 원칙: **collect.sh는 사실만, SKILL.md는 해석만.** 스크립트가 추측하면 근거 표기가
불가능해지므로 판단은 전부 에이전트에 둔다.

`description` 트리거: "리마인드", "요즘 뭐 하던 중이었지", "어디까지 했더라",
"이 저장소 상황 정리해줘", 오랜만의 저장소 복귀. (writing-skills 규율에 따라 **when만** 적고
워크플로 요약은 넣지 않는다 — 요약을 넣으면 에이전트가 본문 대신 description을 따른다)

### 3-2. collect.sh 계약

인자 없음. cwd 기준. stdout에 구획 텍스트를 뱉는다.

| 구획 | 내용 | 범위 |
|---|---|---|
| `### REPO` | 절대경로 · 저장소명 · 브랜치 · git 여부 | — |
| `### COMMITS` | 해시·날짜·제목 | 최근 15개 |
| `### STATUS` | `--porcelain` · stash · ahead/behind | 전체 |
| `### DIRECTION` | 방향 문서 사다리 히트 **경로만** | 첫 히트 1~2개 + 나머지는 경로 나열 |
| `### WORKDOCS` | `.harness/work` · `docs/specs` 등 작업문서 트리 | 있으면 |
| `### SESSION` | `시각 \| 발화` | 최근 2세션, 최대 30줄, 각 200자 절단 |
| `### NOTES` | 생략·열화 경고 | 비면 완전 수집 |

**문서 본문은 스크립트가 읽지 않는다.** 경로만 넘기고 에이전트가 필요한 것만 읽는다.
`CLAUDE.md`는 이미 컨텍스트에 있으므로 재독하지 않는다.

방향 문서 사다리 (위에서부터 첫 히트):
1. `CLAUDE.md` / `AGENTS.md` → 2. `PRD.md` / `docs/` 스펙 → 3. `README.md` 상단
→ 4. 전무 시 커밋 메시지에서 추론 + `(추정)`

### 3-3. 보고 서식 (SKILL.md가 규정)

```
📍 <저장소>  ·  <브랜치>  ·  마지막 커밋 <N>일 전
🧭 큰 방향        ← DIRECTION + (없으면) 커밋 추론(추정)
🔨 진행 중        ← WORKDOCS 최신 + COMMITS
📂 손대다 만 것   ← STATUS
▶️ 다음 한 수     ← (추정) + ← 근거: …
─────────────────
📌 요약   한 줄 / 다음 / 주의
```

불변 규율 셋:
1. `▶️ 다음 한 수`는 **반드시** `(추정)` 표시와 `← 근거:` 를 동반한다.
2. 빈 섹션을 지우지 않는다. `(없음)` 한 줄로 남긴다 — 없다는 것도 정보다.
3. 전체 40줄 이내를 목표로 한다. 길면 "감 잡기"라는 목적 자체가 무너진다.

### 3-4. 예외·열화 (silent 금지 — CLAUDE.md §5)

| 상황 | 동작 |
|---|---|
| git 저장소 아님 | 문서·세션만으로 보고, NOTES 표시 |
| 커밋 0개 | `🔨 진행 중` → `(없음 — 첫 커밋 전)` |
| `python3` 없음 | 세션 축 생략 + `⚠️ 세션 기록 생략 (python3 없음)` |
| 세션 디렉토리 없음 | 동일 문구, 사유만 교체 |
| jsonl 파싱 실패 | 예외 종료 금지 — `⚠️ 세션 기록 일부 해석 실패` 후 진행 |
| 방향 문서 전무 | 커밋 추론 + `(추정)` 표시 |

**모든 경고는 `### NOTES`를 거쳐 보고서 하단에 그대로 드러난다.** 스크립트는 어떤 경우에도
비정상 종료로 사용자에게 침묵하지 않는다.

### 3-5. 검증 — writing-skills Iron Law

**RED를 먼저 관찰한다. 순서를 뒤집지 않는다.**

1. **RED** — 스킬 없이 서브에이전트에 "이 저장소에서 최근 뭐 하고 있었는지 정리해줘"를 던져
   베이스라인을 기록한다. 예상 실패 양상(가설, 관찰로 대체될 것): 커밋만 나열하고 미커밋 무시 /
   방향 없이 사실만 열거 / 세션 기록 존재를 모름.
2. **GREEN** — 관찰된 실패를 겨냥해 SKILL.md를 쓰고 재실행해 준수 확인.
3. **REFACTOR** — 새 회피 논리가 나오면 봉쇄 후 재검증.

대상 저장소 2곳: **이 레포**(문서 풍부) + **문서 없는 레포 1곳**(`~/dev/` 하위에서 선정).
`collect.sh` 단위 확인: git 아닌 디렉토리 / `PATH`에서 python3를 가린 상태.

## 4. 작업 범위 / 비대상

**범위**
- `~/.claude/skills/reminder-latest/SKILL.md` 신규 작성
- `~/.claude/skills/reminder-latest/collect.sh` 신규 작성 + 실행권한
- RED→GREEN→REFACTOR 검증 (저장소 2곳)
- 작업 문서 3종 (`.harness/work/reminder-latest/2026-08-20/`)

**비대상 (알면서 이번에 안 한다)**
1. **`scope-splitter` 이중 관리 해소** — 전역본과 레포 `skills/` 본의 보고 문구가 갈라져 있음을
   §2-2에서 확인했으나, 이번 작업과 독립이다. 별건으로 남긴다.
2. **이 레포 `skills/`로의 편입** — reminder-latest는 하네스 흐름과 무관한 범용 스킬이므로
   전역에만 둔다. 하네스 배포물에 넣지 않는다(넣으면 1번 문제를 재생산한다).
3. **다중 저장소 동시 브리핑** — "내 프로젝트 전체 근황" 같은 확장. cwd 단일 저장소로 고정한다.
4. **세션 기록의 어시스턴트 응답 파싱** — 브레인스토밍에서 "과함, 대부분 중복"으로 기각(다안).
5. **`git diff` 본문 분석** — 어떤 파일이 더러운지까지만 본다. 변경 내용 해석은 범위 밖.
