# 구현 계획 — install/setup · update

## 1. 작업 범위
- 승인된 설계(설계.md, 2026-07-17)의 범위 그대로: `install/lib.sh`·`setup`·`update` 신설,
  `.harnessignore`에 `.harness/` 추가, PRD §8에 `HRN-E006` 추가.

## 2. 작업 대상
- 신규: `install/lib.sh`, `install/setup`, `install/update`
- 수정: `.harnessignore`(1줄), `PRD.md`(에러표 1행)

## 3. 작업 방법 (예시 포함)

### T1. `.harnessignore` + PRD 갱신 (독립, 선행)
- `.harnessignore`에 `.harness/` 추가. PRD §8 표에 `HRN-E006 | 업데이트 소스 레포 미발견 | 경로 재입력 또는 재설치`.
- 검증: 파일 diff 확인.

### T2. `install/lib.sh` — 공용 함수 (T3·T4 의존 대상)
- 색상 출력(say/ok/warn/err), `ask "질문" "디폴트"`(TTY 없으면 디폴트+로그),
  `hrn_err "E006" "메시지" "조치a" "조치b"`, `.harnessignore` → rsync `--exclude` 변환
  (rsync 없으면 tar 폴백). 예: `mapfile -t EXC < <(harnessignore_excludes "$SRC")`
- 검증: `bash -n` + source 후 함수별 단위 실행 (TTY/비TTY 양쪽).

### T3. `install/setup [대상경로]` — 설계 3-1의 8단계
- 예: `./install/setup /tmp/target-proj` → 복사→컨피그→vault_root 질문→훅 병합(python3
  JSON 병합, 기존 훅 보존)→`.meta`(소스경로·커밋해시·일시)→종료 요약.
- 검증(실행): 임시 대상에 설치 → `.harness/` 내용에 PRD.md·CLAUDE.md·tests/·`.harness/`
  미포함 확인, 컨피그 생성 확인, **재실행 시 기존 컨피그 보존** 확인, settings.json에
  기존 키 보존된 채 훅 추가 확인.

### T4. `install/update` — 설계 3-2의 5단계
- `.meta` 소스 확인(부재: HRN-E006+재입력) → `git pull` [Y] → 재복사(보존: `work/`,
  `.meta`는 해시만 갱신, 루트 컨피그 미접촉) → 새 최상위 컨피그 키 감지 안내 → 요약.
- 검증(실행): T3의 설치본에서 실행 → `work/` 파일 생존, 컨피그 mtime/내용 불변,
  `.meta` 해시 갱신, 소스 컨피그에 가짜 새 키 추가 후 감지 안내 확인.

### 근본 수정 (2026-07-17, 메인 세션 직접) — 접근 전환

- 판단: 문자열 정규화로 변종 추적은 구조적으로 불가 → **실체 경로(realpath -m) 기준 가드**로 전환.
