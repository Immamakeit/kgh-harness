# 설계 — install/setup · update 스크립트

## 1. 요구사항 / 의도
- PRD R4·R10·R11: 어느 프로젝트든 **설치 → 1회 세팅**으로 하네스 동작, **명령 한 번**으로
  업데이트 후 기존 워크플로 즉시 사용, 개발용 파일은 배포에서 제외.
- 사용자 확정: **복사형 `.harness/`** 설치, 업데이트는 **로컬 소스 레포 경유**.
- 두 스크립트 모두 interactive-script 스킬 표준 준수 (사전 점검·대화형+디폴트·
  에러 메시징·종료 요약).

## 2. 작업 대상 및 영향도
- 신규: `install/setup`, `install/update`, `install/lib.sh`(공용 함수).
- `install/`은 배포물에 포함 → 대상 프로젝트에서 `.harness/install/update` 실행 가능.
- `.harnessignore`(기존)가 복사 제외 목록의 단일 기준 — setup·update 둘 다 이 파일을 읽음.
- 영향: 기존 파일 수정 없음 (신규 3파일 + `.harnessignore`에 `.harness/` 자기 자신 추가 —
  소스 레포에서 dogfooding으로 생긴 `.harness/work/`가 배포에 섞이면 안 됨).

## 3. 설계안

### 3-1. `install/setup [대상경로]` — 최초 설치 (소스 레포에서 실행)
1. **사전 점검**: bash·rsync(없으면 cp 폴백)·소스 레포 무결성(core/playbook.md 존재).
2. **대상 경로**: 인자 없으면 질문 (디폴트: 현재 디렉토리). 검증 후 확인.
3. **배포물 복사** → `<대상>/.harness/` (`.harnessignore` 적용).
4. **컨피그**: `<대상>/harness.config.yaml` 없으면 템플릿 복사. **있으면 절대 덮어쓰지
   않고** "기존 유지" 안내.
5. **대화형 세팅**: `storage.vault_root` 입력 요청 (디폴트 없음 — Enter로 건너뛰기 가능,
   건너뛰면 HRN-W010이 흐름에서 안내됨을 고지).
6. **훅 연결**: `<대상>/.claude/settings.json`에 SessionStart 훅 병합 (python3로 JSON
   병합, 기존 훅 보존. python3 없으면 수동 연결 방법 안내 후 계속 — 비차단).
7. **`.harness/.meta` 기록**: 소스 레포 절대경로 · 소스 커밋 해시 · 설치 일시.
8. **종료 요약**: 설치 경로·버전·컨피그 상태·훅 연결 여부·다음 할 일.

### 3-2. `install/update` — 업데이트 (대상 프로젝트의 `.harness/install/update`로 실행)
1. **사전 점검**: `.meta`에서 소스 경로 읽기 → 소스 부재 시
   `HRN-E006 — 소스 레포를 찾을 수 없음` + 경로 재입력 선택지.
2. **소스 갱신**: 소스에서 `git pull` 여부 질문 [기본: Y]. 실패 시(오프라인 등) 현재
   소스 상태로 진행할지 선택지 (비차단).
3. **재복사**: `.harness/` 갱신하되 **보존 목록은 절대 미접촉** — `work/`(작업 문서),
   `.meta`(소스 커밋 해시만 갱신). 루트의 `harness.config.yaml`은 **아예 건드리지 않음**.
4. **컨피그 스키마 diff**: 새 템플릿에 있는데 사용자 컨피그에 없는 최상위 키를 감지해
   "새 설정 항목 N개: ..." 안내 (자동 추가하지 않음 — 안내만, PRD §8 에러 계약 준수).
5. **종료 요약**: 이전→새 커밋 해시, 갱신 파일 수, 보존된 것, 발견된 새 설정 키.

### 3-3. 공통 (`install/lib.sh`)
- 색상 출력 함수(안내/성공/주의/오류), `.harnessignore` 파서(rsync exclude 변환),
  TTY 감지 폴백(비대화형이면 디폴트 적용+로그), HRN 에러 포맷터.
- **[변경 2026-07-18, 판정 실패 보완 B1] cp 폴백 제거 — rsync 필수화.**
  cp 폴백의 삭제 동기화가 사용자 work/를 지울 수 있는 위험 표면임이 검증 5라운드로
  실증됨 → 위험 로직을 방어하는 대신 제거. `setup`·`update` 사전 점검에서 rsync 부재 시
  `HRN-E008`(필수 실행체·도구 미발견) + 설치 안내 후 중단. F6(cp 폴백 패턴 매칭)은
  폴백 제거로 소멸.

### 3-4. 실행체·모델 실존 예외처리 [추가 2026-07-18, 보완 B7]
컨피그에 지정된 에이전틱 하네스·모델이 실존하지 않는 3계층 실패의 처리:
- **L1 실행체(CLI) 미설치**: `setup` 사전 점검에서 active_harness의 실행체 확인
  (claude→`command -v claude`, codex→`command -v codex`, ollama(추후)→엔드포인트 probe —
  확인 방법은 어댑터 소유) → 미발견 시 `HRN-W013` **비차단 경고**(설치 명령 안내).
  흐름 시작 시(플레이북 §1)에는 `HRN-E008` **차단** + 조치: (a) CLI 설치 (b) active_harness 변경.
- **L2 어댑터 미구현**: `active_harness: codex|ollama`(v1 스텁) 지정 시 흐름 시작에서
  `HRN-E010` 차단 — "추후 작업(PRD §10). 조치: (a) claude로 변경 (b) 어댑터 구현".
- **L3 모델 런타임 거부**(폐기·권한·플랜 — 정적 목록 E001로 못 잡는 것): 사전 프로빙
  하지 않고 **디스패치 실패 시점**에 처리 — ① 즉시 보고(silent 금지) ② `defaults.model`로
  **1회만** 폴백 재시도(같은 모델이면 생략, 폴백 사실 명시) ③ 재실패 시 `HRN-E009` 중단
  + 조치: (a) 컨피그 model 변경 (b) 어댑터 지원 목록 갱신.
- PRD §8 에러표에 `E008`·`E009`·`E010`·`W013` 추가. 플레이북 §1 검증 절차 확장.
