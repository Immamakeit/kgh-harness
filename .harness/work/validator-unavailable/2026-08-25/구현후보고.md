# 구현 후 보고 — validator-unavailable (`HRN-W020`)

## 1. 변경 요약

에러 계약에 빠져 있던 칸 하나를 채웠다 — **검증기 파일은 있는데 실행 자체가 안 되는 경우.**

| 태스크 | 결과 |
|---|---|
| T1 | `PRD.md` §8에 `HRN-W020` **먼저 등재** (대장 규칙 준수) |
| T2 | 플레이북 §1-3 분기표 완성 — `없음→E005` 옆에 `있으나 실행 불가→W020` |
| T3 | `install/setup`·`install/update` 분기 쪼개기 — `[ -f ]`(부재) → `[ -x ]`(실행 불가) → 종료코드 |
| T4 | 회귀 테스트 15케이스 (셸 동작 + 플레이북 계약) |
| T5 | `(예정 — validator-unavailable)` 표기 제거 |

**이번 작업은 서로 다른 두 결함을 함께 고쳤다.** 구현자가 스스로 밝히고 리뷰어가 확인했다:

- **T2가 관찰된 진짜 경로**를 덮는다. 오케스트레이터가 Bash 도구로 검증기를 호출했다가
  세션 승인 게이트에 막힌 경우 — 셸은 이걸 원천적으로 관측할 수 없고, 플레이북 문구만이
  올바른 코드를 고르게 할 수 있다. 새 문구는 **"승인 거부·정책 차단"을 명시**해 관찰된
  실패 모드를 코드 선택 기준에 못박았다.
- **T3는 별개의 실재하던 버그**다. `setup`·`update` 가 파일이 멀쩡히 있는데 "검증기 없음"
  이라고 말하던 오보. 관찰된 사건의 수정은 아니지만 **설계 §2 표가 처음부터 대상으로
  명시**한 결함이라 범위 밖이 아니다.

## 3. 검증 결과

- **린트:** `shellcheck -S warning` 6개 파일 **경고 0**.
- **코드리뷰: 수행함 (서브에이전트, sonnet).** **차단 0 · 권고 0 · 참고 1건.**
  리뷰어가 **직접 실행해서** 확인한 것:
  - **회귀 없음** — 검증기 파일을 실제로 치운 임시 사본에서 `setup`·`update` 를 돌려
    기존 문구가 그대로 나오고 rc=0인 것을 확인.
  - **비차단 보장** — `chmod 644` 사본에서 `setup` rc=0 / `update` rc=0, `HRN-W020` +
    복구 경로 2개 출력 후 **완주**.
  - **뮤테이션 독립 재확인** — 구현자가 `setup` 쪽만 뮤테이트했기에 리뷰어가 **`update`
    쪽을 직접** 되돌려봤다: update 전용 단언 2건만 정확히 FAIL(176→174), 나머지 통과.
    원복 후 `md5sum` 일치·`git status` 공백 증명.
  - **대장 규칙 준수** — 커밋 순서가 T1(등재) → T3(사용)임을 `git log` 로 확인. 오늘 아침
    만든 규칙의 첫 사례를 우리가 지켰다.
  - **T5가 다른 코드를 안 건드림** — `E011~E014`·`W017~W019` 7건은 `(예정)` 그대로 남음.
  - **비대상 침범 0** — `install/validate-config` 자체 미수정, `HRN-E003` 미접촉.
  - **참고 1건**: 셸의 `hrn_warn "W020"` 은 사유를 `"실행 권한 없음"` 고정 문자열로 쓴다.
    설계 §3-1의 "사유를 지어내지 말라"는 원칙 위반이 아니다 — **셸이 관측 가능한 사유는
    그것뿐**이고, 승인 거부·정책 차단은 애초에 셸이 볼 수 없어 플레이북 쪽에서 오케스트레이터가
    직접 관찰 사실을 채우도록 설계됐다. 리뷰어도 "지적이라기보다 참고 확인"으로 분류.
- **테스트:** `tests/install/run-tests.sh` **176 PASS / 0 FAIL** (161 → +15)
- **여전히 못 잡는 것:**
  - **에이전트가 실제로 `W020` 을 고르는지의 행동 검증은 없다.** 계약 테스트는 "그 분기가
    문서에 실존하는지"만 고정한다. 이 문서를 읽고도 여전히 다른 코드를 고를 가능성은 남는다.
    설계 §4가 비대상으로 명시한 한계다.
  - **셸은 승인·정책 차단을 관측할 수 없다.** T3가 잡는 것은 OS 실행 비트뿐이다.
  - root 환경에서는 실행 비트 케이스가 건너뛰어진다(사유는 메시지에 남는다). 이번 실행
    환경은 `id -u`=1000이라 실제로 검사됐다.

## 4. 직접 확인 시나리오

1. 코드표에 등재됐는지 본다.
   ```bash
   cd ~/dev/kgh-dev-harness && grep 'W020' PRD.md
   ```
   - **기대 결과:** `(예정)` 표기 없는 `HRN-W020` 행 1줄.

2. 플레이북 분기가 다섯 갈래인지 본다.
   ```bash
   sed -n '/검증은 직접 하지 않는다/,/지원 모델 목록은/p' core/playbook.md
   ```
   - **기대 결과:** `0`·`1`·`2`·`없으면 E005`·**`있으나 실행 불가면 W020`** 다섯 칸.
     `W020` 줄에 "승인 거부·정책 차단"과 "비차단"이 함께 있어야 한다.

3. **실행 비트를 떼고 설치해본다** (임시 사본에서).
   ```bash
   S=$(mktemp -d); git clone -q ~/dev/kgh-dev-harness "$S/src"
   chmod 644 "$S/src/install/validate-config"
   mkdir -p "$S/proj" && "$S/src/install/setup" "$S/proj" </dev/null 2>&1 | grep -A2 'W020'; echo "rc=${PIPESTATUS[0]}"
   ```
   - **기대 결과:** `HRN-W020 — 컨피그 검증기를 실행할 수 없습니다 (파일은 존재, 사유: 실행 권한 없음)`
     + 안내 2줄(chmod +x / 검증 없이 진행). **설치는 rc=0으로 완주.**

4. **부정 케이스 ①** — 파일이 아예 없으면 예전 문구 그대로다(회귀 방지).
   ```bash
   rm "$S/src/install/validate-config"
   "$S/src/install/setup" "$S/proj" </dev/null 2>&1 | grep '컨피그 검증'
   ```
   - **기대 결과:** `건너뜀 (검증기 없음 — install/update로 최신본을 받으세요)`. `W020` 안 나옴.

5. **부정 케이스 ②** — 정상이면 아무 경고도 없다.
   ```bash
   cd ~/dev/kgh-dev-harness && ./install/validate-config | tail -3
   ```
   - **기대 결과:** `검증 통과`, `W020` 미출현.

6. 전체 회귀.
   ```bash
   bash tests/install/run-tests.sh | tail -2
   ```
   - **기대 결과:** `PASS: 176  FAIL: 0`
