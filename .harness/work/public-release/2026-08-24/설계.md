# 설계 — public-release (클론→설치→즉시사용)

## 1. 요구사항 / 의도

사용자 지시(2026-08-24): 원격 `https://github.com/Immamakeit/kgh-harness.git` 공개 후

- **R-A (사람 경로)** 저장소를 클론해 **가이드대로** 설치·세팅하면 바로 쓸 수 있어야 한다.
- **R-B (에이전트 경로)** 에이전트에게 **저장소 주소만** 주고 "설치해"라고 하면,
  스스로 설치·세팅까지 끝내고 바로 쓸 수 있어야 한다.
- **R-C** 결정이 필요한 항목은 설계자가 추천으로 확정한다(사용자 위임). 게이트에서
  멈추지 않고 완료까지 진행한다 — design-doc §2의 "승인 없이 진행해" 명시 지시에 해당.

상류: 직전 턴 입구 게이트(cost-bottleneck-check) 판정 **CONDITIONAL** — 되물음 1~5
미해소 + P0 차단 버그 1건. 그 되물음의 답을 R-C로 위임받아 §3에서 확정한다.

### 3-2. G1 — 템플릿 컨피그 분리 (근본 원인 제거)

루트 `harness.config.yaml` 이 **이 레포의 실사용 컨피그**이자 **배포 템플릿** 두 역할을
겸하는 것이 원인이다(PRD.md:75). 역할을 쪼갠다.

- 신설 `config/harness.config.template.yaml` — 배포 템플릿. `vault_root: null`,
  `path_template` 의 `<프로젝트>` 는 그대로(플레이스홀더), 주석은 신규 사용자용으로 재작성.
- 루트 `harness.config.yaml` — 이 레포 자신의 컨피그로 격하. `.harnessignore` 에 추가해
  **배포물에서 제외**한다. 개인 vault 경로가 남의 프로젝트로 흘러갈 경로가 사라진다.
- `install/setup:153` `TEMPLATE_CONFIG` → `${HARNESS_DIR}/config/harness.config.template.yaml`.
  `install/update:142` 의 스키마 diff 기준도 동일.
- 치환 정규식(`install/setup:218`)은 방어적으로 **값이 무엇이든** 치환하도록 넓힌다
  (`null` · 따옴표 문자열 · 맨 문자열 모두). 템플릿이 오염돼도 사용자의 선택이 이긴다.
- `install/setup:87` 의 L1 폴백(`SOURCE_DIR/harness.config.yaml`)도 템플릿을 보도록 변경 —
  소스 레포의 개인 설정이 대상의 사전 점검 판단에 끼어들지 않게 한다.

### 3-3. G4 — 자기 자신 설치 차단

`TARGET_DIR` 가 `SOURCE_DIR` 와 같으면 `HRN-E007` 로 **차단**한다(복구 경로 2개:
다른 경로 지정 / 인자로 명시). 소스 트리에 `rsync --delete` 를 거는 사고를 원천 봉쇄.
도그푸딩(CLAUDE.md §7)은 별도 작업으로 남긴다 — 지금은 자기설치 경로가 검증된 적이 없다.

### 3-4. G3·G9 — README (사람 · 에이전트 겸용)

`README.md` 한 장으로 두 경로를 모두 만족시킨다.

1. **맨 위에 에이전트용 블록** — "에이전트가 이 문단만 그대로 실행하면 설치 완료"라고
   명시하고, 클론→설치→검증 3명령을 복붙 가능한 형태로 둔다. 비TTY에서 전부 디폴트로
   흘러가므로 추가 플래그 없이 동작한다(`install/lib.sh:30-64` 폴백).
2. 사람용: 전제(bash·rsync·python3·PyYAML·git / Claude Code / superpowers 선택),
   설치, 설치 후 확인, 업데이트, 제거, 무엇이 설치되는가, HRN 에러 대처, WSL 한정 기능
   (`install/lib.sh:392` vault 탐지), 라이선스.
3. `install/setup -h|--help` 를 추가해 스크립트 단독으로도 사용법이 나오게 한다 —
   에이전트가 README를 못 찾아도 두 번째 경로가 있다.

### 3-5. G5 — templates/ 편입 + 폴백

vault의 3종(`설계`·`구현계획`·`구현후보고`)을 `templates/` 로 동기화(원본은 계속 vault).
`skills/obsidian-cli/SKILL.md` 에 폴백 순서를 명시: **① `<vault_root>/harness/templates/`
가 있으면 그것 ② 없으면 하네스의 `templates/`**. CLAUDE.md §3의 "templates/ 직접 수정
금지" 룰은 유지하되 "vault에서 동기화한 사본을 배포물로 포함한다"는 단서를 추가한다.

### 3-6. G6·G7·G8

- `LICENSE` — **MIT**, 저작권자 `immamakeit`(GitHub 핸들, 실명 비노출).
- `.gitignore` — OS/에디터 부산물 + `*.local.*` 최소 집합. `.harness/work/` 는 ②에 따라 계속 추적.
- 이름 — `install/setup`·`install/update`·`install/lib.sh`·훅의 사용자 노출 문자열에서
  `kgh-dev-harness` → `kgh-harness`. 개발 문서는 미변경.

### 3-7. 검증 설계

- G2를 닫는 회귀 테스트를 `tests/install/run-tests.sh` 에 추가: ① 소스 템플릿이
  `vault_root: null` 임을 단언 ② 값이 박힌 템플릿을 줘도 사용자 입력이 반영됨
  ③ 대상 컨피그에 소스의 개인 경로가 **없음** ④ 자기설치 차단.

  글자 그대로 실행해 빈 프로젝트에 설치 → 개발용 파일 누출 0 · 훅 연결 · 컨피그 생성 ·
  `.harness/install/validate-config` 통과를 확인한다. R-A·R-B의 합격 판정은 이것이다.
