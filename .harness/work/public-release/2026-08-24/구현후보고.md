## 3. 검증 결과

- **린트:** `shellcheck -S warning` — `install/{setup,update,lib.sh,validate-config}`,
  훅, 테스트 스크립트 **경고 0**. `bash -n` 전 파일 통과.
- **코드리뷰:** **서브에이전트 디스패치 없이 메인 세션 자체 리뷰로 대체.**
  이 세션은 Agent 도구 사용이 금지돼 있어 컨피그의 `verify.dispatch: true` ·
  `superpowers:requesting-code-review`를 그대로 실행하지 못했다. 대신 diff 전수 재독 +
  잔여 참조 grep(`HARNESS_DIR}/harness.config` 등 0건) + 기존 설치본 업데이트 경로
  영향 검토를 수행했다. **제3자 리뷰는 미수행 — 이 항목은 "통과"가 아니라 "대체 수행"이다.**
- **요건 충족:**
  - R-A(사람) — README 절차대로 클론→설치→검증이 실측 통과(§4).
  - R-B(에이전트) — README 에이전트 블록을 비대화형(`</dev/null`)으로 글자 그대로 실행해
    통과. 질문은 전부 디폴트로 흘러가고 그 사실이 로그에 남는다.
  - R-C(결정 위임) — 되물음 5건을 설계 §3-1에서 확정, 근거 기재.
- **미검증으로 남는 것 (영향권 명시):**
  - macOS·순수 Linux 실환경 — 이 세션은 WSL뿐이라 vault 탐지 열화 경로를 실측하지 못했다.
    README「한계」에 명시. 탐지 실패는 자유 입력으로 열화하도록 이미 설계돼 있고
    테스트에서 PATH를 깎아 그 경로만 재현했다.
  - 실제 원격에서의 클론 — 원격이 아직 미설정이라 **로컬 경로를 소스로** 클론해 검증했다.
    `git clone <URL>`의 네트워크 구간만 미검증이고 이후 절차는 동일하다.
  - Claude Code 실세션에서의 훅 로드 — 훅 스크립트를 직접 실행해 플레이북+컨피그
    출력을 확인했다(§4-6). 실제 세션 시작은 사용자만 재현 가능하다.

## 4. 직접 확인 시나리오

> 아래를 순서대로 실행하면 "클론한 사람/에이전트가 바로 쓸 수 있는가"가 그대로 확인된다.

1. 클론본을 만든다 (원격 푸시 전이므로 로컬 경로를 소스로).
   ```bash
   S=$(mktemp -d); git clone -q ~/dev/kgh-dev-harness "$S/kgh-harness"
   ```
   - **기대 결과:** 오류 없이 클론됨.

2. 빈 프로젝트에 설치한다 — README 에이전트 블록과 같은 형태.
   ```bash
   mkdir -p "$S/myproject" && "$S/kgh-harness/install/setup" "$S/myproject" </dev/null | tail -8
   ```
   - **기대 결과:** `컨피그: 신규 생성` · `SessionStart 훅: 연결됨` · `컨피그 검증: 통과` ·
     `설치 완료`. vault 미지정이므로 `HRN-W010` 안내가 함께 뜬다(비차단).

3. 개인 정보가 새지 않았는지 본다.
   ```bash
   grep -rn 'gh-obsidian-vaults\|/home/ghkim' "$S/myproject" | wc -l
   grep vault_root "$S/myproject/harness.config.yaml"
   ```
   - **기대 결과:** `0` / `vault_root: null`.

4. 개발용 파일이 섞이지 않았는지 본다.
   ```bash

   ```

     `PRD.md`·`CLAUDE.md`·`tests`·`.claude`·`harness.config.yaml`은 **없어야 한다.**

5. 대상에서 검증기를 돌린다.

   - **기대 결과:** `검증 통과`, `rc=0`.

6. 훅이 플레이북을 주입하는지 본다.


7. 업데이트가 사용자 설정·작업 문서를 지키는지 본다.
   ```bash
   printf '\n# 내설정\n' >> "$S/myproject/harness.config.yaml"
   mkdir -p "$S/myproject/.harness/work/demo" && echo doc > "$S/myproject/.harness/work/demo/설계.md"
   cd "$S/myproject" && ./.harness/install/update </dev/null | tail -6
   ```

9. **부정 케이스 ②** — 소스 자신을 대상으로 지정해도 같다.

   ```bash
   cd "$S/kgh-harness" && ./install/setup "$S/kgh-harness"; echo "rc=$?"
   ```
