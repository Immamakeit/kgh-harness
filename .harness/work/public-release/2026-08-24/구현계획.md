## 1. 작업 범위

설계 §3-2~§3-7 전부. 결함 G1·G3·G4·G5·G6·G7·G8·G9 를 닫고, G2(테스트 사각)를

- E2E(T8)는 마지막 관문 — 앞의 모든 태스크가 실제 설치 경로에서 함께 도는지 본다.

### T2. 자기설치 차단 (G4)
- 목적: 비TTY에서 인자 없이 실행해 소스 트리에 `rsync --delete` 를 거는 사고를 막는다.
- 범위(In/Out): In — `TARGET_DIR == SOURCE_DIR` 가드 / Out — 도그푸딩 설치 지원
- 선행조건: T1 (같은 파일)
- 구현 체크리스트:
  - [ ] `TARGET_DIR` 확정 직후 `SOURCE_DIR` 비교
  - [ ] 같으면 `hrn_err "E007"` + 복구 경로 2개 후 `exit 1`
- 작업 방법 예시:
  ```bash
  if [ "$TARGET_DIR" = "$SOURCE_DIR" ]; then
    hrn_err "E007" "대상이 하네스 소스 레포 자신입니다 (${TARGET_DIR})" \
      "설치할 프로젝트 경로를 인자로 지정하세요: ./install/setup /path/to/project" \
      "자기 자신에 설치(도그푸딩)는 아직 지원하지 않습니다 — 별도 디렉토리를 사용하세요"
    exit 1
  fi
  ```
- 테스트 방식:
  - 절차: fake 소스에서 `setup <소스경로>` 를 비TTY로 실행하고 종료코드·출력을 단언.
  - 기대결과: rc=1, `HRN-E007` 출력, 소스에 `.harness/` 미생성.
  - 테스트 적절성 근거: 파괴적 경로라 "안 도는 것"을 명시적으로 고정해야 한다.
- 완료 기준: 위 단언 PASS.
- 리스크/충돌: T1 직후 같은 파일 편집 — 순차 진행.
