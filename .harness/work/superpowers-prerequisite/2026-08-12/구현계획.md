# 구현 계획 — superpowers 전제화

## 1. 작업 범위

승인된 설계(설계.md, 2026-08-12 승인)의 범위 그대로:
`PRD.md` 문안 정정(R4·R6·§3·§5·§8·§10) · `install/setup` L1b 검출 + 종료 요약 ·

- **목적**: 문서가 구현하지 않을 것을 요구사항으로 주장하는 상태를 없앤다.
- **범위(In/Out)**: In — `PRD.md`만 / Out — 코드·테스트 일체
- **선행조건/의존성**: 없음. T2·T3와 파일이 겹치지 않아 병렬 가능.
- **구현 체크리스트**:
  - [ ] R4(29행) 문안에 전제 명시 + 비고에 W014 안내
  - [ ] R6(30행) "핀 고정 pull" → "사용자 전역 설치 전제(superpowers)", 비고에 §10 이월
  - [ ] §3(41행) v1 범위 문안 수정 + **제외 목록에 "오픈소스 스킬 vendoring·버전 핀 고정" 추가**
  - [ ] §5 구조도(84행)에서 `vendor/skills/` 행 제거
  - [ ] §8 에러표에 `HRN-W014 | superpowers 플러그인 미발견 (경고, 비차단) | 플러그인 설치 또는 컨피그에서 제거`
  - [ ] §10에 "오픈소스 스킬 vendoring / 버전 핀 고정 pull" 항목 신설
- **테스트 방식**:
  - 절차: `git diff PRD.md`로 6곳 전부 확인 + `grep -rn "vendor/skills\|핀 고정 pull" PRD.md`
  - 기대결과: diff 6곳 일치, grep 결과는 §10 이월 항목 **1건만** 남음
  - 테스트 적절성 근거: 문서 단독 변경이라 실행 검증 대상이 없고, 누락·잔존이 유일한 실패 모드라 grep이 정확히 그것을 잡는다.
- **완료 기준**: 위 6개 체크 전부 + grep 잔존 1건(§10)만.
- **리스크/충돌 가능성**: 문서 단독. T2·T3와 파일 비중복이라 충돌 0.

### T2. superpowers 검출 (TDD — 테스트 먼저)

- **목적**: 전제가 깨진 환경에서 setup이 silent 성공하지 않게 한다.
- **범위(In/Out)**: In — `tests/install/run-tests.sh`·`install/lib.sh`·`install/setup` /
  Out — `install/update`(설계 비대상), 자동 설치, 버전 판정
- **선행조건/의존성**: 없음(T1과 독립). 단 W014 코드 정의는 T1과 문안이 일치해야 함.
- **구현 체크리스트** (순서 강제 — RED 먼저):
  - [ ] **RED**: `run-tests.sh`에 신규 섹션 "전제: superpowers 플러그인 → HRN-W014"
        4분기 어서션 추가 → 실행하여 **실패를 눈으로 확인**
  - [ ] `lib.sh`: `superpowers_skills_in_config <yaml>` — `stages.*.skills`에서
        `superpowers:` 접두사 항목을 수집해 개행 구분 출력 (0개면 빈 출력)
  - [ ] `lib.sh`: `detect_superpowers` — `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/installed_plugins.json`
        조회. python3 있으면 JSON 파싱, 없으면 `grep -q '"superpowers@'` 폴백,
        둘 다 불가면 `unknown` 반환(fail-open). 발견 시 버전 문자열도 반환
  - [ ] `setup`: L1 블록(82-99행) 뒤에 L1b — `active_harness != claude`면 `note` 후 통과,
        컨피그 superpowers 항목 0개면 점검 건너뜀, 그 외 검출 결과에 따라 `ok` / `hrn_warn W014`
  - [ ] W014 메시지: 확인 경로 출력 + **영향 구간·스킬명을 컨피그에서 읽어** 출력(하드코딩 금지)
        + 복구 2경로(플러그인 설치 / 컨피그에서 제거)
  - [ ] 종료 요약에 `superpowers  : 확인됨 v<버전> | 미발견(W014) | 점검 안 함` 1행
  - [ ] **GREEN**: 스위트 재실행 — 신규 4분기 PASS + **기존 57어서션 회귀 0**
- **테스트 방식**:
  - 절차: `CLAUDE_CONFIG_DIR`을 샌드박스로 가리켜 4분기 실측 —
    ① 매니페스트에 superpowers 있음 → W014 미출력·요약 "확인됨"
    ② 매니페스트 있으나 키 없음 → 정상 종료(비차단)·W014 출력·**영향 구간명 4개 포함**·`.meta` 존재
    ③ 매니페스트 파일 부재 → 정상 종료·W014 출력·**확인 경로 문자열 포함**
    ④ 컨피그에 `superpowers:` 0개 → 점검 건너뜀·W014 미출력
  - 기대결과: 신규 전부 PASS, 총계 `PASS 61+ / FAIL 0`
  - 테스트 적절성 근거: 셸 스크립트의 분기 동작이라 단위 함수 호출만으로는 setup 전체
    경로(비차단으로 끝까지 진행하는지)를 못 본다. 기존 스위트와 같은 통합 실행 방식이 맞다.
  - 린트: `bash -n` 3파일. **shellcheck는 여전히 미설치라 못 돌린다 — 통과가 아님을 보고에 명시.**
- **완료 기준**: 스위트 `FAIL 0`, 기존 57 유지, ②③에서 종료코드 0(비차단 실증).
- **리스크/충돌 가능성**: `setup`을 건드리므로 기존 57어서션이 회귀 감시 역할을 한다.
  T1(문서)·T3(플레이북)과 파일 비중복.

### T3. 플레이북 런타임 처리 (독립)

- **목적**: 설치를 통과한 뒤 런타임에 스킬이 없을 때도 silent가 되지 않게 한다.
- **범위(In/Out)**: In — `core/playbook.md` §1-4 / Out — 컨피그 스키마 변경
- **선행조건/의존성**: 없음. T1의 W014 문안과 일치시킬 것.
- **구현 체크리스트**:
  - [ ] §1-4에 추가: Skill 도구 호출이 "스킬 없음"으로 실패하면 ① 즉시 `HRN-W014` 보고
        ② **흐름을 막지 않고** 해당 구간을 스킬 없이 진행 + 그 사실을 구간 보고에 명시
        ③ 복구 2경로 출력
  - [ ] 차단(E)이 아닌 이유를 한 줄로 박아둔다 — 나머지 7구간·내 스킬 7종은 정상 동작
- **테스트 방식**:
  - 절차: 지침 문서라 실행 검증 대상이 없다. `grep -n "W014" core/playbook.md PRD.md`로
    코드·문안이 T1과 일치하는지 대조하고, §1의 기존 E001/E008/E010 항목과 **형식이 같은지**
    육안 대조한다.
  - 기대결과: W014 문구가 두 파일에서 동일, 기존 에러 항목과 서식 일치.
  - 테스트 적절성 근거: 플레이북은 실행 코드가 아니라 세션에 주입되는 지침이므로,
    검증 가능한 실패 모드는 "코드 정의 불일치·서식 이탈"뿐이다. 실동작은 실사용에서 드러난다.
- **완료 기준**: 두 파일 W014 문구 일치, §1 서식 일치.
- **리스크/충돌 가능성**: 문서 단독. 충돌 0.
