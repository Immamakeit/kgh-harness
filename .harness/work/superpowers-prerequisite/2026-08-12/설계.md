# 설계 — superpowers 전제화 (R6 축소 + 전제 깨짐 감지)

## 1. 요구사항 / 의도

- **사용자 확정 (2026-08-12):** superpowers를 패키지가 나르지 않고 **전제로 둔다.**
  `vendor/skills/` 오픈소스 핀 고정 pull은 v1에서 하지 않는다.
- 그 결과 두 가지가 따라온다:
  1. **PRD 문안이 현실과 어긋난다.** R6은 "오픈소스 스킬(핀 고정 pull)"을 요구사항으로
     박아두었고 §5 구조도에 `vendor/skills/`가 있으나 구현은 없다. 문서가 거짓말을
     하는 상태다.
  2. **전제가 깨진 환경에서 silent로 무너진다.** superpowers 미설치 프로젝트에
     설치해도 setup은 성공을 보고하고, 런타임에 ②③⑦⑧ 네 구간이 조용히 깨진다.
     PRD §8 "silent 에러 금지" 위반이다.
- 이번 작업의 목적: **문안 정정 + 전제 깨짐의 비차단 표면화.** 자동 설치는 하지 않는다.

## 3. 설계안

### 3-1. PRD 문안 정정 (문서만)

- **R4**: "패키지 설치형 — **superpowers 플러그인이 설치된** Claude Code 환경이면
  어느 프로젝트든 설치만 하면 동작" + 비고에 "전제 미충족 시 `HRN-W014` 안내"
- **R6**: "스킬 내장: 내 스킬(vendored) + **오픈소스 스킬은 사용자 전역 설치를 전제**
  (superpowers)" + 비고에 "핀 고정 pull은 §10 추후"
- **§3 v1 범위**: "하이브리드 스킬 번들" → "내 스킬 번들 + superpowers 전제",
  **제외 목록에 "오픈소스 스킬 vendoring·버전 핀 고정" 추가**
- **§5 구조도**: `vendor/skills/` 행 제거 (부재 디렉토리를 구조도에 두지 않는다)
- **§8**: `HRN-W014 | superpowers 플러그인 미발견 (경고, 비차단) | 플러그인 설치` 추가
- **§10**: "오픈소스 스킬 vendoring / 버전 핀 고정 pull" 항목 신설 — 포기가 아니라 이월임을 박제

### 3-2. `install/setup` — 사전 점검 L1b (신규, 비차단)

`install/setup:82-99`의 L1 블록 **바로 뒤**에 동일 패턴으로 추가한다.

1. **적용 조건**: `active_harness == claude`일 때만. (플러그인 매니페스트는 Claude Code
   고유 규격 → 어댑터 소유. 다른 값이면 `note`로 건너뜀을 알리고 통과)
2. **필요 여부 판정**: 컨피그의 `stages.*.skills`에서 `superpowers:` 접두사 항목을
   수집한다. **0개면 점검 자체를 건너뛴다** (컨피그에서 다 빼버린 사용자를 괴롭히지 않음).
3. **검출**: `MANIFEST="${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/installed_plugins.json"`
   - 파일 존재 + `superpowers@` 키 발견 → `ok "superpowers 확인: v<버전> (<N>개 구간에서 사용)"`
   - 파일 존재하나 키 미발견 → **W014**
   - 파일 부재 → **W014** (플러그인을 한 번이라도 설치했으면 매니페스트는 존재한다.
     오탐 여지가 있으므로 경고 문구에 **확인한 경로를 반드시 출력**해 사용자가 판단 가능하게 한다)
4. **W014 메시지 계약**:
   - 미충족 사실 + 확인 경로
   - **영향 구간을 이름으로 명시** — 컨피그에서 수집한 실제 구간명(clarify·plan·
     implement·verify)과 스킬명. 하드코딩 금지
   - 복구 경로 2개: (a) `/plugin marketplace add obra/superpowers-marketplace` →
     `/plugin install superpowers` (b) `harness.config.yaml`의 해당 `skills[]`에서
     `superpowers:` 항목 제거
5. **비차단**: 설치는 그대로 완료된다. 종료 요약(`install/setup:253~`)에
   `superpowers : 확인됨 v6.1.1 | 미발견(W014) | 점검 안 함` 한 줄 추가.
6. **파싱**: `python3` 있으면 JSON 파싱, 없으면 `grep -q '"superpowers@'` 폴백.
   둘 다 안 되면 `note`로 "확인 불가, 건너뜀" (fail-open — 오탐보다 낫다).

### 3-3. `core/playbook.md` — 런타임 처리 (§1-4에 추가)

Skill 도구 호출이 "해당 스킬 없음"으로 실패하면:
① silent 금지 — 즉시 `⚠️ HRN-W014 — superpowers 스킬 '<이름>' 미발견` 보고
② **흐름을 막지 않는다.** 해당 구간을 스킬 없이 진행하고, 그 사실을 구간 보고에 명시
③ 복구 경로 2개(플러그인 설치 / 컨피그에서 제거)를 함께 출력

설치 시점(setup=W014 경고)과 런타임 시점(플레이북=W014 보고) 둘 다 비차단으로 통일한다.
E 코드로 올리지 않는 이유: superpowers 없이도 나머지 7구간과 내 스킬 7종은 정상 동작하므로,
차단은 과잉이다.

### 3-4. 회귀 테스트 (`tests/install/run-tests.sh`)

신규 섹션 "전제: superpowers 플러그인 → HRN-W014" — `CLAUDE_CONFIG_DIR`을 샌드박스로
가리켜 3분기를 실측한다:

| 케이스 | 기대 |
|---|---|
| 매니페스트에 superpowers 있음 | setup 정상 종료 · W014 미출력 · 요약에 "확인됨" |
| 매니페스트 있으나 superpowers 없음 | 정상 종료(비차단) · W014 출력 · **영향 구간명 4개 포함** · 설치 완료(.meta 존재) |
| 매니페스트 파일 부재 | 정상 종료 · W014 출력 · **확인 경로 문자열 포함** |
| 컨피그에 `superpowers:` 0개 | 점검 건너뜀 · W014 미출력 |

기존 57어서션은 전부 유지되어야 한다(회귀 0).

## 4. 작업 범위 / 비대상

**범위**: `PRD.md`(R4·R6·§3·§5·§8·§10) · `install/setup`(L1b + 종료 요약) ·
`install/lib.sh`(필요 시 검출 헬퍼) · `core/playbook.md`(§1-4 런타임 처리) ·
`tests/install/run-tests.sh`(신규 4어서션 이상).

**비대상** (알고 있으나 이번에 안 함):
- **superpowers 자동 설치** — 감지·안내까지만. 사용자 전역 환경을 스크립트가 건드리지 않는다
- **버전 하한 검증** — 현재 v6.1.1이 유일한 실측치이고 최소 요구 버전이 정해진 바 없다.
  버전은 **표시만** 하고 판정하지 않는다
- **`install/update`에 동일 점검 추가** — setup 1회 점검 + 런타임 보고로 충분. 후속
- **다른 오픈소스 스킬로의 일반화** — superpowers 하나만 대상
- **`vendor/skills/` 핀 고정 pull** — PRD §10으로 이월(포기 아님)
- **stage 정의 3중 중복 해소**(직전 판단 게이트에서 발견한 결함) — 별도 작업으로 분리
- **shellcheck 정적 분석** — 여전히 미설치. 설치되면 별도로 돌린다
