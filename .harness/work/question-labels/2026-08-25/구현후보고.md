# 구현 후 보고 — question-labels

## 1. 변경 요약

사용자가 지적한 하네스 결함을 닫았다 — **플레이북 §6이 "선택지를 제시하라"까지만 정하고
라벨을 규정하지 않아**, `ask_choice`(번호)와 HRN 복구 경로(`(a)(b)`) 두 관례가 대화에서
섞였다. 심지어 추천을 위로 올리며 라벨을 안 고쳐 **`(b) (a) (c) (d)`** 순서까지 나갔다.

| 태스크 | 결과 |
|---|---|
| T1 | 플레이북 §6에 라벨 조항 — 선택지=번호, 번호는 표시 순서와 일치, 추천은 `(추천)` 꼬리표, 복구 경로 `(a)(b)`는 **안내지 선택지가 아님** |
| T2 | `set-initial`·`branch-strategy` 질문 계약에 **글자 그대로 동일한** 문구 상속 |
| T3 | 계약 테스트 (플레이북 2 + 스킬 2) |
| T4 | **`plan-doc` 범위 게이트 정정 — 이 결함의 발원지** |
| T5 | ⑧ 지적 반영 — 뚫린 단언 교체 + `Y/n` 예외 명문화 |

## 2. 발원지를 찾은 것이 이 작업의 핵심

계획은 손댈 곳을 플레이북 + 스킬 2개로 잡았다. 구현 직후 **전수 grep에서 `plan-doc` 이
걸렸다** — 범위 게이트가 사용자에게 고르라고 물으면서 `(a)/(b)` 를 쓰고 있었다.

**오늘 오케스트레이터가 `model` 미적용 고지를 범위 게이트로 올릴 때 알파벳을 쓴 것도
여기서 배운 것이다.** 플레이북과 스킬만 고쳤으면 **규칙과 교재가 어긋난 채로** 남았다.
번호로 바꾸면서 없던 기본값을 `2) 별도 작업으로 분리` 로 정했다 — 범위 게이트에서는
넓히는 쪽이 아니라 **지키는 쪽**이 안전한 기본값이다.

- **코드리뷰: 수행함 (서브에이전트, sonnet).** **차단 0 · Important 1 · Minor 2** → T5로 처리.
  - **Important — 내가 쓴 단언이 뚫렸다.** T4에서 넣은
    `assert_not_contains "**(a) 설계 수정"` 은 리터럴 한 문자열에만 걸려, 볼드를 떼거나
    문구를 바꿔 다시 넣으면 통과했다. **리뷰어가 뮤테이션으로 실증했다** — 번호형 게이트는
    그대로 두고 `(a) 설계 수정 경로라고 불렀다` 를 다른 곳에 추가했더니 **185/185 전부 PASS.**
    → `plan-doc` 전체에서 `(a)`/`(b)` 부재를 단언하도록 교체. 우회 뮤테이션 재현 시
    새 단언이 정확히 FAIL 하는 것을 확인했다.
  - **Minor — `Y/n` 이진 확인**이 "선택지=번호"를 문자 그대로 읽으면 위반이 된다.
    `ask_yn` 의 관용 형태라 플레이북에 **예외로 명문화**하고 단언을 붙였다.
  - **Minor — `branch-strategy:82` 의 서술형 `(a)(b)(c)`** 는 고르라는 게 아니라 나열이라
    규칙 대상이 아니다. 그대로 둔다.
  - **전수 조사(리뷰어가 더 넓게 돌림)**: `A.`·`가)`·`①` 등 다른 라벨 체계 **매치 0건**,

    **스킬 9개 전수** — 살아있는 선택지 자리에 알파벳이 남은 곳 **없음**.

  - **뮤테이션 5종** 전부 해당 단언만 격리 FAIL, 원복 증명 완료.

## 5. 이 작업이 드러낸 하네스의 다른 공백 (후속 후보)

컨피그는 `implement.dispatch: true` 인데 **3~10줄 수정에 서브에이전트를 띄우면 작업보다
비용이 크다.** 플레이북 §2는 "규모가 작으면 ①·④를 건너뛸 수 있다"만 정하고 **⑦ 디스패치의
최소 단위는 정하지 않는다.** 오늘 그 판단을 **세 번 즉흥적으로** 했고 세 번 다 기록으로
남겼다(`agent-mode` T6, 이 작업 T4·T5). 즉흥 판단이 반복되면 규칙으로 올려야 한다는 신호다.

## 6. 직접 확인 시나리오

1. 규칙이 플레이북에 있는지 본다.
   ```bash
   cd ~/dev/kgh-dev-harness && sed -n '/선택지 라벨/,/이진 확인/p' core/playbook.md
   ```
   - **기대 결과:** 선택지=번호 · 순서 일치 · `(추천)` 꼬리표 · 복구 경로는 안내 · `Y/n` 예외.

2. 두 스킬이 같은 문구를 물려받았는지 본다.
   ```bash
   grep -h '번호는 표시 순서와 항상 일치' skills/set-initial/SKILL.md skills/branch-strategy/SKILL.md | sort -u | wc -l
   ```
   - **기대 결과:** `1` (문구가 하나뿐 = 두 파일이 동일).

3. 발원지가 고쳐졌는지 본다.
   ```bash
   sed -n '/비대상입니다/,/기본: 2/p' skills/plan-doc/SKILL.md
   ```
   - **기대 결과:** `1) 2) 3) 직접 입력` + `번호 입력 [기본: 2]`.

4. **부정 케이스** — 알파벳을 다시 넣으면 테스트가 잡는다.
   ```bash
   cp skills/plan-doc/SKILL.md /tmp/pd.bak
   printf '\n(a) 설계 수정 경로라고 부르기도 한다.\n' >> skills/plan-doc/SKILL.md
   bash tests/install/run-tests.sh 2>&1 | grep '알파벳 라벨 부재'
   cp /tmp/pd.bak skills/plan-doc/SKILL.md && rm /tmp/pd.bak
   ```
   - **기대 결과:** `[FAIL] plan-doc 에 알파벳 라벨 부재 — (a) 또는 (b) 가 발견됨`.
     (원복 후 다시 돌리면 187 PASS)

5. 전체 회귀.
   ```bash
   bash tests/install/run-tests.sh | tail -2
   ```
   - **기대 결과:** `PASS: 187  FAIL: 0`
