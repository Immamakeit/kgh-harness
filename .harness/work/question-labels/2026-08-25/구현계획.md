## 3. 작업 방법 (예시 포함)

### T1. 플레이북 §6 질문 규칙에 라벨 조항
- 목적: 규칙의 원본을 고친다. 셸(`ask_choice`)만 있던 표준을 대화 경로까지 넓힌다.
- 범위(In/Out): In — 선택지 라벨·순서 일치·추천 표시·안내와의 구분 / Out — HRN 복구 경로 표기 변경
- 선행조건: 없음
- 체크리스트:
  - [ ] **선택지 = 번호**, 번호는 **표시 순서와 항상 일치**
  - [ ] 추천은 라벨이 아니라 **`(추천)` 꼬리표**로 — 재정렬 시 번호를 다시 매긴다
  - [ ] **복구 경로 `(a)(b)` 는 선택지가 아니라 안내**임을 명시
  - [ ] 왜 이 조항이 생겼는지 한 줄 근거(2026-08-25 실제 사고)
- 작업 방법 예시:
  ```
  선택지에는 **번호**를 쓴다(`1) 2) 3)`). 번호는 **표시 순서와 항상 일치한다** —
  추천을 위로 올렸으면 번호를 다시 매긴다. 추천은 라벨이 아니라 `(추천)` 꼬리표로
  표시한다. HRN 복구 경로의 `(a) (b)` 는 **선택지가 아니라 안내**다 — 사용자가
  고를 것을 물을 때는 알파벳을 쓰지 않는다.
  ```
- 테스트 방식: 절차 — T3 계약 단언. 기대결과 — 조항 실존, 지우면 FAIL.
  근거 — 플레이북은 LLM이 읽는 문서라 행동은 못 잡아도 **사라지는 것은** 잡는다.
- 완료 기준: 조항 실존 + T3가 고정.
- 리스크/충돌: 플레이북 단독.

### T2. 스킬 두 개에 상속
- 목적: 같은 계약을 쓰는 스킬이 다시 갈라지지 않게 한다.
- 범위(In/Out): In — 질문 계약 4요소에 "번호는 표시 순서와 일치" 추가 / Out — 질문 내용 변경
- 선행조건: T1
- 체크리스트:
  - [ ] `set-initial` 질문 계약 절에 추가
  - [ ] `branch-strategy` 질문 계약 절에 추가
  - [ ] **두 문구가 동일**할 것 — 갈리면 이 작업의 취지가 무너진다
  - [ ] 기존 예시 중 순서·라벨이 어긋난 것이 있으면 바로잡는다
- 테스트 방식: 절차 — 두 파일에서 같은 문구를 grep로 확인 + T3 단언.
  기대결과 — 두 파일 모두 매치. 근거 — 상속 누락은 조용히 지나간다.
- 완료 기준: 두 파일에 동일 문구 + T3 통과.
- 리스크/충돌: 스킬 문서 둘.

### T3. 계약 테스트
- 목적: 규칙이 사라지는 것을 잡는다.
- 범위(In/Out): In — 플레이북·스킬 2개의 조항 실존 단언 / Out — 행동 검증(불가)
- 선행조건: T1·T2
- 체크리스트:
  - [ ] 플레이북에 "번호는 표시 순서와 일치" 취지 실존
  - [ ] 플레이북에 "복구 경로는 선택지가 아니다" 취지 실존
  - [ ] `set-initial`·`branch-strategy` 양쪽에 상속 문구 실존
  - [ ] 기존 `test_playbook_rule_contracts` 스타일(`assert_regex`·`flat` 평탄화) 따를 것
- 테스트 방식: 절차 — 전체 회귀 + 뮤테이션(각 조항을 지우면 해당 단언만 FAIL).
  기대결과 — 176 + 신규, FAIL 0. 근거 — `agent-mode`·`branch-strategy` 에서 뮤테이션이
  "통과만 시키는 테스트"를 실제로 걸러냈다.
- 완료 기준: FAIL 0 + 뮤테이션에서 해당 단언만 죽는다.
- 리스크/충돌: 테스트 파일 단독.

## 6. 착수 후 발견 → T4 (2026-08-25)

계획서 §2가 손댈 곳을 `set-initial`·`branch-strategy` 둘로 잡았는데, **오케스트레이터가
구현 직후 전수 grep(`grep -rn '(a)' skills/ core/playbook.md`)을 돌려 빠진 곳을 찾았다.**

### 무엇이 빠졌나

`skills/plan-doc/SKILL.md:19` 의 **범위 게이트**가 사용자에게 고르라고 물으면서 알파벳을 쓴다:

> **(a) 설계 수정 → 재승인 → 이번 계획에 반영**  **(b) 별도 작업으로 분리**

**이것이 이 결함의 발원지였다.** 오늘 세션에서 오케스트레이터가 `model` 미적용 고지를
범위 게이트로 올릴 때 `(a)/(b)` 를 쓴 것도, `plan-doc` 이 그 형태를 가르치고 있었기
때문이다. 플레이북과 스킬 둘만 고치고 여기를 놔뒀으면 **규칙과 교재가 어긋난 채로
남았을 것이다.**

### T4. `plan-doc` 범위 게이트 라벨 정정 (범위 내)
- 선택지를 `1) 2) 3) 직접 입력` + `번호 입력 [기본: 2]` 로 바꾼다.
- **기본을 2)(별도 작업 분리)로 둔다** — 범위를 넓히는 쪽이 아니라 **지키는 쪽**이 안전한
  기본값이다. 원래 문서에는 기본이 없었으므로 이번에 정한다.
- 본문의 `(a) 경로`·`범위 게이트 (a)` 참조 2곳도 `1)` 로 맞춘다.
- 계약 테스트 2단언 추가 — 번호로 제시되는지 + 알파벳 잔여가 없는지.
- **이 수정은 오케스트레이터가 메인 세션에서 인라인으로 처리했다** — 3줄 편집이라
  디스패치 비용이 작업보다 크다고 판단했다. 컨피그(`implement.dispatch: true`)와 다르게
  행동한 것이므로 여기와 구현후보고에 남긴다.
- 결과: 183 → **185 PASS**, `grep` 재확인에서 스킬 내 선택지용 알파벳 **잔여 0**.
