# 설계 — question-labels (선택지 라벨 통일)

## 1. 요구사항 / 의도

2026-08-25 사용자 지적: *"옵션을 줄 때 1, b, c 왜 이런 식으로 줌? a,b,c 이거나 1,2,3
이런 식으로 통일해서 줘야지?"*

**실물 증거** — 같은 세션에서 오케스트레이터가 낸 선택지들:

| 자리 | 라벨 | 문제 |
|---|---|---|
| 이메일 처리 선택 | `(b) (a) (c) (d)` | **표시 순서와 라벨이 어긋남** |
| `model` 미적용 고지 범위 게이트 | `(a) (b)` | 선택지인데 알파벳 |
| 푸시 여부 · 오픈 이슈 2건 | `1) 2) 3)` | 정상 |

가장 나쁜 것은 이메일 질문이었다. **추천안을 맨 위로 올리면서 라벨은 원래 것(`b`)을 그대로
들고 가** `b → a → c → d` 순서가 됐다.

**실제 손해**: 그 뒤 사용자가 **번호로 제시된 목록에 `1: a` / `2: b` 로 답했다.**
오케스트레이터가 "a는 첫 번째겠지"라고 **추측해서** 읽어야 했다. 라벨 체계가 오락가락하니
답하는 쪽도 아무거나 쓰게 된 것이다.

## 2. 작업 대상 및 영향도 (실측)

| 위치 | 현재 상태 |
|---|---|
| `core/playbook.md` §6 질문 규칙 | *"선택지를 제시하고 디폴트를 표시한다"* 까지만 정하고 **라벨을 규정하지 않는다** |
| `install/lib.sh` `ask_choice` | **번호로 고정.** 셸 경로만 표준이 있다 |
| `PRD.md` §8 · 플레이북 전반 | HRN 복구 경로는 **`(a) (b)`** 형태 |
| `install/lib.sh` `hrn_warn` | 출력은 `안내 1: / 안내 2:` — 같은 복구 경로인데 **또 다른 형태** |
| `skills/set-initial/SKILL.md` | 질문 계약 4요소(번호·직접 입력·건너뛰기·기본번호)를 강제하나 **"번호가 표시 순서와 일치"는 없다** |
| `skills/branch-strategy/SKILL.md` | 같은 계약을 상속 — 같은 공백 |

**근본 원인은 세 층이다.**
1. 규칙이 절반만 있다 — 셸 경로만 표준, 대화 경로는 무규정.
2. 저장소 안에 서로 다른 관례가 둘 다 살아 있다 — `ask_choice`(번호) vs HRN 복구 경로(`(a)(b)`).
3. 라벨을 규칙에서 뽑지 않고 **쓰는 순간에 만든다.** 강제 장치가 없어 문맥에 따라 갈린다.

## 3. 설계안

### 3-1. "선택지"와 "안내"를 가른다 — 이것이 핵심

혼동의 뿌리는 **고르라는 것**과 **알려주는 것**에 같은 표기를 써온 데 있다. 둘을 갈라
각각 라벨을 고정한다.

**선택지(사용자가 고르는 것) = 번호**
```
  1) …  (추천)
  2) …
  3) 직접 입력
번호 입력 [기본: 1]
```
- **번호는 표시 순서와 항상 일치한다.** 추천을 위로 올리면 **번호를 다시 매긴다.**
- 추천은 **라벨이 아니라 `(추천)` 꼬리표**로 표시한다 — 이메일 질문이 깨진 지점이 여기다.
- `ask_choice` 가 이미 번호이므로 셸과 대화가 같은 모양이 된다.

**복구 경로(고르는 게 아니라 안내) = `(a) (b)` 유지**
- HRN 계약 전체가 이미 이 형태다. 바꾸면 `PRD.md` §8과 모든 스킬을 함께 고쳐야 한다.
- 대신 **"이건 선택지가 아니라 안내"임을 명문화**한다. 지금은 그 구분이 어디에도 없어서
  오케스트레이터가 **고르라는 질문에도 `(a)(b)` 를 썼다**(이메일 처리·범위 게이트).
  새 규칙에서 그 둘은 **번호가 된다.**

### 3-2. 상속 — 스킬 두 개

`set-initial` 과 `branch-strategy` 의 질문 계약 4요소에 **"번호는 표시 순서와 일치한다"**
를 더한다. 두 스킬 다 같은 계약을 쓰므로 한쪽만 고치면 다시 갈라진다.

### 3-3. 계약 테스트

`agent-mode` 에서 만든 `test_playbook_rule_contracts` 방식을 그대로 쓴다 — 규칙 문장이
문서에 실존하는지 단언한다. **행동은 못 잡는다**(아래 §4).

## 4. 작업 범위 / 비대상

- **범위:** §3-1 ~ §3-3.
- **비대상:**
  - **HRN 복구 경로를 번호로 바꾸는 것** — `PRD.md` §8 전체와 모든 스킬·스크립트를 동시에
    고쳐야 한다. 얻는 것보다 흔드는 게 크다. 대신 §3-1로 용도를 갈라 혼동을 없앤다.
  - **`hrn_warn` 의 `안내 1: / 안내 2:` 출력 형식 통일** — 같은 복구 경로인데 문서는
    `(a)(b)`, 셸 출력은 `안내 1/2` 로 갈려 있다. 실제 혼동을 일으킨 적은 없어 이번에
    건드리지 않는다. 별도 작업 후보로 기록한다.
  - **에이전트가 실제로 그 라벨을 쓰는지의 행동 검증** — 오늘 이 결함을 찾아낸 것도
    테스트가 아니라 **사용자의 눈**이었다. 그 사실을 규칙 옆에 근거로 적는다.
  - **과거 대화의 라벨 소급 정정** — 지난 턴들을 고쳐 쓰지 않는다.
