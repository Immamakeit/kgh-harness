### T1. `join_lines` 마지막 줄 유실 (트랙 A, 선행)

- **목적**: 개행 없이 끝나는 입력에서 마지막 항목이 사라지는 잠재 결함을 닫는다.
- **범위(In/Out)**: In — `install/lib.sh` 1줄 + `run-tests.sh` 단위 섹션 신설 /
  Out — 호출부 변경(현 2곳은 `sort -u`를 거쳐 이미 안전)
- **선행조건/의존성**: 없음. T3의 선행(같은 파일이라 T3보다 먼저).
- **구현 체크리스트**:
  - [ ] **RED**: `run-tests.sh`에 `test_join_lines` 섹션 신설 — 5케이스
        (0줄 / 1줄 / 다줄 / **개행 없는 마지막 줄** / 다중바이트 구분자 바이트 일치).
        실행해 개행 없는 케이스가 **실패하는 것을 관찰**
  - [ ] `install/lib.sh` — `while IFS= read -r line` → `while IFS= read -r line || [ -n "$line" ]`
  - [ ] **GREEN**: 5케이스 전부 PASS, 기존 72어서션 회귀 0
- **테스트 방식**:
  - 절차: `printf 'a\nb\nc' | join_lines '·'` 가 `a·b·c`인지, `printf '' | join_lines '·'`가
    빈 출력인지, `xxd`로 `·`가 `c2b7` 온전한지 확인. 스위트에 어서션으로 영구화.
  - 기대결과: 수정 전 개행없음 케이스 FAIL → 수정 후 PASS. 총계 72 → 77 이상.
  - 테스트 적절성 근거: 함수 단위 결함이고 통합 경로(`sort -u`)가 가려버리므로,
    통합 테스트로는 영원히 안 잡힌다. 단위 어서션이 유일하게 유효한 검증이다.
- **완료 기준**: 스위트 `FAIL 0`, 신규 5케이스 존재, 기존 72 유지.
- **리스크/충돌 가능성**: T3과 같은 파일 → 반드시 T1 먼저. T2와는 파일 비중복.

### T3. shellcheck 마감 (트랙 A, T1 이후)

- **목적**: 두 작업(install-scripts·superpowers-prerequisite)에 걸쳐 밀린 정적 분석을 닫고,
  검증 없이 박아둔 `disable` 지시자 5개의 진위를 가린다.
- **범위(In/Out)**: In — 셸 5파일의 error/warning 수정, disable 지시자 검증 /
  Out — info·style 지적 수정(기록만), 리팩터링
- **선행조건/의존성**: **T1 완료 후** (같은 파일). shellcheck 설치 성공.
- **구현 체크리스트**:
  - [ ] sudo 없이 `~/.local/bin/shellcheck` 설치 (GitHub 릴리스 정적 바이너리).
        실패 시 **중단하고 보고** — 임의로 sudo 시도 금지
  - [ ] 5파일 실행: `install/{lib.sh,setup,update}` · `tests/install/run-tests.sh` ·
        `adapters/claude/hooks/session-start.sh`
  - [ ] **error·warning 전부 수정**. info·style은 코드별 건수 목록만 남김
  - [ ] 기존 disable 5개 검증 — 지시자를 떼고 재실행해
        ① 경고 없음 → **지시자 제거** ② 경고 있음 → 사유 주석이 실제 코드와 맞는지 확인,
        어긋나면 정정. **5개 각각의 판정과 근거를 남긴다**
  - [ ] 수정 후 스위트 재실행 — 회귀 0
- **테스트 방식**:
  - 절차: `shellcheck -S warning <5파일>` 종료코드 0 확인 + `shellcheck -S style <5파일>`
    출력을 목록으로 보존. 그 뒤 `bash tests/install/run-tests.sh`.
  - 기대결과: warning 이상 0건, 스위트 `FAIL 0`(회귀 없음).
  - 테스트 적절성 근거: 정적 분석 수정은 런타임 동작을 조용히 바꿀 수 있다(인용부호
    추가 등). 스위트 재실행이 유일한 회귀 방어선이다.
- **완료 기준**: `shellcheck -S warning` 클린, 스위트 `FAIL 0`, disable 5개 판정 기록 완료.
- **리스크/충돌 가능성**: 인용부호 수정이 동작을 바꿀 수 있음 → 스위트가 감시.
  T1 이후 직렬이라 트랙 내 충돌 없음.
