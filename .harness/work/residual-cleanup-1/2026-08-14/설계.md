## 3. 설계안

### 3-1. `join_lines` 마지막 줄 유실 (item 1)

- `while IFS= read -r line` → `while IFS= read -r line || [ -n "$line" ]`.
- 테스트: `run-tests.sh`에 **`join_lines` 단위 섹션** 신설(현재 없음). 최소 5케이스 —
  0줄 / 1줄 / 다줄 / **개행 없는 마지막 줄** / 다중바이트 구분자 바이트 일치.
- RED 필수: 개행 없는 케이스가 수정 전에 실패하는 것을 관찰한 뒤 고친다.

### 3-2. status 계약 충돌 (item 2)

**원칙: 문서 status의 정의처는 소유 스킬 하나뿐이다.** obsidian-cli는 값을 지시하지 않고
소유 스킬이 정한 수명주기를 따른다.

수명주기를 각 소유 스킬에서 **끝까지** 정의한다 (지금은 중간에서 끊겨 있어 obsidian-cli가
빈칸을 창작하게 만들었다):

| 문서 | 수명주기 (소유 스킬) |
|---|---|
| 설계 | `작성중 → 승인대기 → **승인**` (반려 시 `승인대기` 유지) — design-doc |
| 구현계획 | `작성중 → 확정` (저장 시 변경 없음) — plan-doc |
| 구현후보고 | `보고 → **판정통과**` (판정 실패 시 `보고` 유지, ⑦ 재진입) — report-doc |

- `skills/obsidian-cli/SKILL.md:34`를 "status는 **소유 스킬이 정의한 수명주기의 최종
  상태**로 갱신한다(값을 창작하지 않는다). 3종 최종 상태는 위 표" 로 교체.
- design-doc·report-doc에 최종 상태를 추가한다. **"다른 상태값 창작 금지" 문구는 유지** —
  창작을 막되 정당한 종착 상태를 비워두지 않는 것이 이번 수정의 요지다.
- 이미 vault에 저장된 6문서의 status도 새 계약에 맞춘다(설계=승인은 이미 맞음,
  구현후보고 2건은 `보고` → `판정통과`).

### 3-3. shellcheck 실행 (item 3)

- **설치**: `sudo -n` 불가로 apt를 못 쓴다. **sudo 없이** GitHub 릴리스의 정적 바이너리를
  `~/.local/bin/shellcheck`에 설치한다(네트워크 확인됨). 사용자 홈을 건드리므로 이 승인에
  포함한다. 실패하면 사용자에게 `! sudo apt install shellcheck` 실행을 요청하고 대기한다.
- **대상 5파일**: `install/{lib.sh,setup,update}` · `tests/install/run-tests.sh` ·
  `adapters/claude/hooks/session-start.sh`.
- **수정 범위 (스코프 가드)**: `error`·`warning` 레벨만 고친다. `info`·`style`은
  **목록으로 기록만** 하고 고치지 않는다 — 범위가 무한히 번지는 것을 막는다.
- **기존 `disable` 지시자 5개 검증**: 전부 미검증 추측이다. shellcheck를 돌려
  ① 지시자를 떼도 경고가 없으면 **불필요한 지시자이므로 제거**
  ② 경고가 나면 **사유 주석이 실제 경고와 맞는지** 확인하고 어긋나면 정정.
