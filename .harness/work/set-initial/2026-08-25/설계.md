# 설계 — set-initial (프로젝트 기반 문서 세팅 스킬)

## 1. 요구사항 / 의도

입구 게이트(cost-bottleneck-check) **PASS** 뒤, clarify에서 사용자가 범위를 두 번
정정했다. 최종 합의(2026-08-25):

- **R1** 설치 부속 기능이 아니라 **독립 스킬 `set-initial`** 로 뺀다. 셸(`.sh`)은 정말
  기계적인 부분만 맡는다 — 필요 없으면 만들지 않는다.
- **R2** 진입로 두 개: **(a)** 설치 직후 첫 세션에 하네스가 제안, **(b)** 기존 프로젝트에서
  사용자가 아무 때나 호출. 기능은 전부 (b)에 있고 (a)는 방아쇠일 뿐이다.
- **R3** 대화로 만드는 것: `PRD.md`(무엇을·왜) → 스택 결정 → `CLAUDE.md`·`AGENTS.md`(작업 규칙).
- **R4** **기존 문서가 있어도 갈아엎을 수 있다.** 단 조용히는 안 된다 — 무엇이 있는지 보여주고
  고르게 하고, 되돌릴 길을 먼저 만든다.
- **R5** **모든 질문에 "직접 입력" 칸이 있다.** 제시한 선택지가 다 마음에 안 들 수 있다.
- **R6** 질문은 짧고 기본값이 있다. 사용자가 지정한 기본 항목: 커밋 규칙 · 커밋명 규칙 ·
  보일러플레이팅 금지 · 기존 컨벤션 유지 · **파생 기능보다 현재 기능을 제대로** · 문서 규칙.
- **R7** 사용자가 이미 가진 문서를 붙여넣으면 질문을 건너뛰고 **빈 칸만** 되묻는다.
- **R8** 작업이 끝나면 이 기능을 **README 등 가이드에 적어** 사람도 에이전트도 알게 한다.

clarify에서 확정한 기본값 3건 (사용자 "1. ok 2. ok 3. ok"):
① `AGENTS.md` 는 `CLAUDE.md` 를 가리키는 3줄 포인터 ② 스택은 문서에 적기만 하고 초기화는 안 함
③ 스킬 이름은 `set-initial`.

## 2. 작업 대상 및 영향도 (실측)

| 대상 | 현재 상태 | 근거 |
|---|---|---|
| `skills/` | 하네스 스킬 7종. `set-initial` 없음 | `ls skills/` — cost-bottleneck-check·design-doc·interactive-script·obsidian-cli·plan-doc·report-doc·scope-splitter |
| 훅 | 하는 일 2개(플레이북 `cat`, 컨피그 주입/`HRN-W012`). **문서 유무를 보는 코드 0줄** | `adapters/claude/hooks/session-start.sh:23-42` |
| 플레이북 | §0 트리거 표에 이 경로 없음. 비-superpowers 스킬은 `skills/<이름>/SKILL.md` 직독 계약 | `core/playbook.md` §0, §1-4 |
| 컨피그 스키마 | 미지 최상위 키는 **차단**된다 — 실측 `❌ HRN-E004 — 알 수 없는 최상위 키` | `install/validate_config.py:134-140` |
| 하위 키 검증 | `stages` 만 하위 키를 검사한다. `defaults`·`workdocs`·`storage` 는 안 한다 | `install/validate_config.py:147-169` |

**영향 없음 확인:** 이 스킬은 9구간 스킬이 아니다(`stages[].skills` 에 넣지 않는다) —
따라서 컨피그의 스킬 참조 검증 경로를 건드리지 않는다.

## 3. 설계안

### 3-1. 역할 분담 — 로직은 어디에 사는가

```
훅 (bash, ~6줄)        문서 3종의 유무만 사실로 보고. 판단하지 않는다.
   ↓ 주입
플레이북 (규칙 1개)     "부재 + bootstrap.prompt≠off 면 set-initial 을 제안하라"
   ↓ 호출
set-initial 스킬        질문·문서 생성·기존 문서 처리 전부. 본체.
```

**훅은 컨피그를 파싱하지 않는다.** 훅은 어차피 컨피그 원문을 바로 아래에 주입하므로
(`session-start.sh:32-36`), 끄기 판단은 그 원문을 읽는 에이전트가 하면 된다. bash에서
YAML을 파싱하는 취약한 코드를 만들지 않기 위한 선택이다.

훅이 추가로 내보내는 것 (플레이북 뒤, 컨피그 앞):

```
## 프로젝트 기반 문서 상태
PRD.md: 없음 / CLAUDE.md: 없음 / AGENTS.md: 없음
```

"없음"의 정의: **파일이 없거나 공백만 있음.** 내용의 품질은 판정하지 않는다 —
"부실하다"를 기계가 재려 들면 반드시 오검출한다.

### 3-2. 컨피그 키

```yaml
bootstrap:            # 기반 문서 세팅 제안 (set-initial)
  prompt: ask         # ask = 문서가 없으면 세션 시작 때 제안 | off = 제안 안 함
```

`config/schema.yaml` 의 `top_level` 에 `bootstrap: { type: map, required: false }` 한 줄.
하위 키 검증은 `storage`·`defaults` 와 같은 수준(없음)으로 둔다 — 일관성.
사용자가 "나중에"를 고르면 에이전트가 이 값을 `off` 로 바꿔주겠다고 제안한다.

### 3-3. 스킬 흐름 (5단계)

**0단계 · 입구 — 기존 문서 처리 (R4)**

기존 문서가 하나라도 있으면 목록(줄 수·최종 수정)을 보여주고:

```
  1) 전부 새로 만든다 (기존 내용 대체)
  2) 없는 것만 만든다
  3) 파일별로 하나씩 묻는다
  4) 직접 입력 / 다른 방식
  5) 취소
번호 입력 [기본: 3]
```

**되돌릴 길을 먼저 만든다:** 작업트리가 깨끗하면 git이 곧 백업이므로 그대로 진행하고,
더러우면 덮어쓸 파일을 `<파일>.bak` 으로 남긴 뒤 그 사실을 보고한다. 백업 없이 덮어쓰지 않는다.

**1단계 · 무엇을·왜 → PRD 초안** — 질문 3개(무엇 / 누가 / 지금 불편한 것).
**2단계 · 스택 추천 → 선택** — PRD 기준 3안 + 이유. 고른 스택과 이유를 PRD에 적는다.
**초기화(`npm create` 등)는 하지 않는다** (확정 ②).
**3단계 · 작업 규칙 6문항 → CLAUDE 초안** — R6의 항목들. 전부 기본값 있음.
**4단계 · 생성** — 전문 확인 → `PRD.md`·`CLAUDE.md`·`AGENTS.md`(포인터 3줄) 생성 →
`[docs]: 프로젝트 기반 문서 3종` 커밋 제안.

**붙여넣기 경로(R7):** 0단계에서 "가진 문서를 넣겠다"를 고르면 텍스트를 받아 서식으로
정리하고 **빈 칸만** 되묻는다.

### 3-4. 질문 계약 (R5 — 이 스킬의 핵심 규율)

모든 질문은 다음을 **전부** 갖춘다. 하나라도 빠지면 위반이다.

1. 번호 선택지 (최대 4개, 우선순위 순)
2. **`직접 입력`** — 항상 마지막 직전
3. **`건너뛰기`** — 그 항목을 문서에서 빼거나 기본 문구로 둔다
4. 기본번호 표시

예시(3단계 Q1):

```
Q1. 커밋 메시지 형식
  1) [작업유형]: 메시지        예) [feat]: 로그인 추가
  2) Conventional Commits     예) feat: add login
  3) 직접 입력
  4) 건너뛰기 (규칙 안 적음)
번호 입력 [기본: 2]:
```

### 3-5. 산출물 서식

- `PRD.md` — 정체성 / 문제 / 사용자 / 범위 / 비범위 / 기술 스택(+선택 이유)
- `CLAUDE.md` — 3단계 답 + 항상 들어가는 항목(기존 컨벤션 유지, 보일러플레이트 금지,
  현재 기능에 집중). **≤10자 요약 헤더**는 이 저장소 관례라 강제하지 않는다 — 대상 프로젝트의 문서다.
- `AGENTS.md` — `> 이 저장소의 작업 규칙은 CLAUDE.md 를 따른다.` 3줄 포인터 (확정 ①)

### 3-6. 문서화 (R8)

- `README.md` 에 **"초기 세팅"** 절 신설 — 설치 다음 순서로 놓고, 사람용 호출법과
  에이전트용 한 줄(`set-initial 스킬을 읽고 따르라`)을 함께 적는다. 지난 정리에서 잡은
  **가이드 형식**(내부 사정 금지, 짧은 문장)을 유지한다.
- `install/setup` 종료 요약의 "다음 할 일"에 한 줄 추가.
- `PRD.md`(하네스) §5 구조와 §3 v1 범위에 스킬 1종 추가 반영.

### 3-7. 테스트 (CLAUDE.md §4)

- **RED** — 스킬 없이 "초기 세팅 해줘"를 시켰을 때의 베이스라인 실패를
  `tests/skills/set-initial/baseline-results.md` 에 관찰 기록. 예상 실패: 기존 문서를 말없이
  덮어씀 · 직접 입력 칸 없음 · 질문이 장황함 · PRD 없이 CLAUDE.md부터 만듦.
- **GREEN** — 스킬 작성 후 같은 시나리오 재실행 기록.
- **REFACTOR** — 관찰된 허점 봉쇄 + 합리화 반박표.
- 훅 분기는 셸 테스트로: 문서 3종 부재/존재/공백 3케이스가 올바른 상태 줄을 내는지
  `tests/install/run-tests.sh` 에 추가.

## 4. 작업 범위 / 비대상

- **범위:** §3-1 ~ §3-7 전부.
- **비대상:**
  - **프로젝트 초기화·스캐폴딩** (`npm create`, `git init`, 디렉토리 생성) — 확정 ②.
    스택은 문서에 적기만 한다.
  - **기존 문서의 품질 평가·보강 제안** — "부실하다"는 판정을 하지 않는다.
    있으면 있는 것으로 취급하고, 갈지 말지는 사용자가 정한다.
  - **`.sh` 스크립트 신설** — 훅 6줄과 스킬로 충분하다. 백업·감지도 스킬이 셸 한 줄로 한다.
    필요가 실제로 드러나면 그때 별도 작업으로 뺀다.
  - **9구간 흐름 편입** — `stages[].skills` 에 넣지 않는다. 부트스트랩에 설계 승인·판정
    게이트까지 태우면 첫 5분이 무거워진다.
  - **다국어 문서 생성** — 한국어만.
  - **george-orwell 적용 강제** — 게이트에서 (d)로 확정. orwell vendoring(보류 ①)과
    이 작업은 서로 의존하지 않는다.
  - **기존 `AGENTS.md` 규격 지원** — 포인터 방식 하나만 만든다.
