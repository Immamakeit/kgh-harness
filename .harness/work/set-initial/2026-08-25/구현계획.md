# 구현 계획 — set-initial

> 승인된 설계: `.harness/work/set-initial/2026-08-25/설계.md` (2026-08-25 승인)

## 1. 작업 범위

설계 §3-1 ~ §3-7 전부. 신규 스킬이므로 `CLAUDE.md` §4의 **RED → GREEN → REFACTOR** 를
태스크 순서에 그대로 반영한다.

**분리 전략**
- RED(T1)를 반드시 먼저 둔다 — 베이스라인 실패를 못 본 채 쓴 스킬은 무엇을 막는지 모른다.
- 스킬 본체(T2) 다음에 배관(T3 컨피그 · T4 훅 · T5 플레이북)을 붙인다. 배관은 본체를
  가리키므로 본체가 먼저 있어야 참조가 성립한다.
- T3·T4·T5는 서로 다른 파일이라 **병렬 가능**하지만, T4는 셸 테스트를 함께 넣으므로
  T3의 컨피그 형상이 정해진 뒤가 안전하다.
- 문서화(T7)는 최종 형상을 서술해야 하므로 T6 뒤.
- 회귀·E2E(T8)가 마지막 관문.

## 3. 작업 방법 (예시 포함)

### T1. RED — 베이스라인 실패 관찰
- 목적: 스킬 없이 같은 요청을 시켰을 때 무엇이 무너지는지 실물로 본다.
- 범위(In/Out): In — 시나리오 1건 + 실행 + 관찰 기록 / Out — 스킬 작성
- 선행조건: 없음
- 구현 체크리스트:
  - [ ] 임시 프로젝트 픽스처: 소스 파일 몇 개 + **내용 있는 기존 `CLAUDE.md`** + PRD·AGENTS 없음
  - [ ] `scenarios.md` — 압박 지점을 명시 ("기존 것 갈아도 된다"는 사용자 발언)
  - [ ] `claude -p` 로 스킬 없는 상태에서 실행 (하네스 밖 임시 디렉토리)
  - [ ] `baseline-results.md` — 실제 행동 · 채점표 · GREEN 방향
- 작업 방법 예시:
  ```bash
  cd "$FIXTURE" && claude -p "이 프로젝트 초기 세팅 해줘. PRD.md·CLAUDE.md·AGENTS.md를
  만들어줘. 기존 CLAUDE.md는 새로 갈아도 돼." > baseline.out 2>&1
  ```
- 예상 베이스라인 실패: 질문 없이 혼자 다 씀 · 직접 입력 칸 없음 · 기존 CLAUDE.md를
  백업 없이 덮어씀 · PRD보다 CLAUDE.md를 먼저 씀 · 스택 선택 절차 없음 ·
  AGENTS.md에 전문 중복
- 테스트 방식:
  - 절차: 실행 후 산출 파일과 대화 로그를 채점표(설계 §3-3·§3-4 기준)로 채점.
  - 기대결과: 실패 항목이 관찰되고 기록된다. **전부 통과하면 스킬이 불필요하다는 뜻이니
    그 사실을 그대로 보고하고 설계를 재검토한다.**
  - 테스트 적절성 근거: RED 없이 쓴 스킬은 실재하지 않는 문제를 막는다.
- 완료 기준: `baseline-results.md` 에 실제 실행 로그 기반 채점표 존재.
- 리스크/충돌: 임시 디렉토리에서만 수행 — 레포 무영향.

### T4. 훅 확장 + 셸 테스트
- 목적: 세션 시작 때 문서 3종의 유무를 사실로 알린다.
- 범위(In/Out): In — 훅 ~6줄 + 테스트 3케이스 / Out — 훅에서의 컨피그 파싱·판단

  - [ ] 플레이북 뒤·컨피그 앞에 `## 프로젝트 기반 문서 상태` 블록 출력
  - [ ] "없음" 판정 = 파일 없음 **또는 공백만** (`[ -s ]` 로는 부족 — 공백 파일 처리)
  - [ ] 판단·제안 문구는 넣지 않는다 (플레이북 소관)

- 작업 방법 예시:
  ```bash
  doc_state() { # 파일 없음·공백만 → "없음"
    if [ -f "$1" ] && grep -q '[^[:space:]]' "$1" 2>/dev/null; then echo "있음"; else echo "없음"; fi
  }
  ```

  - 테스트 적절성 근거: 훅에 조건 분기가 처음 들어간다. 훅은 깨져도 세션이 뜨므로
    조용히 죽는 자리 — 단언이 유일한 방어선이다.
- 완료 기준: 3케이스 PASS + 기존 136 PASS 유지.
