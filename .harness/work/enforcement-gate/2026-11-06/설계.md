# 설계 — enforcement-gate (선언을 계약으로)

## 1. 요구사항 / 의도

외부 평가(2026-11-06, 이 레포 전체를 클론·설치·회귀 실행하며 수행)의 결론을
사용자가 그대로 채택했다. 사용자 발언(원문):

> "오케이 적용한 다음에 푸시해, 그리고 개인도구로 선언해"

지목된 다음 한 수(순서 그대로):

| # | 항목 | 평가가 지적한 결함 |
|---|---|---|
| **A** | PreToolUse 승인 게이트 훅 | 플레이북이 "⑤ 승인 없이 구현 금지"를 **어떤 경우에도 생략 불가**로 선언하는데 강제 수단이 0개다. 훅이 `SessionStart` 하나뿐이라 게이트가 전부 모델의 선의에 의존한다 |
| **B** | 주입 다이어트(라우터만) | 훅이 매 세션 **16,450자**(실측: 플레이북 11,899 + 컨피그 원문 4,371)를 주입한다. "오타 고쳐줘" 세션도 전액 지불한다. 게다가 플레이북 §1이 "흐름 시작마다 컨피그를 다시 읽는다, 캐시 금지"라고 하므로 컨피그 원문 주입은 자기모순이다 |
| **C** | `.claude/skills/` 노출 | 스킬 10종의 `description` 을 superpowers 규율대로 "Use when…" 트리거만으로 공들여 썼는데 **그 description을 읽는 주체가 없다.** 자동 트리거도 `/슬래시` 호출도 안 된다 |
| **D** | CI | 회귀 307케이스가 전부 로컬 수동 실행 의존. 공개 레포인데 push마다 돌지 않는다 |
| **E** | 개인 도구 선언 | WSL 전용 vault 탐지 · Obsidian 커플링 · 한국어 전용 문서인데 MIT + 영어 스킬 description이 외부 사용 의도로 읽힌다. 둘 중 하나로 못박으라는 지적 |

**A가 이 작업의 본체다.** 사용자 판단 원문: "①만 해도 이 하네스의 성격이 '권고'에서
'계약'으로 바뀐다."

## 2. 작업 대상 및 영향도 (실측)

| 대상 | 현재 상태 | 근거 |
|---|---|---|
| `adapters/claude/hooks/` | `session-start.sh` **1개뿐** | 실측 `ls` |
| 세션 주입량 | 16,450자 / 세션 | 실측 `hook | wc -m` |
| `.claude/skills/` 노출 | 없음. **PRD §5가 "등록하지 않는다"로 확정 박제** | PRD §5 "스킬 구동 방식 (확정)" |
| CI | `.github/` 없음 | 실측 `ls -a` |
| 기존 작업 문서 | 13건, **전부 `.approved` 마커 없음** | `.harness/work/*/*/` |
| 에러 코드 최대 번호 | `HRN-E015` · `HRN-W020` | PRD §8 표 |

### 2-1. PRD 결정 번복 (C의 전제)

PRD §5는 `.claude/skills/` 등록을 **"확정"으로 박제**했다. CLAUDE.md §1은 "PRD와
어긋나는 구현 금지"다. 따라서 C는 **PRD 개정을 먼저 거쳐야 하고**, 몰래 어기지
않는다. 번복 사유를 PRD에 그대로 남긴다 — 당시 결정은 "플레이북이 경로로 직독하니
등록은 중복"이었으나, 그 결정의 부작용(스킬 description이 사문화, 사용자가 스킬을
직접 호출할 길이 없음)이 실측으로 드러났다. **직독 방식은 그대로 유지하고 노출을
추가한다** — 대체가 아니라 병행이다.

### 2-2. 부트스트랩 함정 (A의 전제, 실측)

승인 마커(`.approved`) 부재를 "승인 전"으로 읽으면, **기존 작업 13건이 전부 승인 전으로
판정되어 설치 직후 모든 편집이 차단된다.** 이 함정을 설계 단계에서 못 박는다 —
`install/setup`·`install/update` 가 기존 작업 디렉터리에 마커를 **백필**하고, 그 사실과
"진행 중인 작업이 있으면 해당 마커를 지우라"는 안내를 요약에 낸다.

## 3. 설계안

### 3-1. A — 승인 게이트 (`PreToolUse`)

**무장 신호를 파일에서 유도한다(상태 파일 없음).** 모델이 "게이트를 켜겠다"고
선언해야 켜지는 구조면 선언을 빼먹는 순간 집행이 0이 된다. 그래서:

> `<workdocs.path>/<작업명>/<날짜>/` 안에 **설계 문서가 있고 `.approved` 가 없으면**
> 그 작업은 "승인 대기"이고, 게이트는 **무장**된다.

⑤ 설계는 **문서를 생산하는 구간**이므로(플레이북 §5), 흐름이 ⑤를 지나면 무장은
모델의 협조 없이 자동으로 일어난다. 이것이 이 설계의 핵심이다.

**차단 대상 (무장 시):**

| 도구 | 판정 |
|---|---|
| `Edit` · `Write` · `MultiEdit` · `NotebookEdit` | 대상 경로가 `<workdocs.path>` **밖**이면 차단. 작업 문서 자체는 항상 쓸 수 있다(⑤⑥이 문서를 만드는 구간이므로) |
| `Bash` | `git commit` · `git push` · `sed -i` · `perl -i` 만 차단 |
| 그 외 전부 | 통과. 읽기·탐색·테스트 실행은 막지 않는다 |

**셸 경유 임의 수정(`python - <<EOF`, `cat >` 등)까지 막지는 못한다.** 이것은
표류(drift)를 잡는 장치지 적대적 우회를 막는 장치가 아니다 — 에이전트에게 셸이 있는
한 완전 봉쇄는 불가능하다. 과장하지 않고 README·PRD에 그대로 적는다.

**마커 생성 경로:** `install/approve <작업명>`. 마커에 **승인 시각과 승인 경로(tty /
비대화형 플래그)를 기록**해 git diff에 남는다. 비대화형에서는 `--by-user` 를 명시해야
하고 그 사실이 마커에 적힌다 — 모델이 마커를 만들 수는 있지만 **조용히** 만들 수는 없다.

**모드 (`gate.enforce`):** `block`(기본) · `warn`(통과시키되 경고) · `off`.
§1-5 원칙 적용 방향은 **"멈춘다"쪽** — `off`·`warn` 이 아닌 모든 값(오타·부재 포함)은
`block`. 승인 없이 구현이 나가는 쪽이 한 번 더 멈추는 쪽보다 훨씬 놀랍다.

**성능·고장 방향:** 훅은 매 도구 호출마다 돈다. (a) 무장 여부를 **순수 bash로 먼저**
판정하고 미무장이면 즉시 통과한다(JSON 파싱 없음 — 평시 비용 거의 0). (b) 무장
상태에서만 python3로 JSON을 정확히 파싱한다. (c) 어떤 내부 실패도 **통과(fail-open)**
시키고 `HRN-W021` 을 낸다 — 게이트 고장이 작업을 세우면 안 된다.

**이 훅은 `install/lib.sh` 를 source 하지 않는다.** 설치 스크립트가 깨져도 게이트는
살아 있어야 하고, 매 도구 호출의 비용을 최소로 두어야 한다. 중복되는 YAML 스칼라
읽기는 훅 안에 최소 구현으로 두고, 회귀가 훅 동작을 직접 고정한다.

### 3-2. B — 주입 다이어트

`core/router.md` 신설(목표 ≤50줄): 역할 선언 · 트리거 표 · **"흐름을 시작하면
`core/playbook.md` 전문을 먼저 Read 하라"** · 게이트 요약 · 컨피그 **경로**(원문 아님).

`injection.mode`: `router`(기본) · `full`(옛 동작). `full` 이 아닌 값은 전부 `router`.

**라우터를 모델이 무시하면?** A의 게이트가 파일 기반이라 **그래도 하드 게이트는
살아 있다.** B가 A 뒤에 오는 순서인 이유다 — A 없이 B만 하면 집행력이 더 얇아진다.

### 3-3. C — 스킬 노출

`skills.expose_to_claude`: `true`(기본) · `false`.
`<대상>/.claude/skills/<이름>` → `../../.harness/skills/<이름>` **상대 심링크**.

- 같은 이름이 이미 있고 우리 심링크가 아니면 → **`HRN-W022` 로 보고하고 건너뛴다.**
  조용히 가리지 않는다(`HRN-E015` 와 같은 철학, 다만 설치는 막지 않으므로 W).
- 심링크 생성 실패(파일시스템 제약) → 복사로 열화하고 그 사실을 보고.
- `.gitignore` 에는 **우리가 만든 항목만 줄 단위로** 추가한다. `/.claude/skills/` 를
  통째로 무시하면 그 프로젝트 자신의 스킬까지 가려진다.

### 3-4. D — CI

`.github/workflows/ci.yml`: 회귀 스위트 + shellcheck + `py_compile` + 검증기 self-check.
`.github/` 는 개발용이므로 `.harnessignore` 에 등재한다.

### 3-5. E — 개인 도구 선언

README 머리와 PRD §1에 전제를 명시한다: **개인 도구**, WSL+Obsidian+한국어 전제,
지원·호환성 약속 없음, 그래도 MIT 유지(쓰고 싶으면 포크). "범용 패키지"로 읽히는
문구를 거둔다.
