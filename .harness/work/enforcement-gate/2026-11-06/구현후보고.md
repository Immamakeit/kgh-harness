### 구현 중 실측으로 잡은 결함 4건

1. **`python3 - <<'PY'` 가 훅 JSON 을 먹었다** — 스크립트 본문이 stdin 을 차지해 모든
   판정이 `UNKNOWN` 으로 떨어졌다(fail-open 이 작동해 사고는 없었다). 판정부를
   `gate_decide.py` 로 분리.
2. **`printf` 포맷이 `-` 로 시작해 옵션으로 먹혔다** — 라우터의 경로 블록이 깨졌다.
   `printf --` 로 끊었다.
3. **`.gitignore` 가 남의 스킬을 가렸다** — 노출 목록을 "하네스 스킬 전체"로 적어,
   충돌로 **건너뛴** 이름(그 프로젝트 자신의 `design-doc`)까지 무시 목록에 들어갔다.
   `exposed_skill_names()` 로 실제로 만든 링크만 세도록 고쳤다.
4. **승인 마커에 머신 절대경로가 박혔다** — 스크래치패드 경로가 이력에 들어갔다.
   프로젝트 기준 상대경로로 바꿨다.

### 설계에서 바꾼 결정 1건

`git commit`·`git push` 를 차단 대상에서 **뺐다.** 승인 전 설계 문서를 커밋하는 것이
이 하네스의 정상 흐름이고(git 이력에 "설계 — 승인대기" 커밋이 실재한다), 커밋은 소스를
바꾸지 못한다. 소스를 바꾸는 경로를 막으면 커밋할 변경 자체가 생기지 않는다.

## 4. 직접 확인 시나리오

1. 새 프로젝트에 설치한다.
   ```bash
   ~/.kgh-harness/install/setup /tmp/demo && cd /tmp/demo
   ```
   - **기대 결과:** 요약에 `훅: 연결됨 — SessionStart + PreToolUse 게이트`,
     `스킬 노출: 생성 10`, `승인 게이트: gate.enforce=block` 이 보인다.
2. 승인 없이 구현을 시도한다 (설계 문서만 만들어 게이트를 무장시킨다).
   ```bash
   mkdir -p .harness/work/demo/$(date +%F) && echo '# 설계' > .harness/work/demo/$(date +%F)/설계.md
   printf '%s' '{"tool_name":"Edit","tool_input":{"file_path":"src/a.js"}}' \
     | CLAUDE_PROJECT_DIR=$PWD bash .harness/adapters/claude/hooks/pre-tool-use.sh; echo "rc=$?"
   ```
   - **기대 결과:** `rc=2` 와 `❌ HRN-E016` + 복구 경로 2개.
3. 승인하고 다시 시도한다.
   ```bash
   .harness/install/approve demo        # [y/N] 에 y
   printf '%s' '{"tool_name":"Edit","tool_input":{"file_path":"src/a.js"}}' \
     | CLAUDE_PROJECT_DIR=$PWD bash .harness/adapters/claude/hooks/pre-tool-use.sh; echo "rc=$?"
   ```
   - **기대 결과:** 마커에 `승인경로=tty` 가 적히고 `rc=0`.
4. 주입량을 본다.
   ```bash
   CLAUDE_PROJECT_DIR=$PWD bash .harness/adapters/claude/hooks/session-start.sh | wc -m
   ```
   - **기대 결과:** 2천자 대. `injection.mode: full` 로 바꾸면 1만 7천자 대.
5. 스킬 호출이 되는지 본다 — Claude Code 세션에서 `/design-doc` 가 목록에 뜬다.
   - **기대 결과:** 심링크로 노출된 스킬 10종이 디스커버리에 걸린다.

### 판정 전 알아야 할 것 (과장 없이)

- 게이트는 **셸 경유 임의 쓰기를 막지 못한다.** 표류를 잡는 장치다.
- `install/approve` 는 에이전트도 실행할 수 있다. 막을 방법은 없고, **조용히는 못 하게**
  해뒀다(승인 시각·경로가 마커에 남아 git diff 에 드러난다).
- 라우터 주입은 모델이 플레이북을 **읽어야** 흐름이 완전해진다. 안 읽으면 흐름 품질이
  떨어지지만, 파일 기반 게이트 덕에 **하드 게이트는 그래도 살아 있다.**
- **vault 를 대조하지 못했다.** CLAUDE.md §1은 "정의는 vault 가 이긴다"인데 이 작업을
  수행한 환경에 `/mnt/c/gh-obsidian-vaults/LLM-Wiki/harness/` 가 없었다. 레포 안의
  규약(PRD·CLAUDE.md)만 기준으로 진행했다 — vault 의 `workflow.md`·`script-standards.md`
  와 어긋나는 부분이 있으면 그쪽이 이긴다.
