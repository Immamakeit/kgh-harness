# 구현 계획 — config/ 스키마 신설 + 검증기

> **에이전트 실행자에게:** 태스크 단위로 진행한다. 각 태스크는 독립 구현 + 독립 검증이
> 가능하며 자체 커밋으로 끝난다. RED(실패 관찰) 없이 구현 코드를 쓰지 않는다.

**목표:** `harness.config.yaml`의 구조 오타·값 오류·참조 오타를 지침이 아니라 코드로 잡는다.

**전제(전 태스크 공통, 설계에서 확정):**
- 신규 에러코드는 `HRN-W015` **하나뿐**. 나머지는 PRD §8의 기존 코드만 쓴다.
- 검증 전제(`python3` **또는** `PyYAML`) 미충족 시 `HRN-W015` 경고 + **종료코드 2**,
  흐름을 막지 않는다. 파서는 PyYAML **한 벌만** 쓴다 (내장 파서 폴백 없음 — 2026-08-20 확정).
- 모든 에러는 CLAUDE.md §5대로 **복구 경로 2개**를 함께 낸다.
- 셸 스크립트는 `set -euo pipefail`, 기존 `install/lib.sh` 헬퍼(`say`/`ok`/`warn`/
  `hrn_err`/`hrn_warn`)를 쓴다.

## 1. 작업 범위

승인된 설계(설계.md, 2026-08-20 승인)의 범위 그대로. 범위 밖 요구 없음 — **범위 게이트
미발동.**

구현 중 확정한 사항 1건: 설계 §3-6이 열화 조건을 "python3 부재"로만 적었으나, `PyYAML`
부재도 같은 등급(`HRN-W015`, 비차단)으로 처리한다. 같은 슬롯의 구체화이므로 설계 변경이
아니다.

# ---- 컨피그 검증기 (config-schema) -----------------------------------------
test_validate_config() {
  group "컨피그 검증기 — install/validate-config"

  local vc="${SOURCE_DIR}/install/validate-config"
  local dir="${WORK}/vc"; mkdir -p "$dir"

    return

  cp "${SOURCE_DIR}/harness.config.yaml" "${dir}/harness.config.yaml"
  if "$vc" "${dir}/harness.config.yaml" >"${dir}/ok.log" 2>&1; then
    pass_case "정상 컨피그 통과 (exit 0)"
  else
    fail_case "정상 컨피그 통과" "exit=$? — $(tail -2 "${dir}/ok.log")"

    { assert_contains "$(cat "${dir}/e004a.log")" "HRN-E004" "알 수 없는 구간 → HRN-E004"
      assert_contains "$(cat "${dir}/e004a.log")" "desing" "오타 구간명을 그대로 지목"; }

  # (3) 알 수 없는 키 → HRN-E004 차단

  "$vc" "${dir}/typo-key.yaml" >"${dir}/e004b.log" 2>&1 && \
    fail_case "알 수 없는 키 차단" "exit 0으로 통과함" || \
    assert_contains "$(cat "${dir}/e004b.log")" "HRN-E004" "알 수 없는 키 → HRN-E004"

### T3 — 검증기 구현 (`install/validate-config`)

**목적:** T1의 7건을 GREEN으로 만든다.

**인터페이스 (T4·T5가 의존):**
- 호출: `install/validate-config [컨피그경로]` (생략 시 `./harness.config.yaml`)
- 종료코드: `0` 통과(경고 가능) · `1` 차단 오류 · `2` 검증 불가(비차단)

- [ ] **3-1. 파일 생성**

```bash
#!/usr/bin/env bash
# install/validate-config [컨피그경로] — harness.config.yaml 3단계 검증.
# ① 구조(HRN-E004) ② 값/어댑터 위임(HRN-E001·E002) ③ 참조 실존(HRN-E005·W014)
# 검증 전제 미충족 시 HRN-W015 + exit 2 (비차단).
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
SOURCE_DIR="$(cd "${SCRIPT_DIR}/.." && pwd)"
# shellcheck source=./lib.sh
source "${SCRIPT_DIR}/lib.sh"

CONFIG="${1:-$(pwd)/harness.config.yaml}"
SCHEMA="${SOURCE_DIR}/config/schema.yaml"
ADAPTER_DIR="${SOURCE_DIR}/adapters"

if [ ! -f "$CONFIG" ]; then
  hrn_warn "W012" "컨피그 미발견: ${CONFIG}" \
    "install/setup 으로 harness.config.yaml 을 생성하세요" \
    "검증 없이 진행 — 플레이북 기본값이 적용됩니다"
  exit 2
fi

if [ ! -f "$SCHEMA" ]; then
  hrn_err "E005" "스키마 미발견: ${SCHEMA}" \
    "install/update 로 하네스 최신본을 받으세요" \
    "소스 레포에서 config/schema.yaml 을 복원하세요"
  exit 1
fi

if ! command -v python3 >/dev/null 2>&1; then
  hrn_warn "W015" "python3 미발견으로 컨피그 검증을 건너뜁니다" \
    "python3 설치 후 install/validate-config 를 재실행하세요" \
    "검증 없이 진행 — 오타는 해당 구간 도달 시 드러납니다"
  exit 2
fi

if ! python3 -c 'import yaml' >/dev/null 2>&1; then
  hrn_warn "W015" "PyYAML 미발견으로 컨피그 검증을 건너뜁니다" \
    "pip install pyyaml 후 install/validate-config 를 재실행하세요" \
    "검증 없이 진행 — 오타는 해당 구간 도달 시 드러납니다"
  exit 2
fi

say "=== 컨피그 검증 ==="
say "대상  : ${CONFIG}"
say "스키마: ${SCHEMA}"
echo

set +e
python3 "${SCRIPT_DIR}/validate_config.py" "$CONFIG" "$SCHEMA" "$ADAPTER_DIR" "$SOURCE_DIR"
rc=$?
set -e
exit "$rc"
```

- [ ] **3-2. 파이썬 본체 생성** — `install/validate_config.py`

셸 heredoc 대신 파일로 분리한다. heredoc 안의 파이썬은 shellcheck·문법 검사를 못 받는다.

```python
#!/usr/bin/env python3
"""harness.config.yaml 3단계 검증. 종료코드 0=통과 1=차단."""
import sys, os, yaml

C_ERR, C_WARN, C_OK, C_RST = "\033[31m", "\033[33m", "\033[32m", "\033[0m"
errors, warns, checked = [], [], 0


def err(code, msg, fix_a, fix_b):
    errors.append(f"{C_ERR}❌ HRN-{code} — {msg}{C_RST}\n"
                  f"   조치: (a) {fix_a}\n         (b) {fix_b}")


def warn(code, msg, fix_a, fix_b):
    warns.append(f"{C_WARN}⚠ HRN-{code} — {msg}{C_RST}\n"
                 f"   조치: (a) {fix_a}\n         (b) {fix_b}")


def load(path):
    with open(path, encoding="utf-8") as f:
        return yaml.safe_load(f) or {}


def check_type(val, spec, where):
    """타입·허용값 검사. 위반 시 사유 문자열, 통과 시 None."""
    t = spec.get("type")
    if val is None and spec.get("nullable"):
        return None
    if t == "enum":
        allowed = [str(v) for v in spec.get("values", [])]
        if str(val) not in allowed:
            return f"{where}: '{val}' 은 허용값이 아님 (허용: {', '.join(allowed)})"
    elif t == "bool":
        if not isinstance(val, bool):
            return f"{where}: '{val}' 은 참/거짓이 아님"
    elif t == "list":
        if not isinstance(val, list):
            return f"{where}: 목록이 아님"
    elif t == "map":
        if not isinstance(val, dict):
            return f"{where}: 매핑이 아님"
    return None


def main(config_path, schema_path, adapter_dir, source_dir):
    global checked
    cfg, sch = load(config_path), load(schema_path)

    # ── ① 구조 ────────────────────────────────────────────────────────────
    top = sch.get("top_level", {})
    for key in cfg:
        checked += 1
        if key not in top:
            err("E004", f"알 수 없는 최상위 키 '{key}'",
                "harness.config.yaml 에서 해당 키를 제거하거나 철자를 고치세요",
                f"의도한 키라면 {schema_path} 의 top_level 에 추가하세요")
    for key, spec in top.items():
        if spec.get("required") and key not in cfg:
            err("E004", f"필수 키 '{key}' 누락",
                f"harness.config.yaml 에 {key} 를 추가하세요",
                f"필수가 아니라면 {schema_path} 에서 required 를 내리세요")

    stages_sch = sch.get("stages", {})
    known = stages_sch.get("known", [])
    stage_keys = stages_sch.get("keys", {})
    for name, body in (cfg.get("stages") or {}).items():
        checked += 1
        if name not in known:
            err("E004", f"알 수 없는 구간 '{name}'",
                "harness.config.yaml 의 구간명 철자를 고치세요 "
                f"(알려진 구간: {', '.join(known)})",
                f"새 구간이라면 {schema_path} 의 stages.known 에 추가하세요")
            continue
        for k, v in (body or {}).items():
            checked += 1
            if k not in stage_keys:
                err("E004", f"알 수 없는 키 'stages.{name}.{k}'",
                    "해당 키를 제거하거나 철자를 고치세요 "
                    f"(허용: {', '.join(stage_keys)})",
                    f"의도한 키라면 {schema_path} 의 stages.keys 에 추가하세요")
                continue
            reason = check_type(v, stage_keys[k], f"stages.{name}.{k}")
            if reason:
                err("E004", reason,
                    "값을 허용 범위로 고치세요",
                    f"{schema_path} 의 허용값을 넓히세요")

    # ── ② 값 (어댑터 위임) ────────────────────────────────────────────────
    active = cfg.get("active_harness")
    caps_path = os.path.join(adapter_dir, str(active), "capabilities.yaml")
    caps = None
    if not os.path.isfile(caps_path):
        err("E010", f"active_harness '{active}' 의 어댑터 능력 파일 미발견 ({caps_path})",
            "active_harness 를 claude 로 변경하세요",
            f"해당 어댑터를 구현하고 {caps_path} 를 추가하세요")
    else:
        caps = load(caps_path)
        if not caps.get("implemented", False):
            err("E010", f"active_harness '{active}' 는 아직 구현되지 않은 어댑터",
                "active_harness 를 claude 로 변경하세요",
                "해당 어댑터를 구현한 뒤 capabilities.yaml 의 implemented 를 true 로 바꾸세요")

    if caps:
        models = caps.get("models", [])
        eff = caps.get("effort", {}) or {}
        eff_values = eff.get("values", [])

        def check_val(val, kind, where):
            global checked
            checked += 1
            if kind == "model" and val not in models:
                err("E001", f"{where}: 알 수 없는 model '{val}' (지원: {', '.join(models)})",
                    "harness.config.yaml 의 model 값을 지원 목록에서 고르세요",
                    f"모델이 새로 나왔다면 {caps_path} 의 models 를 갱신하세요")
            if kind == "effort" and val not in eff_values:
                err("E002", f"{where}: 알 수 없는 effort '{val}' (지원: {', '.join(eff_values)})",
                    "harness.config.yaml 의 effort 값을 지원 목록에서 고르세요",
                    f"{caps_path} 의 effort.values 를 갱신하세요")

        d = cfg.get("defaults") or {}
        if "model" in d:
            check_val(d["model"], "model", "defaults.model")
        if "effort" in d:
            check_val(d["effort"], "effort", "defaults.effort")
        for name, body in (cfg.get("stages") or {}).items():
            for k in ("model", "effort"):
                if body and k in body:
                    check_val(body[k], k, f"stages.{name}.{k}")

        if not eff.get("dispatch_supported", False):
            used = [f"stages.{n}" for n, b in (cfg.get("stages") or {}).items()
                    if b and "effort" in b]
            if "effort" in (cfg.get("defaults") or {}):
                used.insert(0, "defaults")
            if used:
                print(f"{C_WARN}⚠ effort 는 {active} 어댑터의 Agent 디스패치에서 "
                      f"지원되지 않아 무시됩니다 — 지정된 곳: {', '.join(used)}{C_RST}")

    # ── ③ 참조 실존 ───────────────────────────────────────────────────────
    for name, body in (cfg.get("stages") or {}).items():
        for s in ((body or {}).get("skills") or []):
            checked += 1
            if str(s).startswith("superpowers:"):
                sp = str(s).split(":", 1)[1]
                warn("W014", f"stages.{name}: superpowers 스킬 '{sp}' 는 "
                             "전역 설치 전제 — 미설치 시 해당 구간만 스킬 없이 진행",
                     "/plugin install superpowers 로 설치하세요",
                     f"쓰지 않는다면 stages.{name}.skills 에서 제거하세요")
                continue
            path = os.path.join(source_dir, "skills", str(s), "SKILL.md")
            if not os.path.isfile(path):
                err("E005", f"stages.{name}: 스킬 '{s}' 의 파일 미발견 ({path})",
                    f"stages.{name}.skills 의 스킬명 철자를 고치세요",
                    f"의도한 스킬이라면 skills/{s}/SKILL.md 를 만드세요")

    # ── 요약 (결과 비은닉) ────────────────────────────────────────────────
    for w in warns:
        print(w)
    for e in errors:
        print(e)
    print()
    print("=== 검증 요약 ===")
    print(f"검사 항목 : {checked}")
    print(f"경고      : {len(warns)}")
    print(f"오류      : {len(errors)}")
    if errors:
        print(f"{C_ERR}검증 실패 — 위 오류를 해결한 뒤 재실행하세요.{C_RST}")
        return 1
    print(f"{C_OK}검증 통과{C_RST}")
    return 0


if __name__ == "__main__":
    sys.exit(main(*sys.argv[1:5]))
```

## 4. 작업 비대상

승인된 설계의 비대상 **전 항목을 그대로 승계**한다. 이번 계획에서 편입된 항목은 없다.

- **`adapters/codex/`·`adapters/ollama/`의 capabilities.yaml을 만들지 않는다.** 스텁조차
  두지 않는다. 파일이 없으면 기존 `HRN-E010`으로 처리된다(T3의 ② 단계에 반영됨).
- **`install/lib.sh`의 기존 YAML 헬퍼를 리팩터링하지 않는다.** `yaml_top_keys`(L183)·
  `read_active_harness`(L193)·`superpowers_skills_in_config`(L225)는 검증기와 기능이
  일부 겹치지만 그대로 둔다. **중복이 남는 것을 알면서 두는 것**이며, 건드리면
  `setup`·`update`의 검증된 동작까지 흔들린다. 후속 후보로 기록한다.
- **흐름 시작 시 자동 실행을 훅으로 강제하지 않는다.** 플레이북이 지시할 뿐이며
  `session-start.sh`는 손대지 않는다 (PRD §4 "얇은 훅" 결정 유지).
- **`harness.config.yaml`의 구조를 바꾸지 않는다.** `defaults:` 블록 유지.
- **PRD §7.1(저장 규칙) 문안은 건드리지 않는다.** §7의 예시 코드블록만 교체한다.
- **모델 목록의 실시간 검증(API 조회)을 하지 않는다.** 정적 목록을 손으로 관리한다.
- **내장 YAML 파서를 만들지 않는다.** PyYAML 부재는 `HRN-W015`로 건너뛴다 (2026-08-20 확정).
