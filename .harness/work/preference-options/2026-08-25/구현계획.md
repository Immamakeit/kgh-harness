# 구현 계획 — preference-options

> 설계: `.harness/work/preference-options/2026-08-25/설계.md` (2026-08-25, **승인대기** —
> 오픈 이슈 2건 미해소. §6 오픈 이슈 참조. 승인·이슈 해소 전에는 구현 착수 금지)

## 1. 작업 범위

설계 §3-1 ~ §3-7 전부. 신규 스킬(`preference-options`)이 포함되므로 `CLAUDE.md` §4의
**RED → GREEN → REFACTOR**를 태스크 순서에 그대로 반영한다.

**분리 전략 (두 국면, 문서는 하나로 유지)**

- **국면 A — 선호 프로필 코어** (T1~T3): `preference-options` 스킬 자체. `as-recommended`
  없이도 독립적으로 값이 있다 — 사용자가 "내 선호 프로필 보여줘"라고 명시 호출하거나,
  다른 스킬이 옵션 순서·기본번호 개인화만 참조하는 용도로 그 자체로 merge 가능하다.
  컨피그를 건드리지 않는다.
- **국면 B — `as-recommended` 모드** (T4~T7): 국면 A가 만든 프로필 스키마·추천 계산 위에
  컨피그 토글·플레이북 규칙·set-initial 통합을 얹는다. 국면 A 없이는 추천 근거 자체가
  없으므로 반드시 뒤에 온다(설계 §1 "두 기능은 짝" 판단을 그대로 따름).
- T8(전체 REFACTOR)·T9(회귀)은 두 국면을 합쳐서 검증한다.
- scope-splitter 원칙(독립 구현 + 독립 검증)에 따라 국면 A는 국면 B 착수 전에 그 자체로
  커밋·검증이 끝난 상태여야 한다.

## 3. 작업 방법 (예시 포함)

### T1. RED — 베이스라인 실패 관찰

- 범위(In/Out): In — 시나리오 1건 + 실행 + 관찰 기록 / Out — 스킬·컨피그 작성
- 선행조건/의존성: 없음
- 구현 체크리스트:
  - [ ] 임시 프로젝트 픽스처: `set-initial`을 이미 3회 정도 돌려 "커밋 형식은 항상
        Conventional Commits, 브랜치는 항상 기능 브랜치→PR"을 매번 답한 것으로 가정한
        대화 로그(사람이 준비한 시나리오 텍스트)
  - [ ] `scenarios.md` — 압박 지점 명시("매번 같은 답을 반복해서 치는 게 피곤하다"는
        사용자 발언, `preferences.as_recommended: true`를 컨피그에 넣어도 아무 효과가
        없어야 함을 관찰 대상으로 명시)
  - [ ] `claude -p`로 스킬·컨피그 키 없는 상태에서 set-initial 질문 흐름을 재현 실행
        (하네스 밖 임시 디렉토리, set-initial 스킬 자체는 있는 채로 — 이 흐름이
        관찰하려는 결핍은 set-initial의 결함이 아니라 "개인화·자동채택 계층의 부재"다)
  - [ ] `baseline-results.md` — 실제 행동·채점표·GREEN 방향
- 작업 방법 예시:
  ```bash
  cd "$FIXTURE" && claude -p "이 프로젝트 초기 세팅 해줘. 참고로 나는 지난 세 번 다
  Conventional Commits랑 기능 브랜치를 골랐어. harness.config.yaml에
  preferences.as_recommended: true 도 넣어놨으니 그거 참고해서 빨리 진행해줘." \
    > baseline.out 2>&1
  ```
- 예상 베이스라인 실패: 과거 선택을 참고할 데이터 구조 자체가 없음(스킬이 참고할
  파일이 없음) · `preferences.as_recommended` 키가 스키마에 없어 컨피그 검증이
  `HRN-E004`로 차단되거나(스키마 반영 전이면 차단), 반영돼 있어도 아무 동작이 없음 ·
  Q1~Q6이 매번 표 기본값 그대로(개인화 0) · "빨리 진행"이 반영되지 않고 한 문항씩
  대화형 대기.
- 테스트 방식:
  - 절차: 실행 후 대화 로그를 설계 §3-1~§3-4 기준 채점표로 채점.
  - 기대결과: 위 실패 항목이 관찰되고 기록된다. **전부 통과하면 이 작업이 불필요하다는
    뜻이므로 그대로 보고하고 설계를 재검토한다.**
  - 테스트 적절성 근거: RED 없이 만든 스킬은 실재하지 않는 문제를 막는다(`CLAUDE.md` §4).
- 완료 기준: `baseline-results.md`에 실행 로그 기반 채점표 존재.
- 리스크/충돌: 임시 디렉토리에서만 수행 — 레포 무영향.

### T4. 컨피그 키 `preferences.as_recommended`
- 목적: "추천대로 자동 진행" 여부를 컨피그가 소유하게 한다.
- 범위(In/Out): In — 스키마 1줄 + 템플릿·루트 컨피그 블록 + 해석 규칙 문서화 / Out — 하위 키 값 검증 로직
- 선행조건/의존성: T3 (가리킬 스킬이 존재해야 컨피그 주석이 참조를 가진다)
- 구현 체크리스트:
  - [ ] `config/schema.yaml` `top_level`에 `preferences: { type: map, required: false }`
  - [ ] 템플릿·루트 컨피그에 아래 블록 + 주석
  - [ ] `install/validate-config`로 두 컨피그 모두 통과 확인 (키를 빼도 통과해야 함)
- 작업 방법 예시:
  ```yaml
  preferences:                      # 선호 기반 추천 (preference-options 스킬)
    as_recommended: false           # true = 번호 선택형 질문을 추천대로 자동 채택
                                     # 주의: 이 값은 검증기가 검사하지 않는다 — 오타·부재는
                                     # 전부 false로 취급된다(bootstrap.prompt와 반대 방향의
                                     # 안전 규칙 — 플레이북 §6 참조)
  ```
- 테스트 방식:
  - 절차: `./install/validate-config`를 루트·템플릿 각각 실행.
  - 기대결과: 둘 다 `검증 통과`, exit 0. 키를 빼도 통과.
  - 테스트 적절성 근거: 미지 최상위 키는 `HRN-E004`로 차단되므로(실측, `install/validate_config.py:134-140`)
    스키마 누락이 곧 전체 흐름 정지다.
- 완료 기준: 위 두 조건.
- 리스크/충돌: 스키마·컨피그 파일 단독 — T5·T6과 무충돌.

- 구현 체크리스트:

        순서·기본번호·추천 표시를 개인화한다" 규칙 추가
  - [ ] `as_recommended: true`일 때의 절차(설계 §3-4: 표로 모아 보여준 뒤 자동 진행,

  - [ ] **자동 채택 제외 원칙 하나**(설계 §3-4-4: 되돌릴 길 확보 장치가 미치지 않는

  - [ ] `as_recommended` 해석 규칙(오타·부재 → false)을 `bootstrap.prompt` 해석 규칙

- 리스크/충돌: 플레이북 단독.

**아래 2건이 미해소라 이 문서의 status를 `확정`이 아닌 `작성중`으로 둔다. 답이 갈리는

1. **`as-recommended`가 ⑤ 설계 승인·⑩ 사용자 판정 게이트도 자동 통과시키는가?**
   이 계획은 **아니오**(오케스트레이터 추천 그대로) 가정으로 T5·T8을 채웠다. "예"로
   바뀌면 T5(제외 원칙 자체를 다시 씀)·T8(게이트 자동 통과 시나리오 검증으로 교체)이
   갈라진다 — 영향 범위가 커서 답이 늦어지면 국면 B(T4~T8) 착수를 미루는 편이 안전하다.
2. **선호 프로필 저장 위치 — 사용자 전역인가, 프로젝트 소속인가?**
   이 계획은 **사용자 전역**(`~/.claude/harness/preferences.yaml`) 가정으로 T2·T4·T7을
   채웠다. "프로젝트 소속"으로 바뀌면 저장 경로·`.harnessignore` 취급·설치/업데이트
   영향이 전부 달라져 T2(경로·형식)·T4(컨피그 키가 `harness.config.yaml` 자체 안으로
   들어갈 가능성)·T7(README 서술)이 갈라진다.

**새로 발견한 이슈 (설계 중 발견, 사용자 확인 필요하지 않으나 기록해 둠):**

3. `question_id` 네이밍 규칙(예: `set-initial.commit_format`)을 스킬마다 어떻게 붙일지
